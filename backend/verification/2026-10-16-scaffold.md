## 분리한 검증 범위

- 위 HTTP 결과는 테스트 컨텍스트 실행이다. 패키징 JAR의 8080 foreground 실행과 `local-infra` JDBC health는 루트 실행 도구로 별도 확인한다. 이 기록에서 해당 실행의 PASS를 대신 주장하지 않는다.
- 한 번의 숨김 JAR 실행·정리 통합 명령은 자동 승인 검토에서 `blocked by policy`로 실행 전에 거절됐다. 그 명령으로 시작한 프로세스는 없다. 루트 담당자가 foreground 실행과 Ctrl+C 종료로 검증 경로를 대체한다.
- 기본 profile은 DB 없이 동작한다. `UP`은 업무 readiness, authority, 스키마 준비, 영속화·원접수·원판정의 증거가 아니다.
- 차단된 `/api/v1/rounds`의 `403`은 보안 골격 검사다. OpenAPI 응답·인증·세션의 구현/인수 결과가 아니다.
- 실제 domain/application 기능은 아직 없다. 빈 패키지에 적용할 ArchUnit 규칙과 대조 fixture 검사는 경매 도메인 구현 검증이 아니다.
- 원접수·공식 순번·시간 전이 B·old transaction fence·중단/복구·ACK·snapshot/replay/live handoff·SSE·동시성/장애/성능·브라우저 기능 검증: 이 골격 작업에서 `NOT_RUN`.
- DB migration/업무 transaction, 메일 발송, 사진 저장/업로드 adapter: 미구현. 준비 환경 변수와 JDBC opt-in 설정을 실제 기능으로 취급하지 않는다.

## 인수 조건 QA-AC

1. 빈 DB/migration 후 empty list, 명시적 합성 공개·미공개·같은 시작 시각·경계보다 많은 회차로 공개 필터/정렬/페이지 끝을 실제 HTTP 스키마 검사와 대조한다. 운영 schema migration에 seed를 넣지 않는다.
2. 비회원 첫 화면→복수 페이지→ID에 예약문자가 포함된 상세→목록 복귀, 0개/오류, 기존 상세 회귀를 Chromium에서 관측한다. privacy 필드·큰 counter/시각을 독립 기대값으로 검사한다. 잘못된 응답의 소비자 거부는 Playwright 응답 가로채기 등 합성 fault/mock 증거로 별도 기록하며 실제 DB/HTTP 관측에 합산하지 않는다. 이를 위해 제품 서버에 계약 위반 응답을 추가하지 않는다.
3. DB 중단 시 HTTP 503과 열린 목록 화면의 오류를 확인한다. DB 복구 후 **동일 페이지의 재시도 동작**으로 정상 목록이 복원됨을 검사한다. 새 페이지를 열어 성공한 결과로 대체하지 않는다.
4. 승인 원본 무변경, synthetic fixture 배포물 제외, JSON no-store, 공통 오류 형식, 관측 로그의 비밀 미포함을 검사한다. 업무 상태/세션/공식 접수/SSE 복구는 NOT_RUN이다.
5. 실행기는 자기 disposable 프로세스·컨테이너·볼륨만 종료하고 cleanup 결과를 남긴다. CI는 해당 커밋이 만든 JAR/dist를 사용하고 새 테스트 결과 artifact를 보존한다.

원시 결과는 실행기의 `.artifacts/integration/<run-id>/`와 `output/playwright/`를 유지하고 `.artifacts/tasks/T-003/<run-id>/`에서 연결한다. 테스트 코드 작성과 실제 실행을 구별한다. 기존 성공 횟수를 고정 기대 개수로 재사용하지 않고 새 사례의 수집/실행 여부를 확인한다.

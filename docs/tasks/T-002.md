## 인수 조건 FE-AC

1. `/`에서 loading/목록/빈 목록/오류를 구별한다. “더 보기”는 서버 cursor를 변형하지 않고 사용하며 null이면 끝난다. 고정 페이지 크기·페이지 번호·전체 개수를 가정하지 않는다.
2. 승인된 생성 타입을 사용하고 응답/항목의 알 수 없는 필드를 거부한다. counter를 부정확한 JS number로 바꾸지 않으며 ID는 정확히 인코딩해 상세로 전달한다.
3. 목록 선택→기존 `?roundId=` 상세→목록 복귀/브라우저 뒤로가기를 확인한다. 기존 직접 링크·새로고침·상세 오류·개발 fixture 진입을 회귀 검증한다. 목록 상태 복원 방식은 FE 내부 선택이며 서버 snapshot 보장처럼 표시하지 않는다.
4. 페이지 요청 실패 후 사용자 재시도에서 누락·중복 append가 생기지 않는다. 늦게 도착한 응답이 다른 화면/새 요청을 덮지 않는다. 503을 빈 목록이나 “회차 없음”으로 표시하지 않는다.
5. 기존 서울 시각·서버 상태 의미와 공개 필드를 유지한다. 로컬 시계 기반 자동 진행·가짜 로그인·실시간처럼 보이는 fixture를 추가하지 않는다.
6. Chromium desktop 1280px/mobile 390px를 제안 개발 조건으로 관측한다. OPEN-08 지원환경 전체 승인/AC-R47-01 전체 PASS와 구별한다.

실제 API 관측은 최신 T-001 포함 dev를 반영한 worktree에서 수행한다. T-002가 소유한 기존 `frontend/e2e/public-round.spec.ts`에 기존 합성 공개 회차를 사용하는 목록→상세→목록 복귀 smoke를 추가하고, 공통 `verify.ps1 -Integration`의 disposable 실행기로 실행한다. 현재 실행기는 자동 시험 후 정리하므로 수동 관측용 대기 모드를 가정하지 않는다. T-003은 이후 복수 페이지·빈 목록·동일 화면 장애 복구를 독립 확장 검증한다. fixture/mock 성공을 실제 연동 PASS로 제출하지 않는다.

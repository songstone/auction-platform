## 인수 조건 BE-AC

1. 익명 `GET /api/v1/rounds`는 닫힌 `PublicRoundPage`로 응답한다. 명시적 공개 사실과 공개 가능한 상태를 상세와 동일하게 판정하며 private 데이터와 미공개 회차를 포함하지 않는다.
2. `scheduledStartsAt`, `roundId` 오름차순·동일 시각 tie-break·여러 페이지·마지막 null·빈 목록을 실제 DB로 확인한다. 페이지 경계보다 많은 합성 데이터를 사용한다. 변경 없는 데이터의 반복 탐색에서 중복·누락이 없고 변경 중 완전 snapshot 보장을 추가하지 않는다.
3. 커서는 opaque 값으로 scope를 구별하고 SQL은 파라미터 바인딩한다. 반환된 커서 왕복, 잘못된 입력의 계약상 400, 끝 페이지 처리를 확인한다. stream cursor를 목록 cursor로 소비하지 않는다. 내부 크기를 제품 데이터 제한으로 만들지 않는다.
4. 각 항목은 기존 12필드 DTO 의미를 유지한다. 큰 문자열 counter·UTC 정밀도·opaque ID·취소/완료 등 공개 상태를 보존한다.
5. 성공/오류의 no-store·고정 오류 형식·trace 정책, DB 미구성/중단 시 503, 기존 상세/비공개 404/보호 경로 거부가 유지된다. 조회가 레코드를 쓰거나 상태를 진행시키지 않는다.

```powershell
# worktree 루트; JAVA_HOME은 이 프로세스에만 설정
$env:JAVA_HOME = $env:AUCTION_JAVA_HOME
python -X utf8 scripts/check-approved-baseline.py --strict-evidence
Push-Location backend
.\gradlew.bat --no-daemon --console=plain clean build integrationTest
Pop-Location
git diff --check
```

각 명령의 exit code를 따로 기록한다. 컨테이너/DB를 사용하지 않은 MockMvc 성공만으로 BE-AC를 완료하지 않는다. DB 장애 후 조회 복구는 검증한 범위로 보고하며 입찰/세션/실시간 복구로 확대하지 않는다.

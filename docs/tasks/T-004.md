## 마감 절차

1. T-001/T-002의 개별 검증과 T-003 통합 증거를 독립 확인한다. 카드별 실제 통과 범위만 VERIFIED/MERGED로 기록한다. 전체 R-37(상품/실시간 포함)·R-47·R-49 또는 인증/입찰의 PASS로 확대하지 않는다.
2. 보호 브랜치 설정은 별도로 조회했을 때만 기술적 강제 상태를 주장한다. workflow에 구성된 contracts/backend/frontend/integration 4개 job의 해당 커밋 성공을 직접 확인한다.
3. 최신 dev와의 병합 해결로 코드가 바뀌면 해당 원담당의 검증 및 CI를 다시 받는다. 단순 완료 보고나 오래된 green CI를 사용하지 않는다.
4. 승인된 다음 작업만 새 실제 SHA/계약으로 READY 전환한다. 출시 승인/배포 증거가 없으면 마일스톤은 dev 통합 완료에 머물고 RELEASED는 기록하지 않는다.

```powershell
git fetch origin --prune
git rev-parse origin/dev
git worktree list
# 실제 수집한 task tip마다 실행하고 exit 0 확인
git merge-base --is-ancestor <local-task-tip> origin/dev
git merge-base --is-ancestor <remote-task-tip> origin/dev
python -X utf8 scripts/check-approved-baseline.py --strict-evidence
git diff --check
```

위 `<...>`는 확인한 실제 task tip으로 치환한다. 아직 없는 commit을 예시 SHA로 채우지 않는다. 브랜치 정리 명령은 경로·사용 여부·미병합 변경 확인 뒤 리드가 실행한다.

# 의사결정 기록

- 문서 상태: 승인된 초기 기획을 반영한 초안
- 기획 승인일: 2026-10-14
- 최종 제품 책임자·기술 승인자: 사용자
- 근거: 이 프로젝트 대화에서 사용자가 선택·승인한 운영 정책
- 관련 문서: [PRODUCT-BRIEF.md](./PRODUCT-BRIEF.md), [AUCTION-RULES.md](./AUCTION-RULES.md)

이 문서는 확정 결정, 검토 대안, 미정 정책, 기술 검증 위험을 구분한다. 아래 결정의 승인은 제품 기획 범위에 한한다. 상세 아키텍처·API 계약·구현 계획은 아직 승인되지 않았으며, 구현·테스트·성능 검증·병합이 완료됐다는 의미가 아니다.

결정 이유는 대화에서 검토한 장단점과 선택 취지를 요약한 것이다. 새로운 기능이나 승인되지 않은 정책을 추가하는 근거로 사용하지 않는다. 상세 운영 규칙과 상태 전이는 `AUCTION-RULES.md`를 함께 참조한다.

## 1. 확정된 결정

### 제품 목적과 개발 범위

| ID | 결정 | 이유 | 검토한 대안·경계 |
| --- | --- | --- | --- |
| D-001 | 웹 기반 개인 간 중고 물품 경매를 포트폴리오로 구현하되, 실제 물품 출품과 낙찰을 허용한다. | 실제 서비스에 가까운 전체 경매 흐름을 구현하려는 사용자 목표를 따른다. | 모의 상품·모의 낙찰만 제공하는 시연용 서비스 대신 실제 출품·낙찰을 선택했다. 검수·분쟁 처리는 이번 MVP의 중점 범위에서 제외한다. |
| D-002 | MVP는 출품, 사전 공개, 실시간 입찰, 낙찰·유찰·취소 결과 기록까지 다룬다. 결제·정산과 물품 전달은 서비스 밖에서 처리한다. | 경매의 정확성과 이용 흐름에 먼저 집중한다. | 결제·정산을 MVP에 통합하는 안은 제외했다. 향후 확장이 가능하도록 고려하되, 지금 상세 결제 도메인이나 연동 구조를 확정하지 않는다. |
| D-003 | MVP부터 점진적으로 확장하며 객체지향 설계, 유지보수성, 테스트 가능성, 실시간 입찰의 정확성과 데이터 정합성을 중시한다. | 장기적으로 유지·확장할 수 있는 제품을 만든다. | 불필요하게 복잡한 분산 시스템을 초기부터 도입하지 않는다. Java·Spring Boot는 우선 검토 대상, React는 후보이며 기술 스택 확정은 별도다. |
| D-004 | 향후 역할별 AI 에이전트 작업은 승인된 도메인 규칙·API 계약과 명확한 책임·완료 기준을 바탕으로 나눈다. | 병렬 작업 중 규칙과 계약의 충돌을 방지한다. | 에이전트가 공통 코드·계약을 임의 변경하지 않는다. 구현 완료, 검증 완료, 병합 완료를 구분한다. 구체적인 작업 분담과 계약은 아직 정하지 않았다. |
| D-005 | 첫 MVP 검증 목표는 4개 레인을 동시에 운영하는 조건에서 동시 참여자 총 100명이다. | 사용자가 20명 수준보다 큰 초기 검증 범위를 선택했다. | 20명 수준 검증안을 선택하지 않았다. 100명은 향후 검증 목표이며 가입자 제한·입찰 빈도·달성한 성능 수치를 의미하지 않는다. |

### 회원, 상품, 조회 권한

| ID | 결정 | 이유 | 검토한 대안·경계 |
| --- | --- | --- | --- |
| D-006 | 가입 즉시 한 회원이 출품과 입찰을 모두 할 수 있다. 본인 출품에는 입찰할 수 없다. | 개인이 판매자와 구매자를 함께 맡는 거래 구조를 단순하게 표현한다. | 참가자별 운영자 승인과 본인 출품 입찰 허용은 채택하지 않았다. 본인 판별의 구체적인 인증·계정 기준은 후속 결정이다. |
| D-007 | 한 회원이 여러 레인에 동시에 입찰하고 여러 상품을 낙찰받을 수 있다. | 원하는 상품이 여러 레인에 분산될 수 있다. | 회차당 한 레인만 참여하는 제한은 두지 않는다. |
| D-008 | 비회원에게는 출품 목록까지만 허용하고 상세 페이지는 로그인 후 조회하도록 한다. | 공개 목록으로 서비스를 소개하면서 상세 접근은 회원에게 제공한다. | 모든 정보를 비회원에게 공개하는 초기 제안은 사용자가 제한했다. 별도 실시간 화면과 목록의 세부 노출 필드는 미정이며 이 결정으로 비회원의 상세·실시간 접근을 자동 허용하지 않는다. |
| D-009 | 출품 필수 정보는 상품명, 설명, 사진 1장 이상, 시작가, 희망가, 입찰 단위다. | 최소 입력으로 상품을 설명하고 경매를 진행할 수 있다. | 카테고리와 상품 상태를 별도 필수 분류로 받는 안은 MVP에서 채택하지 않았다. 사진 수·크기 등 입력 제한은 후속 결정이다. |
| D-010 | 원화 정수 금액을 사용한다. 시작가·희망가·입찰 단위는 모두 양수이고 희망가는 시작가 이상이어야 한다. | 계산과 잘못된 가격 조건을 명확하게 한다. | 0원 시작이나 소수 금액은 허용하지 않는다. 금액 상한과 희망가의 입찰 단위 정렬 여부는 정하지 않았다. |
| D-011 | 출품자는 희망가와 별도로 시작가를 정한다. 입찰 단위는 정해진 후보를 선택하거나 직접 입력한다. | 낮은 시작가로 경쟁을 시작하면서 상품 가격대에 맞게 단위를 정할 수 있다. | 희망가를 곧 시작가로 사용하는 방식과 모든 상품에 공통 입찰 단위를 강제하는 방식은 채택하지 않았다. 후보 금액 자체는 미정이다. |

### 회차와 레인 운영

| ID | 결정 | 이유 | 검토한 대안·경계 |
| --- | --- | --- | --- |
| D-012 | 매주 각 모집 기간에 수집한 상품을 예약된 회차에서 경매한다. 운영자가 회차별 모집 기간, 경매 시작 시각, 운영 레인 수를 등록한다. | 출품과 참가자의 사전 확인 시간을 확보하고 운영 일정을 명확히 한다. | 상품 등록 즉시 경매하거나 매번 운영자가 시작하는 방식 대신 예약 자동 시작을 선택했다. 주간 반복 회차 자동 생성은 채택하지 않았다. 주 1회로 횟수를 고정하지 않는다. |
| D-013 | 회차의 모집 기간은 서로 겹치지 않는다. 상품은 등록 시점에 모집 중인 회차에 자동 출품한다. 모집 중인 회차가 없으면 출품 신청을 받지 않고 다음 모집 일정을 안내한다. | 회차 선택 없이 출품할 수 있고 귀속 기준이 명확하다. | 여러 회차를 동시에 모집하고 출품자가 선택하는 방식은 채택하지 않았다. |
| D-014 | 사전 공개는 회차 시작 전날 0시에 시작하며, 모집은 그 공개 직전에 마감한다. 사전 공개 기간에는 출품 목록·상세를 통해 상품 정보를 미리 확인할 수 있다. | 공개 시 상품 목록을 정하고 참가자의 확인 시간을 확보한다. | 정확히 24시간 전 공개와 공개 중 추가 모집은 채택하지 않았다. 일정의 기준 시간대와 경계의 정확한 포함·제외 처리는 미정이다. |
| D-015 | 회차별 운영 레인 수는 1~4개 중 선택한다. K개를 선택하면 1번부터 K번까지 사용하며 운영자는 사전 공개 전까지만 수정할 수 있다. | 레인마다 별도 목적이 없는 현재 MVP에서 설정을 단순하게 한다. | 1·3레인처럼 특정 번호만 선택하는 방식은 채택하지 않았다. 사전 공개 후 레인 수를 수동 변경하는 권한은 없다. |
| D-016 | 상품은 해당 회차에서 대기 상품 수가 가장 적은 운영 레인에 자동 배정한다. 각 레인에서는 최초 출품 등록순으로 진행한다. | 자동 분산과 예측 가능한 순서를 함께 제공한다. | 출품자 레인 선택, 운영자 배정, 무작위 순서, 운영자 순서 지정은 채택하지 않았다. 대기 수가 같은 레인의 우선순위는 미정이다. |
| D-017 | 사전 공개 전에 운영 레인 구성이 변경되면 해당 회차의 전체 상품을 다시 자동 배정한다. 재배정 후에도 레인 안의 최초 등록순을 유지하고 수정 시각으로 순서를 바꾸지 않는다. | 레인 증감 시 상품 수를 다시 분산할 수 있다. | 제외된 레인의 상품만 옮기는 방식은 채택하지 않았다. 이 전체 재배정 규칙은 레인 구성 변경에 대한 결정이며, 일반 등록·수정·취소마다 전체 재배정한다는 뜻이 아니다. |
| D-018 | 한 회차의 운영 레인은 회차가 실제로 시작하는 시점에 함께 출발하며 상품 진행 속도와 종료 시점은 서로 독립적이다. 정상 시작은 공동 예약 시각을 따르고 지연은 D-019를 따른다. | 공동 일정으로 안내하면서 레인별 경쟁을 독립적으로 처리한다. | 레인별 다른 시작 일정, 모든 레인의 상품을 함께 마감·전환하는 방식, 레인 순차 진행은 채택하지 않았다. |
| D-019 | 동시에 진행하는 회차는 하나다. 예약 시각에 이전 회차가 미완료라면 다음 회차는 시작 지연 상태로 대기하고, 이후 이전 회차 완료 후 자동 시작한다. 이전 회차가 일찍 완료돼도 다음 회차를 예약 시각보다 앞당겨 시작하지 않는다. | 기존 경매를 보존하고 자동 운영을 이어간다. | 운영자가 지연 회차를 확인한 뒤 수동 시작하는 안은 채택하지 않았다. 이는 공개된 예약 시각을 임의 변경하는 권한과 구분되는 자동 지연 규칙이다. |
| D-020 | 공개 후 아직 시작하지 않은 회차는 일정 변경을 허용하지 않고, 회차 취소만 허용한다. 취소 기록은 보존하며 상품을 다른 회차로 자동 이동시키지 않는다. | 공개된 일정과 출품 귀속을 안정적으로 유지한다. | 공개 후 시작 시각을 운영자가 연기하는 안은 채택하지 않았다. D-019의 자동 시작 지연은 별도 예외다. |
| D-021 | 운영 레인이 모두 종료되고 보류된 상품이 없으면 회차를 자동 완료한다. | 자동 진행 흐름을 마무리하고 미결 결과를 완료로 오인하지 않는다. | 모든 레인 종료 후 운영자 최종 승인으로 완료하는 단계는 두지 않는다. 회차 완료는 결제·정산 완료가 아니다. |

### 출품 변경과 경매 가격

| ID | 결정 | 이유 | 검토한 대안·경계 |
| --- | --- | --- | --- |
| D-022 | 출품자는 사전 공개 전에는 상품을 수정·취소할 수 있다. 공개 후에는 수정할 수 없고 해당 상품의 경매 시작 전까지 취소만 할 수 있다. | 공개된 설명·가격을 안정적으로 유지하면서 판매 철회를 허용한다. | 공개 후 수정까지 허용하는 안과 취소도 전면 금지하는 안은 채택하지 않았다. 준비 단계와 취소 마감의 관계는 미정이다. |
| D-023 | 사전 공개 후 상품이 취소되면 다른 상품의 레인과 상대적인 순서를 유지한다. 취소 상태를 표시하고 진행 시 건너뛴다. | 참가자가 미리 확인한 배치를 유지한다. | 공개 후 다시 균등 배정하는 안은 채택하지 않았다. 진행 번호를 재부여할지는 별도 결정이다. |
| D-024 | 현재 최고가는 공개한다. 희망가 금액은 다른 참가자에게 숨기고 최고가가 희망가 이상이면 낙찰 가능 구간 진입을 UI로 표시한다. 출품자는 자신의 희망가를 확인할 수 있다. | 낙찰 가능한 상태를 알려주면서 출품자의 기준 금액은 노출하지 않는다. | 희망가 금액 전체 공개와 도달 여부까지 숨기는 안은 채택하지 않았다. 낙찰 가능 표시는 경매 종료나 낙찰 확정 표시가 아니다. |
| D-025 | 첫 입찰은 시작가, 이후 입찰은 현재 최고가에 설정된 입찰 단위를 더한 금액으로 한다. | 빠른 버튼 입찰과 예측 가능한 가격 상승을 제공한다. | 입찰자가 금액을 자유롭게 입력하거나 상한액을 지정하는 자동 대리입찰은 채택하지 않았다. 출품자의 입찰 단위 직접 입력과 입찰자의 가격 직접 입력은 구분한다. |

## 5. 후속 결정 기록 원칙

1. 확정 결정의 의미를 바꾸려면 변경 이유와 검토 대안을 제시하고 사용자 승인을 받는다. 기존 기록을 조용히 덮어쓰지 않는다.
2. 미정 사항은 실제로 답변·승인받기 전까지 미정으로 유지한다. 기술 검증 결과는 정책 승인과 구분한다.
3. 변경 시 관련 결정 ID와 영향을 받는 제품 개요·상세 규칙을 함께 갱신해 세 문서의 불일치를 방지한다.
4. 향후 검증 결과에는 검증 대상·조건·관찰 결과·미검증 범위를 남긴다. 설계안, 정적 검토, 실행 검증, 실제 운영 증거를 서로 대체하지 않는다.

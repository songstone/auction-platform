## 1. 기존 기록과 이번 승인 관계

기존 문서는 참고 자료로 사용했으며, 이번 대화에서 다시 확인한 정책을 현행 기준으로 삼았다. 이전 원문은 Git 커밋 `018f56521179103542e348df75beac28602492c2`의 `docs/decisions/DECISION-LOG.md`에 보존되어 있다. 해당 커밋의 제품 개요와 경매 규칙도 같은 기준의 참고본이다.

기존 `D-001`~`D-041`은 주제와 식별자를 유지하면서 아래 현행 결정으로 갱신했다. `D-042`는 과거 문서에 적힌 승인·작성 이력으로 남기며, 현재 승인은 `D-054`에 별도로 기록한다. 기존본에만 있는 세부 정책을 이번 승인으로 자동 승계하지 않는다.

## 2. 확정된 결정

이유는 승인된 선택의 취지를 요약한다. 새로운 정책의 근거로 사용하지 않는다. 상세 행동과 판정 기준은 관련 요구사항 및 [경매 규칙](../product/AUCTION-RULES.md)을 따른다.

화면 밖 경매 알림, 소셜 로그인, 계정 관리 확장 등 필요성이 확인되지 않은 기능은 위 질문만으로 MVP에 추가하지 않는다. 실제 결제·정산 기능을 도입할 때는 거래·환불·정산 정책과 필요한 별도 검토를 다시 진행한다.

## 8. 후속 변경 원칙

1. 승인 요구사항의 의미를 바꾸려면 관련 R/D ID, 변경 이유, 대안, 인수 조건 영향을 제시하고 제품 책임자의 승인을 받는다.
2. OPEN은 결정 근거·승인일을 기록한 후 해결 처리한다. PROP 채택과 HYP 검증은 각각 정책 승인·실행 증거와 구분한다.
3. 변경 시 [제품 개요](../product/PRODUCT-BRIEF.md), [MVP PRD](../product/MVP-PRD.md), [경매 규칙](../product/AUCTION-RULES.md), 이 기록을 함께 맞춘다.
4. 대체 시 이전 근거와 대체 관계를 남긴다. 과거 기록을 현행 정책 근거로 오인하지 않게 한다.
5. 이후 검증 결과는 대상·조건·관찰 결과·미검증 범위를 기록한다. 문서 정적 검토, 구현 검증, 실제 운영 증거는 서로 대체하지 않는다.

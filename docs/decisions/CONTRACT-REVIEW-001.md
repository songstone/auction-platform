## 1. 승인된 범위와 남은 결정

사용자는 CR-01~03의 제품 정책을 D-092~D-094로 승인한 데 이어, **남은 OPEN과 미검증 위험을 유지한 채 현재 시스템 설계와 정의된 API·이벤트를 구현 기준선으로 승인했다(D-095).** SYSTEM-DESIGN은 1.0, 계약은 기존 draft.2의 wire 정의를 유지한 `0.1.0`으로 식별한다. T-01~06의 현재 설계·계약 원칙은 이 범위로 채택하되 미완성 메커니즘의 정확성·실행 성공을 입증한 것은 아니다. **CR-04~10·SEC-01~04의 미정 제안값과 deferred 표면은 미승인으로 남는다.** 질문의 기본 선택값·응답 대기 시간 경과·문서 검토 PASS를 별도 승인으로 처리하지 않는다.

승인된 R/AC와 현행 OPEN의 원본은 [DECISION-LOG](DECISION-LOG.md#3-아직-결정되지-않은-정책과-세부-조건), [MVP-PRD](../product/MVP-PRD.md)다. 이 문서는 선택지·추천·적용 영향을 소유하는 검토 자료다. 승인 이후의 현행 정책은 기존 원본에 기록하고 이 문서는 당시 검토 이력으로 남긴다. HTTP·JSON을 이 문서에서 새로 정의하지 않는다.

## 2. 승인된 제품 정책 3개와 반영 상태

먼저 제시한 세 질문에 사용자가 추천안대로 적용하도록 명시 답변했다. 아래 세 항목은 **제품 정책 승인 완료**이며 다시 선택할 질문이 아니다. 제품 원본·도메인·시스템 설계·당시 계약 초안·예제를 동기화하고 정적 검사·독립 문서 검토로 확인했다. 세 제품 정책의 승인 자체를 전체 계약 승인으로 확대하지 않았으며, 이후 별도 D-095로 현재 정의된 설계·계약 범위를 채택했다.

| --- | --- | --- |
| CR-01 / **D-092**, OPEN-06, R-16/45/52 | **운영자 계정은 운영 전용, 회원 기능은 별도 일반회원 계정 사용** | 같은 사람이 별도 일반회원 계정으로 참여하는 것까지 금지하지 않음. `SessionUser.roles`에 역할 1개 제약 반영. 제품 원본·OAS 동기화 및 겸용 세션 스키마 거절 확인 완료 |
| CR-02 / **D-093**, OPEN-05, R-09/10/12/46 | **최저낙찰가의 입찰 단위 정렬을 요구하지 않음** | 시작 10,000원·단위 1,000원·최저 10,500원이면 실제 입찰은 10,000→11,000원이고 11,000원부터 기준 도달. 기존 양수·최저≥시작 조건 유지. `CreateLotRequest`, `UpdateLotRequest` 설명과 비정렬 예제에 반영하고 스키마·예제 산술 확인 완료 |

이전 대안인 운영자 계정의 MEMBER 겸용과 유찰 최종 최고가 제공은 이번에 선택하지 않았다. D-092가 같은 사람의 별도 일반회원 계정에 기존 회원 규칙을 면제하지 않으며, D-093도 임의 높은 입찰을 허용하거나 정확한 다음 금액 규칙을 바꾸지 않는다. 낙찰자 식별 상세·금액/시간 상한·단위 후보 등 나머지 OPEN은 그대로 남는다.

## 3. 다음 제품 결정 묶음의 추천안

**CR-04~10은 미승인 제안이다.** CR-01~03이나 D-095의 현재 설계·계약 채택으로 아래 수치·조회 권한·계정 범위가 함께 승인된 것은 아니다.

수치에는 실험으로 입증한 성능·최적 UX라는 의미가 없다. 입력 실수·자원 사용·작업 범위를 제한하기 위한 초기 제안이며 현재 스키마에 적용하지 않았다. 값 수정·부분 채택·미정 유지가 가능하다.

CR-05를 채택해도 공통 `MoneyWon` 전체에 출품 상한을 넣지 않는다. 진행 중 정확한 다음 금액이 출품 상한을 넘는다는 이유로 임의 마감·금액 변경·새 거절 정책을 추가하면 R-08/10과 충돌한다. 입력용 스키마와 실제 입찰 금액의 의미를 구분하고 저장·연산 범위는 구현 설계에서 확인한다. 실제 입찰 총액의 상한도 원한다면 초과 시 업무 처리까지 별도 결정해야 한다.

CR-07은 안전한 업로드의 기본 원칙인 형식 허용목록·내용 검증·크기/디코딩 자원 제한·권한 확인을 참고한 제안이다. **10 MiB·2,000만 픽셀·10장**은 OWASP가 정한 수치가 아니다. [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

## 4. 보안 설계의 채택 제안

이 절은 기술 설계자가 구체화한 **SEC-01~04 미승인 보안 제안**이다. 수명·범위의 사용자 경험 비용을 확인하고 채택할 수 있으며, 실제 보안 집행 성공은 별도 검증한다. D-092~D-095의 승인에 이 미정 제안값을 포함하지 않는다. 기존 계약에 정의된 동일 출처 쿠키·CSRF 구조의 채택과 토큰/세션 수명 등 추가 수치의 채택을 구분한다. 모든 상세를 새로운 경매 업무 정책 질문으로 되돌리지 않는다.

| 검토 ID / 항목 | 추천 후보와 이유 | 확인할 비용·잔여 검증 |
| --- | --- | --- |
| SEC-01 / 비밀번호 | 신규 설정은 **15~128 Unicode 코드포인트**. NFC 처리 후 길이 평가·저장/검증을 일치시키고 공백·유니코드 허용. 임의 trim·대소문자 변환·잘림 없음. 문자종류 혼합·정기 변경 강제 대신 알려진 취약 비밀번호 차단 | 현 MVP의 비밀번호 단일요소 인증에 맞춘 참고안. 128 상한은 프로젝트 후보. 차단목록·해시/작업비용·입력 한계·회귀 사례는 구현에서 고정. NIST 적합성 인증이나 피싱 방지를 주장하지 않음 |

SEC-01의 길이·유니코드·문자종류 규칙은 [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#passwordver)를 참고했다. 이 서비스의 128자 상한·수명 수치까지 표준 의무라는 뜻은 아니다. SEC-02의 일회성/만료·계정 유무를 숨기는 응답·재설정 후 로그인과 세션 무효화는 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)를 참고했다. ## 5. D-095로 채택한 기술 선택의 범위

## 6. 정의된 부분의 구현 기준선과 병렬 작업

## 7. 승인 반영과 추가 답변의 처리 절차

1. 답변의 검토 ID·정확 범위·추천 대비 변경값을 확인한다. CR-01~03의 제품 승인과 D-095의 정의된 설계·계약 채택을 구분하며 CR-04~10·SEC의 미정 제안값으로 확대하지 않는다.
2. 제품 정책 답변은 DECISION-LOG에 승인일·새 D와 관련 OPEN의 해결 부분을 기록한다. 요구/AC 원본인 PRD와 업무 설명인 RULES를 맞추고, 불변식에 영향이 있을 때만 DOMAIN-MODEL을 바꾼다.
3. 결정된 입력·권한·필드를 OpenAPI 한 곳에서 수정하고 새 draft 버전·예제·오류·음성 검사를 맞춘다. 이벤트 의미가 바뀔 때만 auction-events를 수정한다. 정책 몇 개의 승인이 전체 계약의 최종 승인은 아니다.
4. 정적 검사·독립 문서 검토를 수행하고 구체 diff와 미결정 잔여를 제시한다. 승인 대상 파일 hash를 새로 산출한다.
5. D-095로 승인된 버전·범위만 현재 기준선으로 기록한다. 이후 추가·변경도 해당 범위의 사용자 승인을 기록한다. T-01의 방향 채택을 미완성 B 프로토콜 전체의 정확성 입증으로 기록하지 않는다. 실제 구현·성능·장애 결과는 별도 증거다.

전체 변경 절차의 원본은 [ADR-005](adr/ADR-005-CONTRACT-BASELINE.md)다. CR-01~03은 D-092~D-094를, T-01~06의 현재 채택 범위는 D-095를 참조한다. CR-04~10·SEC-01~04는 승인 대기 검토용 ID다. 어느 검토 ID도 승인된 D 번호를 대신하지 않는다.

**이전 0.2 / 계약 draft.2의 검사 이력:** CR-01~03 제품 정책을 원본·도메인·시스템·OAS·이벤트·예제에 반영했고 계약 정적 검사와 독립 문서 검토를 통과했다. 당시 계약 검사는 공유 예제 24개·미디어 연결 예제 15곳·음성 스키마 사례 38개였다. 이는 현재 승인 상태·버전·manifest 갱신의 새 검사 결과가 아니다. 승인 전 파일 식별은 review-baseline의 당시 검토 이력으로 남긴다.

**현재 1.0 / 계약 0.1.0:** D-095에 따라 남은 OPEN과 미검증 위험을 유지한 채 현재 시스템 설계·정의된 API/이벤트를 구현 기준선으로 승인받았다. 신규 계약 정적 검사·승인 전 원본과의 구조 동일성 대조·독립 문서 검토는 PASS다. 승인 manifest에 출발 검토본과 현재 파일 hash·제외 범위·검사 결과를 기록했다. 문서 검사의 최신 범위는 DECISION-LOG §7이 원본이다. 제품 서비스·DB·네트워크·브라우저·부하·장애·배포는 새로 실행하지 않았다. CR-04~10·SEC의 미정 제안값은 여전히 미승인이다.

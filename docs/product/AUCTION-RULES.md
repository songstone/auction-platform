실제 개인 소유 중고 물품의 출품과 낙찰을 대상으로 한다. 결제·정산·물품 전달은 서비스 밖에서 처리하며 경매 완료를 외부 거래 완료로 해석하지 않는다. 향후 결제·정산 확장 방향은 고려하되 구현 구조는 별도 설계한다. (R-01, R-03, R-05)

[MVP-PRD.md](MVP-PRD.md)는 G-01, R-01~R-52와 인수 조건의 정본이다. 본 문서는 관련 요구사항 번호를 연결하여 정상·예외 상황의 업무 규칙을 설명한다. [PRODUCT-BRIEF.md](PRODUCT-BRIEF.md)는 제품 목적과 범위를, [DECISION-LOG.md](../decisions/DECISION-LOG.md)는 결정 이력·제안·가설·미결정 정책·위험을 관리한다.

본문의 승인 규칙과 미결정 항목을 구분한다. 아래 상태 명칭은 업무 설명용이며 코드의 상태 값, API, DB 테이블, 클래스 또는 실시간 통신 방식을 확정하지 않는다. 예시는 인수 검증에 사용할 기대 결과이며 실행 증거가 아니다.

1.1은 공식 접수·동일 경매 순번·후속 대기 시간 기준점의 추가 승인(D-055~D-057)을 반영한다. 당시 남긴 경합 중 아래 1.3 승인 범위는 D-063~D-066을 따른다. 당시 잔여 경합·장애 정책의 현재 승인 범위는 아래 1.5를 따른다. 저장·순서 보장 기술과 예시의 실행 검증은 별도로 남아 있다.

1.2는 입찰 의도별 요청번호, 동일 요청의 원접수·원판정 유지, 조회·재전송, 앱의 최종 판정 수신·반영 확인 후 신규 제한 해제, 별도 미접수 종료 기능 제외의 추가 승인(D-058~D-062)을 반영한다. 당시 남긴 다중 기기·보존·재시도·복구 정책 중 이번 승인 범위는 아래 1.5를 따르며 구체 기술 프로토콜은 별도 결정·검증한다.

1.3은 2026-10-15 승인된 외부 요청 공통 순번·개시 정각 개시 우선·현재 마감 정각 정상 종료 우선·상품/레인 대상 고정(D-063~D-066)을 반영한다. 당시 남긴 준비·재개 시간 기준점은 아래 1.4에서 확정했다. 당시 미정이던 장애·회차 시작/취소 정책은 아래 1.5에 반영했다. 공통 순번은 특정 큐·락·분산 처리 기술의 승인이 아니다.

1.4는 2026-10-15 승인된 첫 준비의 공통 실제 회차 시작 시각, 다음 준비·재개의 실제 전이 확정 시각, 입찰 가능 구간의 하한과 정각 순번, 기존 개시·마감의 유지(D-067~D-070)를 반영한다. 당시 남긴 장애 보류·기록 불명·운영 명령 중복/재시도 정책은 아래 1.5를 따르며 기록·시각·복구 기술은 별도 설계·검증 대상이다.

1.5는 2026-10-15 승인된 장애 범위·마감/복구·재개 확인(D-071~D-075), 운영 명령·중단 발생건·공유 입찰 의도·확인·원기록 보존(D-076~D-080), 모집/공개·회차 진행/취소(D-081~D-086), 배정 동률·재배정·취소 자리(D-087~D-090)를 반영한다. 위 1.1~1.4의 당시 미결정 사항 중 이 범위는 이번에 해결했다. 구체 저장·시각·감지·동기화 기술, 입력 수치·권한·UX·실제 운영 보존 기간은 별도 결정·검증 대상이다. 복구 불능의 장기 보류 비용은 수용하며 이를 종료할 별도 기능은 이번 승인에 포함하지 않는다.

1.6은 사용자가 명시 승인한 CR-01~03의 운영 전용 계정·회원 계정 분리(D-092), 최저낙찰가 단위 정렬 불필요(D-093), 유찰 종료 응답·결과 화면의 최고입찰가 미노출(D-094)을 반영한다. 다른 CR·SEC·기술·설계·전체 공통 계약의 승인은 아니며 새 실행 검증은 NOT_RUN이다.

## 3. 역할과 조회 권한

### 3.1 계정과 참가

- 이메일 인증으로 가입을 완료하고 이메일·비밀번호로 로그인한다. 인증 이메일을 이용한 비밀번호 재설정을 제공한다.
- 일반회원은 별도의 참가·판매자 승인 없이 출품자와 입찰자 역할을 수행한다.
- 운영자 계정은 사전 지정한다. 일반 가입으로 운영 권한을 얻을 수 없으며 MVP에는 운영 권한 부여·회수 관리 화면을 두지 않는다.
- 운영자 계정은 운영 전용으로 일반회원 기능을 겸용하지 않는다. 회원 기능은 별도 일반회원 계정을 사용한다. 같은 사람이 별도 일반회원 계정으로 참여하는 것은 금지하지 않으며 같은 이메일의 계정 구분·동일성 정책은 이번에 정하지 않았다. (D-092)
- 이메일 인증은 실명 또는 물품 소유권 검증을 뜻하지 않는다.

관련 요구사항: R-16, R-45, R-50, R-52.

## 4. 회차 모집·공개·시작

### 4.1 모집과 공개 시점

1. 회차는 예약 시작 시각과 모집 기간을 가진다.
2. 서로 다른 회차의 모집 기간은 겹치지 않는다.
3. 출품은 신청 시점에 모집 중인 회차로 자동 접수한다. 모집 중인 회차가 없으면 접수하지 않는다. 설정된 다음 모집 일정이 있으면 안내한다.
4. 다른 회차가 진행 중이어도 미래 회차의 모집은 가능하다. 모집 회차 제한과 동시 진행 회차 제한은 별개다.
5. Asia/Seoul 기준 **예약 시작일 전날 00:00에 모집을 마감하고 사전 공개**한다.

예: 2026-10-20 19:00 시작 회차의 공개 시점은 2026-10-19 00:00이다. 시작 시각으로부터 24시간 전인 10월 19일 19:00이 아니다. 관련 요구사항: R-07, R-30~R-32, R-46.

모집 구간은 **모집 시작 포함·모집 마감 제외**다. 경계 요청은 서버 공식 접수 시각으로 판정한다. 시작 정각에는 모집 개시, 마감·공개 정각에는 모집 마감과 공개를 먼저 적용한다. 공개 직전 공식 접수된 유효 출품·수정·레인 수 변경을 반영한 뒤 공개 배치를 고정하며 처리 지연만으로 앞선 요청을 버리지 않는다. 공개 정각의 새 출품·수정·레인 수 변경은 해당 회차에 적용하지 않는다. 다만 공개 후에도 입찰 개시 전 출품자 취소는 가능하고, 단계 시간 설정은 실제 회차 시작 때 고정한다. (D-081, R-15, R-30, R-33, R-34)

새 회차는 **현재 서버 시각 ≤ 모집 시작 < 공개 시각 < 예약 시작**을 만족해야 한다. 지난 모집 시작·공개로 소급 생성하지 않는다. 같은 예약 시작일이면 공개·모집 종료 시각이 같아 두 양수 모집기간이 겹치므로 신규 중복 설정을 거절한다. 동일 예약시각에 별도 우선순위를 붙여 이 제약을 우회하지 않는다. 서로 다른 예약일의 지연 회차가 같은 실제 날짜에 차례로 진행하는 것까지 금지한 것은 아니다. 일정 입력 정밀도·허용 상한은 별도 결정한다. (D-082)

### 4.2 공개 후 변경 제한

- 사전 공개 후 운영 레인 수와 상품 배치를 고정한다. 취소 상품만 건너뛰고 다른 상품의 레인·상대 순서를 유지한다.
- 사전 공개 후 시작 전인 회차의 예약 일정을 임의 변경하지 않는다. 필요한 경우 회차를 취소하고 취소 기록을 유지한다.
- 취소된 회차의 상품을 다른 회차로 자동 이동시키지 않는다.
- 이전 회차 미완료에 따른 자동 시작 지연은 위 임의 일정 변경과 구분한다.
- 이 규칙은 진행 중 회차 전체 취소나 운영자의 임의 출품 삭제 권한을 추가하지 않는다.
- 공개 전 회차 취소와 진행 중 회차 전체 취소는 MVP에서 제외한다. 회차 취소 권한은 공개 후 실제 시작 전 범위로 한정한다. (D-086, EX-10)

회차 취소 당시 유효한 소속 출품에는 **회차 취소로 경매 미진행**임을 표시하고 회차 취소 사유·이력에 연결한다. 이미 개별 취소된 상품의 원래 사유는 유지한다. 유찰·낙찰로 바꾸거나 실제로 발생하지 않은 개별 운영자 취소를 만들어 기록하지 않는다. (D-085)

관련 요구사항: R-31, R-34, R-41.

### 4.3 실제 시작과 회차 대기

| 상황 | 처리 |
| --- | --- |
| 예약 시각 도래, 이전 회차 완료 | 해당 회차 자동 시작 |
| 예약 시각 도래, 이전 회차 미완료 | 지연 상태를 표시하고 대기 |
| 지연 대기 중 이전 회차 완료 | 다음 회차 자동 시작 |
| 이전 회차가 다음 예약 시각 전에 완료 | 다음 회차의 예약 시각까지 대기 |
| 상품이 하나도 없는 회차 | 같은 대기 규칙을 적용하고, 실제 시작 시 즉시 완료 |

동시에 진행하는 회차는 하나다. 여러 지연 회차는 취소되지 않은 회차의 예약시각 오름차순으로 처리하며, 앞선 중단·보류 회차를 건너뛰지 않는다. 빈 회차도 자기 차례와 시작 조건을 만족한 후 실제 시작·즉시 완료한다. 예약시각은 실제 지연 시각으로 덮어쓰지 않는다. 같은 예약 시작일의 모집 중복 설정은 §4.1에 따라 거절한다. (R-31, R-44, D-082, D-083)

시작 자격을 갖춘 자동 시작 사건과 공개 후 회차 취소는 해당 회차의 공통 판정순서에 넣는다. 같은 기록 시각도 순번으로 구분하고 자기 차례에 예약시각·선행 회차 완료·기록 정합성·미취소 조건을 재확인하여 먼저 유효한 전이만 적용한다. 취소가 먼저 유효하면 시작하지 않고, 시작이 먼저 유효하면 뒤 취소를 거절한다. 예약시각만 지났고 선행 회차 때문에 대기 중인 경우까지 취소를 금지하지 않는다. 실제 시작 확정 시각과 첫 레인 준비의 공유는 D-067을 유지한다. 이 회차 전이 순서를 모든 레인의 입찰 전역 순서로 확대하지 않는다. (D-084)

## 5. 출품·가격·레인 배정

### 5.1 필수 입력과 자동 접수

| 항목 | 확정 조건 |
| --- | --- |
| 상품명 | 필수 |
| 설명 | 필수. 물품 상태와 하자를 설명에 작성 |
| 사진 | 최소 1장 |
| 시작가 | 원화 정수, 0보다 큼 |
| 최저낙찰가 | 원화 정수, 0보다 크고 시작가 이상 |
| 입찰 단위 | 원화 정수, 0보다 큼. 기본 제공 후보에서 선택하거나 직접 입력 |

필수 정보와 가격 조건을 만족하면 운영자 상품 심사 없이 자동 접수한다. 카테고리·물품 상태의 별도 분류는 필수로 두지 않는다. 입찰 단위 후보, 금액 상한, 사진·문자열 제한은 미결정이다. 최저낙찰가가 입찰 단위나 시작가 기준 입찰 금액 격자에 정렬될 필요는 없다(D-093). 실제 입찰은 첫 시작가·이후 현재 최고가+단위의 정확한 버튼 금액을 유지한다. (R-10, R-12, R-35, R-36, R-46)

### 5.2 배정과 진행 순서

- 회차마다 1~4개의 운영 레인을 선택한다.
- 취소되지 않은 대기 상품 수가 가장 적은 운영 레인으로 출품을 배정한다. 동률이면 레인 번호가 작은 순서로 선택한다.
- 같은 회차의 유효 등록은 최초 공식 출품 접수 순번으로 처리한다. 같은 기록 시각에도 순번을 따르고 무효 등록은 상품 수에 포함하지 않는다. 각 레인은 최초 등록순으로 상품을 진행하며 정보 수정으로 순서를 바꾸지 않는다.
- 사전 공개 전에 운영 레인 수를 바꾸면 전체 상품을 다시 자동 배정하고 원래 출품 등록순을 유지한다.
- 사전 공개 후 취소가 발생하면 다른 상품의 레인과 상대 순서를 유지하고 취소 상품만 건너뛴다.
- 공개 전 일반 수정은 기존 배정·등록순을 유지하고 개별 취소는 대기 수에서 제외하되 다른 상품을 재배정하지 않는다. 이후 신규 출품은 변경된 대기 수에 따라 배정한다.
- 공개 전 레인 수 변경에 따른 전체 재배정은 남은 유효 출품을 최초 등록순으로 처리하면서 같은 최소 대기 수·동률 규칙을 적용한다. 취소 상품을 되살리지 않는다.
- 공개 후 취소는 공개 당시 번호와 자리를 유지하여 취소 상태로 표시한다. 뒤 상품 번호를 당기지 않고 진행만 해당 자리를 건너뛴다. 공개 전 취소된 비공개 상품을 이 표시 규칙 때문에 일반 공개하지 않는다.

예: 대기 수가 (2,2,2,2)이면 첫 유효 출품은 1번, 다음 유효 출품은 반영된 수 (3,2,2,2)를 보고 2번 레인으로 간다. 동시 등록이 같은 과거 수를 각각 사용하여 잘못 배정되어서는 안 된다. 배정 순서와 수 변경의 일관성을 어떤 저장 기술로 보장할지는 별도 검증한다. 레인 수 변경 시 전체 재배정 규칙을 모든 출품 변경에 확대 적용하지 않는다. (R-27, R-28, R-34, D-087~D-090)

### 5.3 출품자의 수정·취소

| 시점 | 정보 수정 | 출품자 취소 |
| --- | --- | --- |
| 사전 공개 전 | 가능 | 가능 |
| 공개 후, 상품 준비 전 대기 | 불가 | 가능 |
| 해당 상품의 준비 단계 | 불가 | 가능 |
| 최초 입찰 대기 시작 이후 | 불가 | 불가. 유효 입찰이 없더라도 동일 |

취소 허용 경계는 ‘경매 화면에 상품 등장’이나 ‘첫 유효 입찰 발생’이 아니라 **입찰 접수 시작**이다. 입찰 개시 정각에는 자동 개시를 먼저 적용한다. 개시 직전 공식 접수된 유효 출품자 취소는 처리가 개시 시각 뒤로 늦어져도 허용하며, 개시 정각·이후 접수된 출품자 취소는 거절한다. 개시 전 공식 접수된 입찰은 지연 처리되어도 거절하고 정각의 입찰은 개시 후 나머지 조건으로 판정한다. 선행 유효 취소·중단으로 개시 조건이 바뀌었다면 그 결과를 먼저 반영한다. 운영자의 현재 상품 경매 취소 권한은 별도 규칙이다. (R-26, R-33, D-063, D-064)

### 5.4 유찰 상품의 재출품

- 유찰 상품은 자동 재출품하지 않는다. 출품자가 모집 중인 회차에 새로 신청해야 한다.
- 새 신청 시각으로 배정과 순서를 정한다.
- 이전 회차의 유찰 기록은 보존한다.
- 재출품 시 기존 정보 복사 등 편의 기능은 이번 MVP에 추가로 승인하지 않았다.

관련 요구사항: R-32, R-40.

## 6. 시간 설정과 상품의 정상 진행

### 6.1 회차별 설정

| 단계 | 기본값 | 적용 의미 |
| --- | --- | --- |
| 준비 | 5초 | 상품 전환 후 입찰 접수 전 준비 시간. 입찰 불가 |
| 최초 입찰 대기 | 10초 | 입찰 접수 시작부터 첫 유효 입찰을 기다리는 시간 |
| 후속 입찰 대기 | 5초 | 유효 입찰의 공식 접수 시각부터 계산하는 다음 유효 입찰 대기 시간 |

운영자는 세 시간을 회차별 한 세트로 조정한다. 같은 회차의 모든 운영 레인에 적용하고 실제 회차 시작 시 값을 고정한다. 시작 전까지 수정할 수 있지만 시작 후에는 중단·재개 중에도 바꾸지 않는다. 허용 최솟값·최댓값은 미결정이다. (R-13~R-15)

### 6.2 진행 순서

1. 실제 회차 시작 시 모든 운영 레인이 첫 상품의 준비를 함께 시작한다. 상품이 없는 레인은 종료 규칙을 적용한다.
2. 준비 시간이 끝나면 입찰 접수를 시작하고 최초 입찰 대기 시간을 부여한다.
3. 최초 대기가 끝날 때까지 유효 입찰이 없으면 유찰한다.
4. 첫 유효 입찰을 승인하면 그 입찰의 공식 접수 시각을 기준으로 후속 입찰 대기를 시작한다.
5. 새 유효 입찰마다 **공식 접수 시각 + 회차 고정 후속 대기 시간**으로 마감을 갱신한다. 판정 시각부터 시간을 다시 세지 않는다. 거절된 요청은 최고가·최고입찰자·마감 시각을 변경하지 않는다.
6. 후속 대기가 끝나면 최저낙찰가 조건으로 낙찰 또는 유찰을 판정한다.
7. 결과 처리 후 다음 상품이 있으면 그 상품의 준비 단계로 이동한다.

각 레인은 동시에 상품 하나만 경매하고 이후 진행은 독립적이다. 한 레인의 경쟁이 길어지거나 중단되어도 다른 레인의 상품 단계·최고가·결과를 바꾸지 않는다. 유효 입찰 경쟁이 이어지는 동안 상품의 종료 시점은 늦어질 수 있다. 고정 총 경매 시간이나 최대 입찰 횟수는 확정하지 않았다. (R-04, R-06, R-08, R-09, R-29)

### 6.3 준비 기준점과 이미 정한 자동 경계

실제 전이 시각은 상태와 그 시작·종료 시각을 권위 있는 변경으로 확정하면서 기록하는 서버 시각이다. 요청 수신, 타이머 호출, 화면 표시 시각으로 대신하지 않는다. 이를 어떤 저장·시각 기술로 보장할지는 별도 설계·검증한다.

| 새 준비를 시작하는 상황 | 기준점 |
| --- | --- |
| 회차의 첫 상품 | 모든 운영 레인이 공유하는 실제 회차 시작 사건의 시각. 각 레인의 별도 처리 완료 시각을 사용하지 않음 |
| 정상 종료 후 다음 상품 | 이전 상품 결과를 확인하고 다음 상품의 준비 진입을 확정한 서버 시각 |
| 진행 중 허용된 현재 상품 취소 후 다음 상품 | 취소 결과를 확인하고 다음 상품의 준비 진입을 확정한 서버 시각 |
| 중단 중 현재 상품 취소 후 다음 상품 | 중단을 유지하다가 허용된 실제 재개를 확정한 시각. 상세는 §10.3 |

준비 시작 시각을 P, 회차 고정 준비 시간을 T준비라 하면 개시 시각 O = P + T준비다. 최초 대기 마감은 O + T최초다. 다음 상품의 준비를 이전 상품의 옛 마감부터 소급하여 아직 시작하지 않은 상품의 시간을 소진하지 않는다. 첫 준비는 같은 회차 시작 사건을 공유하고 이후 각 레인의 전환·재개는 독립이다. (R-13, R-29, R-43, D-067)

이미 정한 현재 유효 O와 마감 D는 타이머 실행·판정 처리·화면 표시가 늦다는 이유로 이동하지 않는다. 정상 처리에서 개시 작업이 늦어도 O를 개시로 사용하고 최초 마감도 O + T최초를 유지한다. 유효 입찰은 기존대로 공식 접수 시각 + T후속으로 새 마감을 정한다. 모든 이용자의 화면에서 준비 전체 시간이 보인다는 보장은 아니며 화면 표시·확인 응답을 기다려 O나 D를 다시 부여하지 않는다. 선행 유효 중단·취소·입찰로 무효화되거나 갱신된 경계는 먼저 반영한다. 장애 보류·기록 확정 불명은 이 정상 처리 규칙으로 해결하지 않는다. (D-057, D-064, D-065, D-070)

## 7. 입찰 승인·거절

### 7.1 입찰 방식과 금액

- 첫 유효 입찰은 정확히 시작가로 제출한다.
- 이후에는 정확히 현재 최고가에 해당 상품의 고정 입찰 단위를 더한 금액으로 제출한다.
- 버튼으로 정해진 다음 금액에 입찰한다. 자유 금액 입력·대리입찰은 MVP에서 제공하지 않는다.
- 출품자의 입찰 단위 직접 입력은 위 금액 계산에 사용할 상품 설정이며, 입찰자의 자유 금액 입력이 아니다.

예: 시작가 10,000원·단위 1,000원이면 첫 입찰은 10,000원, 그다음 유효 금액은 11,000원이다. 시작가·최저낙찰가·입찰 단위는 서로 다른 개념이다. (R-09, R-10, R-12)

### 7.2 참가 제한과 효력

- 로그인한 회원만 입찰할 수 있다.
- 출품자는 본인 상품에 입찰할 수 없다.
- 현재 최고입찰자는 자신의 가격을 다시 올릴 수 없다. 다른 사람이 최고입찰자가 된 뒤에는 다시 입찰할 수 있다.
- 한 회원은 여러 레인에 동시에 참여하고 여러 상품을 낙찰받을 수 있다.
- 사용자는 승인된 입찰을 철회할 수 없다.
- 개인의 연결 끊김이나 브라우저 종료는 승인된 입찰의 효력을 없애지 않는다.

단독 입찰자가 시작가로 입찰했고 최저낙찰가가 시작가보다 높다면, 최고입찰자 재입찰 금지 때문에 스스로 증액하지 못하고 미달 유찰될 수 있다. 이것은 승인된 정책 조합의 의도된 결과다. (R-16~R-20, R-22)

### 7.3 접수 순서와 종료 경계

- 처음 공식 접수되는 외부 요청은 인증·기본 형식 확인 후 **공식 접수 기록에 넣은 시점**을 기준으로 한다. 이미 접수된 동일 입찰 요청은 §8의 원접수 유지 규칙을 따른다. 공식 접수는 업무 승인 자체가 아니며 사용자의 클릭 시각을 기준으로 삼지 않는다.
- 같은 회차·레인 진행에 영향을 주는 입찰·출품자 취소·운영자 중단/재개/상품 취소는 **공통 증가 순번**으로 판정한다. 같은 기록 시각에도 순번을 따르고 운영 명령 등 요청 종류에 우선권을 주지 않는다. 같은 경매 입찰의 기존 상대 순서를 보존하며 다른 레인까지 전역 순서를 요구하지 않는다.
- 같은 금액으로 경쟁한 요청은 먼저 접수된 **유효한 요청**만 승인한다. 먼저 도착한 무효 요청이 다음 유효 요청을 막지 않는다.
- 금액·상태·마감의 업무 판정은 선행 요청을 반영한 자신의 순번에서 수행한다. 공식 접수 전에 오래된 업무 금액·마감으로 미리 거절하지 않는다. 자신의 순번에서 제출 금액이 유효하지 않으면 거절하며 서비스가 금액을 자동으로 올리지 않는다.
- 입찰 요청의 공식 접수 시각은 자신의 순번에 적용되는 **현재 유효 마감**보다 빨라야 한다. 그 마감과 같거나 늦으면 거절한다. 선행 유효 요청으로 마감이 갱신되었다면 후행 요청에도 갱신된 마감을 사용한다.
- 현재 유효 마감 전에 공식 접수된 유효 요청은 판정이 마감 뒤로 늦어졌다는 이유만으로 거절하거나 종료 판정에서 누락하지 않는다. 선행 무효 요청은 뒤의 유효 요청을 막지 않는다.
- 유효 입찰의 새 마감은 **공식 접수 시각 + 회차 고정 후속 대기 시간**이다. 판정 시각에 전체 시간을 다시 더하지 않는다.

외부 요청 공통 순번과 개시·마감 경계는 D-063~D-066, 준비·재개 기준점과 입찰 구간은 D-067~D-070을 따르며 기존 공식 접수·후속 시간 기준(D-055~D-057)을 유지한다. 중복 식별·원판정 유지·조회/재전송·확인 종료는 §8과 D-058~D-062, 공유 의도·어느 기기 확인·원기록 보존은 D-078~D-080을 따른다. 장애·장기 지연·복구와 운영 명령은 §10 및 D-071~D-077, 회차 시작/취소는 §4.3 및 D-084를 따른다. 시각 정밀도·저장·순서 보장·공유 등록/확인·장애 증거/복구의 기술과 재시도 간격/횟수·실제 운영 보존 기간은 [결정 기록](../decisions/DECISION-LOG.md)의 남은 결정·검증 사항이다. (R-08, R-21, R-23, R-25, R-26, R-33, R-43; OPEN-09, OPEN-10, OPEN-12)

업무상 '입찰 접수 중단'은 해당 상품의 유효 입찰을 승인할 수 없다는 뜻이다. 공통 접수 기록에 거절 요청의 처리 사실을 남기는 것과 구분한다. 기록 자체가 입찰 승인이나 마감 갱신을 뜻하지 않는다.

검증 예시: 현재 마감이 상대 시각 10.000초이고 유효 입찰이 9.950초에 공식 접수되어 10.080초에 판정되며 후속 설정이 5초라면 새 마감은 14.950초다. 15.080초로 보정하지 않는다. 이 예시의 소수 자릿수는 시각 정밀도를 정하는 정책이 아니며 실행 검증은 NOT_RUN이다.

### 7.4 외부 요청과 자동 개시·정상 마감의 경합

공통 순번은 외부 요청끼리의 선후를 정한다. 자동 개시·마감은 예정된 경계 시각에 효력을 갖는 규칙으로 다루며, 타이머가 실제 실행된 순서로 외부 요청과 경쟁시키지 않는다. 먼저 접수된 유효 입찰·중단·취소가 단계나 유효 마감을 바꾸었다면 그 결과를 먼저 반영한다.

아래 외부 요청 간 경쟁은 각 요청의 판정 차례에 해당 조치의 허용 조건을 확인한다. 입찰·중단·상품 취소의 순서만으로 개시·현재 마감 경계를 무시하거나 이미 종료된 경매를 바꾸지 않는다.

| 경합 | 승인된 판정 |
| --- | --- |
| 입찰 → 운영자 중단 | 앞선 입찰이 유효하면 승인·기록·마감을 반영한 뒤 중단도 유효할 때 중단하고 해당 단계와 입찰을 보존한다. |
| 운영자 중단 → 입찰 | 유효한 중단이 해당 경매의 입찰 가능 상태를 닫으면 후행 입찰을 거절한다. 무효·거절된 중단은 후행 유효 입찰을 막지 않는다. 요청 종류의 우선권으로 순번을 바꾸지 않는다. |
| 입찰 → 운영자 상품 취소 | 유효 입찰을 먼저 기록하고 이어 취소가 유효하면 취소한다. 입찰과 취소 사유를 보존하며 승인 사실을 취소 결과와 구분한다. |
| 운영자 상품 취소 → 입찰 | 유효 취소를 먼저 적용하고 해당 원경매를 대상으로 한 후행 입찰은 거절한다. 무효·거절되거나 다른 상품을 대상으로 한 취소는 후행 유효 입찰을 막지 않는다. |
| 준비 종료·입찰 개시 직전 중단 | 준비 단계에서 중단하며, 판정이 늦어졌다는 이유로 최초 대기 단계로 바꾸지 않는다. |
| 입찰 개시 정각 중단 | 유효한 자동 개시를 먼저 적용한 다음 최초 대기 단계에서 중단한다. |
| 현재 유효 마감 직전 운영자 상품 취소 | 선행 사건을 반영한 상태에서 취소가 유효하면 정상 마감보다 먼저 적용한다. 판정 지연만으로 마감 후 취소로 바꾸지 않는다. |
| 현재 유효 마감 정각·이후 운영자 상품 취소 | 정상 종료를 먼저 적용하여 낙찰·유찰을 보호하고 취소를 거절한다. 타이머 호출이나 물리적 저장이 늦어도 취소가 앞서지 않는다. |

여기서 마감은 선행 유효 입찰을 반영한 **현재 유효 마감**이다. 예를 들어 10초 마감 직전의 유효 입찰이 마감을 14.950초로 바꾸면 10초에 접수된 운영자 상품 취소는 새 마감 전에 해당하므로 나머지 조건을 만족할 때 허용한다. 옛 10초 타이머로 먼저 종료해서는 안 된다. 선행 중단·취소가 있으면 그 상태를 반영하며 장애 보류·확정 여부 불명 상황을 이 정상 종료 규칙으로 임의 해결하지 않는다. (D-063~D-065)

입찰과 출품자/운영자 상품 취소는 원 Lot/Auction에 고정하고 다음 상품으로 돌리지 않는다. 중단·재개는 해당 회차의 Lane을 대상으로 한다. A 종료 후 B가 준비 중일 때 레인 중단을 적용하면 B의 진행을 멈추며 A의 확정 결과는 그대로 보존한다. 다음 상품 준비·재개의 시간 기준점은 D-067/068 및 §6.3·§10.3을 따른다. (D-066)

### 7.5 대표 거절 조건

| 조건 | 처리 |
| --- | --- |
| 비로그인, 본인 출품 상품 | 거절 |
| 현재 최고입찰자의 재입찰 | 거절 |
| 준비 단계, 입찰 미개시, 중단·결과 보류, 종료·취소된 상품 | 입찰 승인 불가 |
| 첫 입찰이 시작가와 다름 | 거절 |
| 다음 입찰이 현재 최고가 + 입찰 단위와 다름 | 거절 |
| 선행 요청을 반영한 현재 유효 마감 시각과 같거나 늦게 공식 접수 | 거절 |

거절은 가격·최고입찰자·대기 시간을 변경하지 않는다. 응답을 받지 못해 결과를 모르는 경우는 거절과 다르며 다음 절의 **처리 확인 중** 규칙을 적용한다. (R-08, R-10, R-17, R-18, R-21, R-23)

## 8. 미확인 요청과 개인 연결 끊김

- 개인 연결이 끊겨도 경매는 계속되고 기존 유효 입찰을 유지한다. 해당 회원이 재접속하기 전에 낙찰·유찰되거나 다음 상품으로 넘어갈 수 있다.
- 입찰 응답을 받지 못하면 성공 또는 실패로 추정하지 않고 **처리 확인 중**으로 표시한다.
- 원요청의 최종 승인·최종 거절을 앱이 수신·반영했음이 확인될 때까지 **요청을 보낸 그 회원의 해당 상품 경매에 대한 새 입찰만 막는다.** 다른 회원의 같은 상품 입찰과 본인의 다른 상품·레인 입찰은 이 사유로 제한하지 않는다.
- 연결 복구 후 최신 상품·가격·단계와 자신의 미확인 요청 결과를 확인한다. 이미 결과가 났다면 해당 결과를 확인할 수 있어야 한다.
- 연결이 끊긴 최고입찰자도 정상 종료 시 최저낙찰가 조건을 충족하면 낙찰받는다.

### 8.1 요청 식별과 원판정 유지

입찰 의도마다 고유 요청번호를 사용한다. 동일 회원·요청번호는 처음의 경매와 제출 금액에 고정된다. 같은 번호·같은 내용의 재전송은 같은 논리 요청이며 새로운 입찰 의도에는 새 번호를 사용한다. 요청번호는 공식 접수 순번과 별개다. (R-23, D-058)

- 이미 공식 접수된 요청의 재전송은 원접수 시각·순번을 유지한다. 원래 승인 또는 거절이 기록돼 있으면 그 판정을 확인하며 현재 상태로 다시 판정하지 않는다.
- 원요청이 아직 처리 중이면 최종 판정을 추정하지 않고 같은 요청의 확인을 이어간다. 원판정·완전한 공식 접수와 선행 이력·불명확 기록의 복구 구분은 §10.2 및 D-073을 따른다.
- 동시에 같은 요청을 재전송해도 입찰 효과는 한 번이다. 재전송 시각으로 후속 마감을 다시 계산하지 않는다.
- 같은 회원·번호로 경매 또는 금액을 바꾸어 보내면 내용 충돌로 구분하고 원요청을 변경하지 않는다. 충돌 응답은 원요청의 최종 거절이 아니다.
- 과거 거절 뒤 경매 상태가 바뀌어도 같은 요청은 원거절을 유지한다. 승인 사실도 이후 최고입찰자 변경·유찰·취소 등과 구분하여 보존한다.

관련 요구사항·결정: R-23, D-058, D-059.

### 8.2 조회·재전송과 최초 접수

미확인 요청은 같은 회원·요청번호로 조회하고, 필요한 재전송도 원경매·원금액을 유지한다. 서버에 도달하지 않았던 요청이 재전송으로 처음 공식 접수된다면 그때의 시각·순번으로 업무 조건을 판정한다. 과거 클릭·전송 시각으로 소급하지 않는다. 이미 접수됐던 요청은 원기록을 확인한다. 단순 조회의 기록 없음만으로 미도달을 확정하지 않는다. (R-23, D-060)

레인이 다음 상품으로 이동했더라도 재전송을 새 상품의 입찰로 바꾸지 않는다. 원요청의 승인 사실은 현재 최고입찰자나 최종 낙찰자라는 의미가 아니며, 최신 상태·최종 경매 결과와 별도로 표시한다.

### 8.3 확인과 신규 제한 해제

원요청의 최종 승인·최종 거절을 어느 기기의 앱이든 수신하여 반영했음이 확인되면 그 미확인 요청으로 인한 회원×상품 경매 신규 제한을 해제한다. 최초 전송 기기나 모든 기기의 확인을 요구하지 않는다. 앱이 자동 확인하며 사람이 읽었음을 증명하거나 별도의 수동 확인 버튼을 누를 것을 요구하지 않는다. 서버가 응답을 보냈다는 사실만으로 앱의 수신·반영 확인을 대신하지 않는다. 구체 확인·동기화 프로토콜은 후속 설계한다. (R-23, D-061, D-079)

시간초과, 조회의 기록 없음(NOT_FOUND), 인증 실패, 내용 충돌 응답, 경매 종료는 원요청의 최종 거절을 뜻하지 않으며 그 사유만으로 미확인 제한을 해제하지 않는다. 최종 판정을 확인해 제한이 해제되어도 최고입찰자의 재입찰 금지·마감·종료 등 다른 입찰 조건은 계속 적용한다.

최종 승인·거절 확인과 별개로 미접수를 확정해 미확인 요청을 종료하는 기능은 MVP에서 제외한다. 기록 없음에 미접수 종료 의미를 붙이거나 시간초과로 자동 실패 처리하지 않는다. (D-062, EX-09)

### 8.4 실제 입찰 전 공유 의도 등록

실제 입찰을 보내기 전에 회원×상품 경매마다 동시에 하나의 미확인 입찰 의도를 서버에 공유 등록한다. 원최종 판정의 수신·반영이 확인되면 다른 업무 조건 안에서 새 의도를 등록할 수 있다. 의도는 요청번호·원경매·원금액을 유지하며 등록 확인 뒤에 실제 입찰을 보낸다. 다른 기기는 같은 의도를 조회·재전송하고, 별도 의도를 동시에 만들어 같은 회원×경매 제한을 우회하지 않는다. 등록 자체가 서버에 도달하지 않았거나 등록 결과가 불명확하면 그 기기는 실제 입찰을 보낼 수 없다. 등록 실패·충돌·불명확 응답을 원입찰의 최종 거절로 표시하지 않는다. (D-078, D-079)

**공유 의도 등록은 공식 입찰 접수가 아니다.** 등록 시각을 입찰 접수 시각이나 가격·마감 판정 기준으로 사용하지 않는다. 실제 입찰이 처음 공식 접수될 때의 시각·순번으로 업무 조건을 판정하며, 이미 공식 접수된 요청은 원기록을 유지한다. 등록 뒤 시간초과를 이유로 의도를 버리거나 새 입찰 제한을 해제하지 않는다. 별도 미접수 종료 기능은 계속 MVP 제외다. (D-055~D-062, D-078, EX-09)

### 8.5 요청 원기록의 보존

진행·보류·미확인 동안 원판정과 중복 식별 관련 기록을 만료시키지 않으며 MVP에 해당 기록의 자동 만료를 두지 않는다. 이 원칙은 입찰과 운영 명령의 원결과 확인을 지키기 위한 것으로 모든 사진·개인정보를 영구 보존한다는 정책이 아니다. 실제 운영에서의 구체 보존 기간·접근·삭제는 OPEN-12에서 별도 결정한다. (D-080)

공유 의도의 저장·복수 기기 동기화·앱 확인 프로토콜, 요청번호 생성과 재시도 간격·횟수, 시각·순번·기록 확정 증거와 복구 기술은 별도 설계·검증한다. 승인된 복구 판단 기준과 그 기준을 입증하는 기술을 구분한다. (OPEN-06, OPEN-09, OPEN-10, OPEN-12)

## 9. 낙찰·유찰·외부 거래

### 9.1 정상 종료 판정

| 종료 시 조건 | 결과 |
| --- | --- |
| 유효 입찰 없음 | 유찰 |
| 최고 유효 입찰가 < 최저낙찰가 | 유찰 |
| 최고 유효 입찰가 = 최저낙찰가 | 해당 최고입찰자에게 그 금액으로 낙찰 |
| 최고 유효 입찰가 > 최저낙찰가 | 해당 최고입찰자에게 그 금액으로 낙찰 |

최저낙찰가를 충족하는 즉시 종료하지 않는다. 진행 중에는 충족 여부만 표시하고 경쟁이 끝난 시점의 최고 유효 입찰을 기준으로 확정한다. (R-08, R-09, R-11)

### 9.2 결과 보존과 거래 연락처

- 공개 상품과 낙찰·유찰·취소 결과, 낙찰가는 종료 후에도 조회할 수 있다.
- 무입찰·최저 미달 유찰 모두 종료 응답·결과 화면과 종료 이벤트의 결과에 최고입찰가를 제공하지 않는다. 진행 중 공개된 가격의 삭제·회수나 본인 원입찰·원판정 기록 삭제를 요구하지 않으며 일반 결과와 본인 원기록 조회를 구분한다. (D-094)
- 일반 사용자에게 최저낙찰가 금액을 공개하지 않는다.
- 낙찰자 식별 정보는 출품자·낙찰자 본인·운영자에게만 허용한다.
- 낙찰된 거래의 출품자와 낙찰자에게 서로의 등록된 인증 이메일을 제공한다.
- 외부 결제·정산·물품 전달의 완료를 서비스가 추적하지 않는다. 낙찰 결과로 지급·전달 완료를 표시하지 않는다.
- 외부 거래 불이행 때문에 이미 확정된 낙찰·유찰을 운영자가 수정·취소하지 않는다.

운영자 연락처 이메일 접근, 상세 낙찰자 표시 필드, 개별 입찰 이력 접근 범위, 보존 기간은 미결정이다. 유찰 종료 응답·결과의 최고입찰가 미노출은 D-094로 확정했으며 본인 원기록 조회 권한을 삭제하는 결정이 아니다. 내부 채팅이나 지급·배송 추적은 MVP 범위가 아니다. (R-03, R-23, R-38, R-39, R-43)

## 10. 중단·장애·재개

### 10.1 운영자의 수동 중단

운영자는 레인을 즉시 중단할 수 있다. 중단은 현재 상품의 입찰 접수와 타이머를 멈추며, 현재 상품이 끝날 때까지 기다리는 방식이 아니다. 승인된 입찰·최고가·최고입찰자를 유지한다. (R-25, R-26)

### 10.2 장애 범위·마감 경쟁과 기록 복구

특정 레인의 문제임이 확실하면 해당 레인만 보류한다. 서비스 전체 장애이거나 영향 범위를 알 수 없으면 현재 회차의 미완료 레인을 모두 보류한다. 기록된 유효 입찰을 유지하고 이미 확정된 결과를 다시 열지 않는다. (D-071)

| 확인한 상황 | 처리 |
| --- | --- |
| 정상 마감이 장애보다 먼저 성립했다는 기록이 확인됨 | 정상 종료 적용, 이미 확정된 결과 유지 |
| 장애가 먼저 발생했거나 마감과 장애의 선후 판단 불가 | 결과 확정 보류. 벽시계 경과만으로 낙찰·유찰하지 않음 |
| 원입찰 판정이 기록돼 있음 | 원판정 그대로 반환 |
| 미결 요청의 공식 접수와 선행 이력이 완전함 | 원접수 시각·순번으로 판정하며 장기 지연 여부도 확인 |
| 장애 복구에서 권위 있는 경매 이력이나 처리 효과가 불명확함 | 성공·실패를 추정하지 않고 보류 |

위 기록 불명 보류는 장애 복구에서 권위 있는 경매 이력·처리 효과를 확정할 수 없는 경우다. 개인의 응답 유실이나 단순 조회의 기록 없음(NOT_FOUND, 최초 미도달 가능)을 곧바로 경매 전체 보류로 확대하지 않는다. 개인 연결 끊김은 경매 전체를 중단시키지 않으며, 원판정 미확인은 §8의 회원×상품 경매 신규 제한과 동일 번호 조회·재전송으로 다룬다. (R-22, R-23, D-073)

예: 마감 10초·장애 9.8초·복구 15초이면 복구 시 바로 낙찰하지 않는다. 결과가 10초에 확정되고 11초에 장애가 난 별도 경우에는 확정 결과를 유지한다. (D-072, D-073)

공식 접수 9.9초의 유효 입찰에 후속 5초를 적용하면 새 마감은 14.9초다. 선행 요청을 정리한 뒤에도 16초에야 이 입찰을 판정할 수 있는 장기 지연이라면 원시각·순번으로 입찰을 판정하되 결과 확정·자동 진행을 보류한다. 지연을 최종 입찰 거절 사유로 삼거나 판정 시각에서 5초를 새로 주지 않는다. 정상 접수·판정이 계속됐고 타이머 콜백만 늦었다면 기존 현재 유효 마감을 유지한다. (D-072)

재개 전 기록·최고입찰·진행 단계·미결 요청을 확인하고 정상 접수와 기록이 가능해져야 한다. 그 뒤 운영자가 명시적으로 재개한다. 수동 중단과 장애 보류가 겹치면 두 원인을 별도로 보존하고 장애 복구 확인만으로 기존 수동 중단을 해제하지 않는다. (D-074)

복구 불능이면 장기 보류로 후속 회차도 대기하는 비용을 수용한다. 이를 임의 유찰·취소나 자동 정상 종료로 바꾸지 않는다. 별도 예외 종료는 이번 승인에 포함하지 않으며 추가하려면 범위 변경 승인이 필요하다. 장애 감지 수치·영향 및 선후 증거 수집·기록 복구 기술은 검증해야 한다. 정책 승인만으로 기록 보존이나 복구 능력이 입증된 것은 아니다.

### 10.3 재개 시간

수동 중단과 서비스 장애 후 재개에 같은 시간 원칙을 적용한다. 필요한 운영자 확인과 재개 조건을 만족한 뒤 실제 재개를 확정한 서버 시각 R부터 해당 단계 전체 시간을 부여한다. 재개 요청의 접수 시각이나 이전 마감으로 소급하지 않는다. (D-068)

| 중단된 단계 | 재개 시 부여할 시간 |
| --- | --- |
| 준비 | 새 개시 O = 실제 재개 R + 그 회차의 준비 시간 전체 |
| 최초 입찰 대기 | 새 마감 D = 실제 재개 R + 그 회차의 최초 입찰 대기 시간 전체 |
| 후속 입찰 대기 | 새 마감 D = 실제 재개 R + 그 회차의 후속 입찰 대기 시간 전체 |

남은 시간만 이어서 사용하지 않는다. 회차가 시작될 때 고정된 설정을 사용하며 기존 입찰·가격·최고입찰자를 초기화하지 않는다. 예를 들어 기본 준비 5초 중 4초 경과 후 중단했다면 재개 시 준비 5초를 새로 부여하고 준비 중에는 입찰을 받지 않는다. (R-15, R-25)

중단 중 A를 취소하고 B가 남았다면 B의 준비 시간을 중단 중에 소비하지 않는다. 허용된 실제 재개 R에서 B의 준비 전체 시간을 시작하며 A의 옛 단계나 최고입찰을 B로 옮기지 않는다. 남은 상품·보류가 모두 없으면 레인 종료 규칙을 적용한다. (R-25, R-42, R-43, D-068)

최초·후속 대기 재개에서는 공식 접수 시각 t가 R보다 이른 입찰을 거절한다. 재개 요청보다 뒤 순번이고 판정이 재개 후에 이뤄져도 같다. t = R인 입찰은 유효 재개보다 뒤 공통 순번이며 나머지 조건을 만족해야 승인할 수 있다. 입찰 순번이 재개보다 앞이면 중단 상태의 입찰로 거절한다. 준비 단계 재개에서는 R이 아니라 새 O부터 입찰 가능하며 O 전 입찰은 거절한다. 각 경우 입찰은 자신의 순번에 적용되는 현재 유효 마감 D보다 일찍 공식 접수되어야 한다. (R-21, D-069)

재개 하한은 새 업무 판정에 적용한다. 재개 전에 이미 최종 승인·최종 거절이 기록된 동일 요청을 조회·재전송하면 새 R로 재판정하지 않고 원접수·원판정을 유지한다. (R-23, D-059)

예: 최초 대기 재개 요청이 20.0초·순번100에 접수되고 실제 재개가 20.8초에 확정됐다면, 20.1초·순번101의 입찰은 뒤늦게 처리돼도 거절한다. 최초 대기 설정이 10초라면 새 마감은 30.8초다. 이후 새 유효 입찰은 D-057의 공식 접수 시각 + 후속 시간으로 다시 마감을 정한다. 첫 유효 입찰이 21.8초이고 후속 시간이 5초면 26.8초로 단축되며, 재개 마감 30.8초와 더 큰 값을 택하지 않는다. 이 예시는 실행 결과나 시각 정밀도 승인이 아니며 검증은 NOT_RUN이다.

기록 확정 여부가 불명확한 상황에서 새 재개 시각을 임의로 만들거나 정상 재개를 추정하지 않는다. 장애·기록 복구는 D-071~D-075, 운영 명령 중복·재시도는 아래 §10.4를 따른다. 구체 기록·시각·복구 기술은 별도 검증한다.

재접속이 성공했다는 사실은 운영자의 장애 확인·재개를 대신하지 않는다. 최신 상태가 중단·보류라면 화면에도 그 상태를 표시한다. (R-24, R-49)

### 10.4 운영 명령 식별과 재개 대상

운영자+요청번호에 명령 종류·대상·제출한 사유를 고정한다. 같은 명령은 원결과를 반환하고 효과를 다시 적용하지 않는다. 내용 충돌은 원명령을 바꾸거나 원명령의 실패로 대체하지 않는다. 재개 성공 후 응답이 유실돼도 같은 명령 재전송은 원결과·원래 실제 재개 시각 R을 반환하며 시간을 새로 부여하지 않는다. (D-076)

재개는 해당 회차·레인과 해제하려는 중단 발생건에 결합한다. 옛 재개 요청을 다시 보내 새로 발생한 중단을 해제할 수 없다. 과거 재개가 성공한 뒤 새 중단이 발생했다면 그 명령의 재전송은 원성공을 확인할 뿐 현재 새 중단은 유지한다. 이미 진행 중인 레인에 새 요청번호로 재개를 보내도 시간을 갱신하지 않는다. 원명령의 결과와 현재 레인 상태를 구분한다. (D-077)

## 11. 취소와 운영자 권한 한계

### 11.1 현재 상품 경매 취소

운영자는 현재 상품의 경매를 취소할 수 있다. 취소는 유찰과 구분하여 기록하고 취소 사유와 원래 입찰 기록을 유지한다. (R-26)

보류 상품은 확정 결과가 없고 선행 요청·현재 상태를 확인할 수 있을 때만 사유를 남겨 취소할 수 있다. 확정 결과 존재 여부조차 알 수 없으면 취소도 보류한다. 취소를 기록 불명 해소의 지름길로 사용하거나 확정 결과를 덮어쓰지 않는다. (D-075)

| 취소 전 레인 상태 | 취소 후 동작 |
| --- | --- |
| 진행 중, 다음 상품 있음 | 다음 대상 상품의 준비 단계로 이동 |
| 중단 중, 남은 상품 있음 | 중단 유지. 취소를 재개 명령으로 보지 않음 |
| 남은 상품·보류 결과 모두 없음 | 레인 종료 |
| 보류 결과 있음 | 보류를 해결하지 않고 레인·회차 완료로 처리하지 않음 |

다른 상품의 레인과 상대 순서를 바꾸지 않는다. 현재 상품을 취소했다고 다음 상품을 즉시 입찰 단계로 시작하지 않는다. (R-34, R-42, R-43)

### 11.2 결과를 임의 변경하지 않는다

- 운영자는 입찰 금액을 수정하거나 낙찰자를 임의 지정할 수 없다.
- 이미 확정된 낙찰·유찰 결과를 수정·취소할 수 없다.
- 회차의 공개 후 시작 전 취소와 현재 상품 경매 취소를 구분한다.
- 결과 확정 후 외부 거래 실패에 대응하는 정책은 별도 운영 검토 대상이며 결과 수정 권한을 암묵적으로 부여하지 않는다.

관련 요구사항: R-41, R-43.

## 12. 레인 종료와 회차 완료

- 남은 상품과 보류 결과가 모두 없는 레인은 종료한다.
- 다른 레인이 계속 진행 중이어도 완료된 레인은 종료 상태를 유지할 수 있다.
- 모든 운영 레인이 종료되고 보류 결과가 없으면 회차를 자동 완료한다.
- 별도의 운영자 회차 완료 승인 버튼을 두지 않는다.
- 처음부터 상품이 없거나 시작 전 모두 취소되어 빈 회차가 되어도 이전 회차 대기 규칙을 지킨다. 실제 시작 시 즉시 완료한다.
- 회차 완료는 경매와 결과 기록의 완료이며 외부 결제·정산·인도 완료가 아니다.

관련 요구사항: R-03, R-31, R-42, R-44.

## 15. 검증 조건과 미결정 사항

데스크톱은 전체 기능, 모바일은 가입·로그인·출품·조회·입찰·결과·거래 연락처 등 일반 회원 기능을 대상으로 한다. 운영자 기능은 데스크톱 대상으로 한다. 원화 정수와 Asia/Seoul을 사용한다. (R-46, R-47)

4개 운영 레인·동시 연결 100명을 초기 검증 규모로 삼는다. 기본 구성은 입찰 역할 20명과 관전자 80명이고 집중 입찰 상황은 별도로 검증한다. 승인 목표는 입찰 클릭→승인·거절 표시 p95 ≤ 1초, 공식 상태 확정→다른 클라이언트 갱신 p95 ≤ 1초, 연결 재수립→최신 상태 표시 p95 ≤ 3초다. 합의한 시험 시나리오에서 정책상 잘못된 승인·거절, 중복 반영, 잘못된 낙찰은 0건이어야 한다. 현재 측정은 **NOT_RUN**이다. (R-48, R-49)

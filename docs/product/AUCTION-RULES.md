# 경매 운영 규칙 초안

- 기준일: 2026-10-14
- 기획 상태: 제품 책임자가 대화에서 승인한 정책을 반영함.
- 문서 상태: 초안. 개념상의 상태와 규칙을 기술하며 API, 데이터베이스, 구현 구조를 확정하지 않음.
- 구현·검증 상태: 미실행. 아래 사례는 승인된 정책에 따른 기대 결과이며 실행 결과가 아님.
- 관련 문서: [제품 개요](PRODUCT-BRIEF.md), [결정 및 미정 사항](DECISION-LOG.md)

## 1. 적용 범위와 읽는 방법

실제 개인 소유의 중고 물품을 출품하고 낙찰받는 웹 경매를 대상으로 한다. 포트폴리오라는 목적이 실제 출품·낙찰을 모의 거래로 제한한다는 뜻은 아니다. MVP는 경매 진행과 결과 기록을 제공하며 결제, 정산, 물품 전달은 서비스 밖에서 처리한다. 플랫폼의 경매 완료는 외부 거래 이행 완료를 의미하지 않는다.

본문의 **확정 규칙**은 승인된 업무 기준이다. `미정`으로 표시한 사항은 후속 합의 또는 설계·검증이 필요하며, 다른 에이전트가 임의로 승인된 정책으로 바꾸지 않는다. 상태 이름은 업무 설명용이며 실제 코드의 상태 값이나 저장 구조가 아니다.

## 2. 주요 용어와 관계

| 용어 | 의미 |
| --- | --- |
| 회차 | 모집 기간, 예약 시작 시각, 운영 레인 수, 상품별 대기 시간 설정을 묶어 운영하는 경매 단위 |
| 레인 | 같은 회차 안에서 상품을 하나씩 순서대로 경매하는 진행 단위. 운영 레인끼리는 독립적으로 진행함 |
| 상품 | 개인이 판매하려는 중고 물품과 상품명·설명·사진 등의 정보 |
| 출품 | 상품을 특정 모집 회차의 경매 대상으로 신청하는 행위와 그 신청 |
| 상품 경매 | 한 출품 상품의 준비, 입찰 경쟁, 낙찰·유찰·취소 처리까지의 진행 |
| 시작가 | 해당 상품의 첫 입찰 금액 |
| 희망가 | 출품자가 정한 낙찰 허용 최저 금액. 최고 유효 입찰가가 이 금액 이상이면 낙찰 가능 |
| 입찰 단위 | 첫 입찰 이후 현재 최고가에 더하는 고정 금액. 해당 상품에 출품자가 설정함 |
| 유효 입찰 | 참가 자격, 상품 상태, 금액, 마감 시각 등의 조건을 충족하여 서비스가 승인한 입찰 |
| 최고가·최고입찰자 | 현재 승인된 유효 입찰 중 최고 금액과 그 입찰자. 시작가 표시만으로 최고입찰자가 생기지는 않음 |
| 낙찰 | 경매 종료 시 최고 유효 입찰이 희망가 이상이어서 해당 입찰자와 금액을 결과로 확정하는 것 |
| 유찰 | 유효 입찰이 없거나 최고 유효 입찰가가 희망가에 미달한 채 정상 종료되는 것 |
| 취소 | 출품 철회 또는 운영자의 취소 처리. 정상 경쟁 종료에 따른 유찰과 구분함 |
| 중단 | 운영자가 레인의 입찰 접수와 진행 타이머를 멈춘 상태. 이미 승인된 입찰은 유지함 |
| 결과 보류 | 서비스 전체 장애 등으로 정상 진행·결과 판단을 확인해야 하므로 결과 확정을 보류한 상태 |
| 재출품 | 유찰 후 출품자가 다시 신청하는 것. 새 신청 순서를 적용하고 이전 회차의 유찰 기록은 보존함 |

한 회차에는 1~4개의 운영 레인이 있고, 각 레인에는 출품 상품이 배정된다. 각 레인은 한 번에 한 상품을 진행하며 다음 상품으로 이동한다. 상품 경매에는 여러 입찰이 참여할 수 있지만 낙찰되는 경우 그 경매의 최고 유효 입찰자 한 명과 금액이 결과가 된다. 재출품은 이전 경매 결과를 다시 여는 행위가 아니다.

## 3. 사용자와 권한

| 주체 | 확정 권한·제한 |
| --- | --- |
| 비회원 | 출품 목록까지 조회 가능. 상품 상세 조회는 로그인 필요. 출품·입찰 불가 |
| 일반 회원 | 가입 즉시 출품과 입찰 가능. 별도의 참가 승인 절차 없이 한 계정으로 두 역할을 수행 |
| 출품자 | 자신의 상품을 출품하고 허용 기간에 수정·취소. 자신의 희망가 확인 가능. 본인 출품 상품에는 입찰 불가 |
| 입찰자 | 다른 사람의 상품에 입찰. 여러 레인에 동시에 참여하고 여러 상품을 낙찰받을 수 있음. 승인된 입찰의 사용자 취소 불가 |
| 운영자 | 회차 등록, 공개 전 운영 레인 구성 변경, 시간 설정 관리, 레인 중단·재개, 진행 중 상품 취소, 확정 범위의 회차 취소 가능 |

운영자는 상품 취소 시 사유와 처리 이력을 남기고 기존 입찰 기록을 보존한다. 입찰 금액을 고치거나 낙찰자를 임의로 지정하는 권한은 승인 범위에 포함되지 않는다.

비회원에게 상품 상세 접근을 허용하는 것으로 결과의 `공개`를 해석하지 않는다. 목록에 표시할 구체적인 결과 필드와 회원·운영자의 세부 화면 권한은 후속 권한 명세에서 구체화한다. 운영자 계정이 일반 회원 기능을 겸하는지, 가입·인증 수단이 무엇인지는 아직 확정하지 않았다.

## 4. 회차 일정과 출품 접수

### 4.1 회차 등록과 모집

1. 운영자가 회차별 모집 기간, 예약 시작 시각, 운영 레인 수를 등록한다.
2. 주간 운영을 전제로 하지만 주 1회로 고정하거나 반복 일정에 따라 회차를 자동 생성하는 기능을 MVP에 포함하지 않는다.
3. 회차들의 모집 기간은 겹치지 않게 운영한다.
4. 출품 신청은 신청 당시 모집 중인 회차로 자동 배정한다.
5. 모집 중인 회차가 없으면 출품 신청을 받지 않고 다음 모집 일정을 안내한다.
6. 사전 공개 시작 직전에 해당 회차의 모집을 마감한다. 마감 이후 신청을 이전 회차에 추가하지 않는다.

다음 회차 정보가 아직 등록되지 않은 경우의 안내 문구와 회차 등록 시 일정 검증의 세부 조건은 후속 설계 항목이다.

### 4.2 사전 공개와 일정 고정

- 사전 공개는 **회차 예약 시작일 전날 0시**에 시작한다. 정확히 24시간 전을 뜻하지 않는다.
- 공개 기간에 출품 목록과 상세 정보를 미리 확인할 수 있다. 상세 조회에는 로그인이 필요하다.
- 사전 공개 전까지 운영 레인 구성을 수정할 수 있다.
- 공개 후에는 회차의 공개된 일정을 변경하지 않는다.
- 사전 공개 후 경매 시작 전에는 운영자가 회차 전체를 취소할 수 있다. 취소 기록을 남기고 다른 회차로 상품을 자동 이동시키지 않는다.
- 진행 중 회차 전체의 강제 취소·강제 마감 권한까지 승인된 것은 아니다. 진행 중 상품 취소와 레인 중단 권한은 별도 규칙을 따른다.

**서비스 기준 시간대는 미정이다.** 문서 작성일이나 사용자의 컴퓨터 시간대를 서비스 정책으로 간주하지 않는다.

### 4.3 예약 시작과 단일 진행 회차

- 한 회차의 운영 레인들은 같은 시작 시점에 출발하고 이후에는 독립적으로 진행·종료한다.
- 동시에 진행하는 회차는 하나로 제한한다.
- 예약 시각에 이전 회차가 이미 완료됐다면 해당 회차를 자동 시작한다.
- 예약 시각이 됐지만 이전 회차가 미완료라면 다음 회차는 대기한다. 이전 회차 완료 후 자동으로 시작한다.
- 이전 회차가 일찍 끝났다는 이유로 다음 회차를 예약 시각보다 앞당겨 시작하지 않는다.
- 이전 회차 지연에 따른 시작 대기는 공개된 예약 시각을 운영자가 임의로 수정하는 것과 구분한다.

복수 회차가 지연된 경우의 세부 실행 순서, 동일 예약 시각의 회차 등록 허용 여부, 지연 안내의 구체적인 화면 표현은 미정이다.

## 5. 출품 정보와 레인 배정

### 5.1 필수 정보와 가격 조건

| 항목 | 확정 조건 |
| --- | --- |
| 상품명 | 필수 |
| 설명 | 필수. 상태·특징 등은 설명에 자유롭게 작성 |
| 사진 | 1장 이상 필수 |
| 시작가 | 원화 정수, 0보다 큰 값 |
| 희망가 | 원화 정수, 0보다 크고 시작가 이상인 값 |
| 입찰 단위 | 원화 정수, 0보다 큰 값. 제공된 후보에서 선택하거나 직접 입력 가능 |

카테고리·상품 상태 분류는 첫 MVP의 필수 입력 항목에서 제외하고 확장 항목으로 둔다. 입찰 단위의 후보 목록, 가격 상한, 사진·문자열의 최대 개수와 크기는 미정이다.

출품자가 입찰 단위를 직접 입력할 수 있다는 것은 **입찰자가 원하는 입찰 금액을 자유롭게 입력할 수 있다는 뜻이 아니다.** 입찰자는 공개된 현재 가격을 기준으로 정해진 다음 금액에 입찰한다.

### 5.2 배정과 진행 순서

1. 운영자는 회차의 운영 레인 **개수**를 1~4개 중 선택한다. N개를 선택하면 1번부터 N번까지 사용한다.
2. 상품은 운영 레인 중 **대기 상품 수가 가장 적은 레인**에 자동 배정한다. 예상 대기 시간으로 배정하는 규칙이 아니다.
3. 레인 안에서는 출품 등록순으로 진행한다.
4. 공개 전에 운영 레인 구성이 바뀌면 해당 회차의 상품 전체를 변경된 구성에 맞춰 다시 자동 배정한다.
5. 재배정에도 최초 등록 시각을 기준으로 순서를 유지한다. 상품 수정 시각으로 등록순을 바꾸지 않는다.
6. 공개 후 상품이 취소되면 다른 상품의 레인과 상대적인 진행 순서를 유지하고 취소 상품만 건너뛴다.

대기 상품 수가 같은 레인 사이의 선택 기준, 동일 등록 시각의 순서 판정, 공개 전 개별 상품 취소 시에도 전체를 재배정할지는 미정이다. 구성 변경 시 재배정 규칙을 모든 상품 변경에 확대 적용하지 않는다.

### 5.3 출품자가 수정·취소할 수 있는 기간

| 시점 | 수정 | 출품 취소 |
| --- | --- | --- |
| 사전 공개 전 | 가능 | 가능 |
| 사전 공개 후, 해당 상품 경매 시작 전 | 불가 | 가능 |
| 해당 상품 경매 시작 후 | 불가 | 출품자에게 허용하지 않음. 운영자 처리 범위와 구분 |

공개된 가격·설명 등을 직접 수정하는 대신 출품을 취소하고 수정한 내용으로 다음 모집 회차에 다시 신청할 수 있다. 취소만으로 다른 회차에 자동 등록되지는 않는다.

준비 단계와 입찰 접수 시작의 정확한 경계, 시작 직전 출품 취소와 경매 시작이 동시에 발생하는 경우의 판정·안내는 후속 명세에서 명확히 해야 한다. 마감 경계의 입찰 접수 규칙을 출품 취소에 임의로 복제하지 않는다.

## 6. 상품 경매의 시간과 정상 진행

### 6.1 회차별 시간 설정

| 설정 | 현재 기본값 | 적용 의미 |
| --- | --- | --- |
| 준비 대기 시간 | 5초 | 다음 상품으로 이동한 뒤 입찰 시작까지의 준비 시간 |
| 최초 입찰 대기 시간 | 10초 | 입찰 시작 후 첫 유효 입찰을 기다리는 시간 |
| 후속 입찰 대기 시간 | 5초 | 마지막 유효 입찰 이후 다음 유효 입찰을 기다리는 시간 |

- 운영자가 회차마다 한 세트의 시간을 설정하며 같은 회차의 모든 운영 레인에 동일하게 적용한다.
- 회차가 시작할 때 적용 값을 확정하고 그 회차의 진행 중에는 바꾸지 않는다.
- 중단·재개도 같은 회차의 기존 설정값을 사용한다.
- 아래 설명의 5초·10초는 현재 기본값 예시다. 실제 판정은 해당 회차에 확정된 설정값을 따른다.
- 회차의 예약 일정과 상품별 대기 시간 설정은 서로 다른 개념이다.

### 6.2 정상 흐름

1. 회차 시작 또는 이전 상품 처리 후 다음 진행 대상 상품을 준비한다.
2. 준비 대기 시간이 지나면 입찰을 시작하고 최초 입찰 대기 시간을 부여한다.
3. 최초 대기 시간 동안 유효 입찰이 없으면 유찰 처리한다.
4. 첫 유효 입찰을 승인하면 그 입찰을 기준으로 후속 입찰 대기 시간을 적용한다.
5. 이후 새 유효 입찰마다 후속 대기 시간을 다시 부여한다.
6. 거절된 요청은 대기 시간을 갱신하지 않는다.
7. 후속 대기 시간 동안 새 유효 입찰이 없으면 낙찰 조건을 판정하고 결과를 기록한다.
8. 다음 상품이 있으면 그 상품의 준비 단계로 자동 이동한다. 취소 상품은 건너뛴다.

고정된 총 경매 시간이나 입찰 횟수 제한은 승인하지 않았다. 따라서 유효 입찰 경쟁이 이어지면 상품 종료 시점이 뒤로 늦어질 수 있다.

## 7. 입찰 승인과 거절

### 7.1 승인 조건

다음 조건을 충족하는 입찰을 승인한다.

- 로그인한 회원이며, 해당 상품의 출품자가 아니다.
- 대상 상품이 입찰 진행 중이고 레인이 중단되지 않았다.
- 현재 최고입찰자가 자신의 가격을 다시 올리는 요청이 아니다.
- 첫 유효 입찰이라면 제출 금액이 시작가다.
- 이미 유효 입찰이 있다면 제출 금액이 현재 최고가에 해당 상품의 입찰 단위를 더한 금액이다.
- 해당 시점의 마감 시각보다 먼저 서비스에 접수됐다.

여러 레인에 참여하고 있거나 다른 상품의 최고입찰자라는 이유만으로 입찰을 제한하지 않는다.

### 7.2 금액 경쟁과 마감 경계

- 현재 최고가는 참가자에게 공개한다.
- 같은 금액의 요청이 경쟁하면 서비스가 먼저 접수한 유효 입찰만 승인한다.
- 뒤의 요청 금액을 자동으로 한 단위 더 올리지 않는다. 바뀐 가격을 확인하고 새로 입찰해야 한다.
- 사용자 화면에서 버튼을 누른 시각이 아니라 **서비스 접수 시각**으로 마감을 판정한다.
- 접수 시각이 마감 시각보다 앞서야 한다. 마감 시각과 같거나 늦으면 거절한다.
- 마감 직전에 접수된 유효 입찰도 승인되면 후속 대기 시간을 새로 부여한다.

접수 순서의 구현 방법, 정밀도, 동일 기록 시각의 처리, 처리 지연 및 재전송의 중복 판정은 설계·검증 항목이다. 위 정책에 맞는 하나의 일관된 결과를 만들어야 하며, 구현 편의로 먼저 클릭한 사람 우선이나 자동 가격 인상으로 바꾸지 않는다.

### 7.3 대표 거절 사유

| 상황 | 결과 |
| --- | --- |
| 미로그인, 본인 출품 상품 | 입찰 거절 |
| 상품 준비 중, 레인 중단 중, 결과 보류 중 또는 이미 종료·취소된 상품 | 입찰 승인 조건 미충족 |
| 현재 최고입찰자의 재입찰 | 거절 |
| 다른 입찰로 가격이 바뀐 뒤 이전 금액을 제출 | 거절. 제출 금액 자동 인상 없음 |
| 시작가 또는 다음 입찰 금액과 맞지 않는 금액 | 거절 |
| 마감 시각과 같거나 늦은 접수 | 거절 |

거절과 처리 결과 미확인은 다르다. 응답을 받지 못했다는 이유만으로 실패·거절·성공 어느 쪽으로도 확정하지 않는다.

### 7.4 승인된 입찰의 효력

- 사용자는 승인된 입찰을 취소할 수 없다.
- 브라우저 종료, 개인의 연결 끊김, 다른 레인으로의 화면 이동 때문에 승인된 입찰이 사라지지 않는다.
- 운영자의 상품 경매 취소는 별도 처리이며 취소 사유와 입찰 기록을 보존한다.

## 8. 낙찰·유찰과 결과 조회

### 8.1 정상 종료 판정

| 종료 시 조건 | 결과 |
| --- | --- |
| 유효 입찰 없음 | 유찰 |
| 최고 유효 입찰가 < 희망가 | 유찰 |
| 최고 유효 입찰가 >= 희망가 | 최고 유효 입찰자에게 그 금액으로 낙찰 |

희망가에 도달하는 즉시 경매를 끝내는 것이 아니다. 희망가 이상이면 **낙찰 가능 상태**가 되고, 이후 경쟁이 끝나는 시점에 최종 최고가로 낙찰한다. 최고입찰자가 연결을 끊었더라도 승인된 입찰을 기준으로 동일하게 판단한다.

### 8.2 진행 중 표시와 종료 후 공개

- 희망가 금액은 다른 참가자에게 숨긴다. 출품자는 자신의 희망가를 확인할 수 있다.
- 최고가가 희망가 이상이 되면 낙찰 가능 구간 진입을 UI로 표시한다. 정확한 문구·색상 등은 후속 UX 설계 사항이다.
- 종료 후에도 출품 목록·상세를 유지하고 낙찰·유찰·취소 상태와 낙찰 금액을 공개한다.
- 낙찰자 정보는 출품자, 해당 낙찰자 본인, 운영자만 확인한다.
- 희망가 금액은 종료 후에도 공개하지 않는다.
- 비회원의 접근은 출품 목록까지라는 별도 권한 제한을 따른다.

낙찰자 정보의 구체적인 표시 항목, 비회원 목록에서 노출할 결과 필드, 유찰 상품의 마지막 최고가 공개 여부, 기록 보존 기간은 미정이다. 실명·연락처 공개나 무기한 보존을 임의로 추가하지 않는다.

### 8.3 재출품

- 유찰 상품은 다음 회차에 자동 등록하지 않는다. 출품자가 다시 신청한다.
- 기존 상품 정보를 활용하여 조건을 검토·수정하거나 그대로 다시 신청할 수 있다.
- 재출품의 대기 순서는 새 신청 시각으로 정한다.
- 이전 회차의 유찰 기록은 보존한다.
- 취소 상품을 자동 재출품하거나 취소된 회차의 상품을 자동 이동시키지 않는다.

## 9. 중단, 장애, 재접속

### 9.1 운영자의 레인 중단·재개

- 중단은 현재 상품의 입찰 접수와 타이머를 즉시 멈춘다. 현재 상품을 끝낸 뒤 다음 상품만 막는 방식이 아니다.
- 기존 유효 입찰과 최고가·최고입찰자는 유지한다.
- 입찰 단계에서 재개하면 중단 시점의 잔여 시간이 아닌 해당 단계의 대기 시간을 새로 부여한다.
  - 첫 유효 입찰 전: 해당 회차의 최초 입찰 대기 시간.
  - 유효 입찰 후: 해당 회차의 후속 입찰 대기 시간.
- 가격과 입찰 이력을 초기화하거나 새 회차의 시간 설정으로 바꾸지 않는다.

준비 단계에서의 중단·복구 세부 동작과 별도의 재개 예고 시간은 미정이다. 다음 상품의 준비 대기 시간을 장애 재개 예고 시간으로 임의 전용하지 않는다.

### 9.2 참가자 개인의 연결 끊김

- 경매는 계속 진행하고 승인된 입찰의 효력을 유지한다.
- 끊긴 동안 상품이 낙찰·유찰되거나 다음 상품으로 넘어갈 수 있다.
- 재접속하면 과거 화면이 아니라 최신 상품, 가격, 진행 상태, 남은 시간 등 현재 경매 화면으로 복귀한다.
- 본인의 미확인 입찰 처리 결과나 낙찰 결과를 함께 안내한다.
- 서비스에 기록된 결과로 승인 여부를 확인한다. 확인되지 않은 요청은 `처리 확인 중`으로 구분한다.

전체 입찰 내역의 재생이나 외부 알림 발송까지 복구 범위로 확정된 것은 아니다. 요청 재전송과 중복 처리 방지는 후속 설계·검증 대상으로 남긴다.

### 9.3 서비스 전체 장애

- 정상적인 입찰 접수가 불가능했던 진행 중 상품은 결과 확정을 보류한다.
- 기록된 유효 입찰을 유지하고 운영자가 상태를 확인한 뒤 재개한다.
- 장애 중 시간이 흘렀다는 사실만으로 정상 종료가 확인된 것으로 보지 않는다.
- 재개 시 입찰 단계의 대기 시간은 9.1의 규칙을 따른다.
- 이미 확정된 과거 낙찰·유찰 결과를 장애 때문에 다시 열거나 재경매하지 않는다.

장애 감지·판정 기준, 마지막 정상 상태 확인, 복구 자료와 절차, 영속화 및 재전송의 정확성은 아직 기술 검증 전이다. 정책 승인 자체가 장애 시 데이터 보존 능력을 입증하지는 않는다.

## 10. 취소 후 진행과 회차 완료

### 10.1 운영자가 진행 중 상품을 취소하는 경우

| 취소 전 레인 상태 | 취소 후 동작 |
| --- | --- |
| 진행 중 | 취소 상품을 건너뛰고 다음 진행 대상 상품의 준비 단계로 이동 |
| 중단 중 | 중단 상태 유지. 취소를 재개 명령으로 취급하지 않음 |
| 처리할 상품과 보류 결과가 모두 없음 | 해당 레인 종료 |

취소는 유찰과 구분하여 기록하고, 사유·처리 이력·기존 입찰 기록을 보존한다. 다른 상품의 레인과 상대적인 순서를 바꾸지 않는다.

### 10.2 레인과 회차의 종료

- 처리할 상품과 보류 결과가 모두 없는 레인은 종료한다.
- 같은 회차의 다른 레인이 진행 중이어도 완료된 레인은 종료 상태를 유지할 수 있다.
- 해당 회차의 **운영 레인 모두**가 종료되고 보류 상품이 없으면 회차를 자동 완료한다. 운영하지 않는 레인을 기다리지 않는다.
- 회차 완료를 위해 별도의 운영자 최종 승인 단계를 두지 않는다.
- 완료는 경매 진행과 결과 기록의 완료다. 외부 결제·정산·물품 전달의 완료를 뜻하지 않는다.

모든 상품이 시작 전에 취소되거나 처음부터 상품이 없는 회차의 표시 상태·종료 처리 시점은 미정이다. 빈 회차를 유찰로 간주하거나 완료 시각을 임의 확정하지 않는다.

## 11. 개념상의 상태 전이

### 11.1 회차

| 현재 상태 | 사건·조건 | 다음 상태·처리 |
| --- | --- | --- |
| 모집 전 | 모집 시작 | 모집 중 |
| 모집 중 | 시작 전날 0시의 사전 공개 시점 도래 | 모집 마감, 사전 공개 |
| 사전 공개 | 예약 시각 도래, 이전 회차 완료 | 운영 레인 동시 시작, 진행 중 |
| 사전 공개 | 예약 시각 도래, 이전 회차 미완료 | 이전 회차 종료 대기 |
| 이전 회차 종료 대기 | 이전 회차 완료 | 자동 시작, 진행 중 |
| 사전 공개·시작 대기 | 시작 전 운영자 회차 취소 | 취소 기록 유지, 자동 다른 회차 이동 없음 |
| 진행 중 | 모든 운영 레인 종료, 보류 상품 없음 | 완료 |

레인 중단·상품 결과 보류는 회차 완료를 막을 수 있다. 회차 전체 상태와 레인별 상태를 실제 화면·저장 모델에 어떻게 표현할지는 별도 설계한다.

### 11.2 상품 경매

| 현재 상태 | 사건·조건 | 다음 상태·처리 |
| --- | --- | --- |
| 순서 대기 | 진행 순서 도래 | 준비 |
| 준비 | 준비 시간 경과 | 입찰 진행, 최초 입찰 대기 시작 |
| 입찰 진행 | 유효 입찰 승인 | 최고가·최고입찰자 반영, 후속 대기 시간 갱신 |
| 입찰 진행 | 입찰 거절 | 승인 상태와 마감 시간 유지 |
| 입찰 진행 | 대기 시간 종료, 정상 판정 가능 | 낙찰 또는 유찰 |
| 입찰 진행 | 운영자 레인 중단 | 중단, 입찰·타이머 정지 |
| 진행 중 | 서비스 전체 장애로 정상 진행 불가 | 결과 보류 및 유효 입찰 유지 |
| 중단·결과 보류 | 운영자 확인 후 입찰 단계 재개 | 기존 유효 입찰 유지, 해당 단계 대기 시간 새로 부여 |
| 시작 전 | 허용 기간에 출품자 취소 | 취소 |
| 입찰 진행·중단 | 운영자 상품 취소 | 취소, 레인의 기존 진행·중단 상태에 따라 후속 처리 |

낙찰·유찰·취소 결과를 임의로 진행 중 상태로 되돌리는 기능은 승인 범위에 없다. 재출품은 새 신청으로 다룬다.

## 12. 대표 경계 사례와 기대 결과

다음은 향후 검증에 사용할 정책 사례이며, 테스트 실행 결과가 아니다.

| 사례 | 기대 결과 |
| --- | --- |
| 시작가 1만 원, 최초 대기 10초 동안 유효 입찰 없음 | 유찰 |
| 희망가 2만 원, 최종 최고가 1만 9천 원 | 유찰 |
| 희망가 2만 원, 최종 최고가 정확히 2만 원 | 낙찰. 동액도 허용 |
| 현재가 1만 원·단위 1천 원에서 두 사람이 1만 1천 원 요청 | 먼저 접수된 유효 요청 승인, 뒤 요청 거절. 뒤 요청을 1만 2천 원으로 바꾸지 않음 |
| 마감 시각과 정확히 같은 시각에 요청 접수 | 거절, 시간 갱신 없음 |
| 마감 직전 유효 입찰 접수 | 승인 후 후속 대기 시간 새로 부여 |
| 최고입찰자가 다시 입찰하거나 본인 출품에 입찰 | 거절, 시간 갱신 없음 |
| 최고입찰자의 개인 연결 끊김 | 기존 입찰 유지. 정상 종료 시 희망가 조건에 따라 낙찰 가능 |
| 응답을 못 받은 입찰의 결과가 아직 확인되지 않음 | 실패로 단정하지 않고 처리 확인 중으로 구분 |
| 장애 중 유효 입찰이 있던 상품의 시간이 경과 | 결과 보류 후 확인·재개. 기록된 유효 입찰 유지 |
| 중단 레인의 현재 상품을 운영자가 취소 | 중단 유지. 다음 상품을 자동으로 입찰 진행시키지 않음 |
| 이전 회차가 다음 회차 예약 시각까지 미완료 | 다음 회차 대기. 이전 회차 완료 후 자동 시작 |
| 이전 회차가 다음 회차 예약 시각보다 일찍 완료 | 다음 회차를 예약 시각보다 앞당기지 않음 |
| 유찰 상품 재출품 | 새 신청 순서 적용, 이전 유찰 기록 보존 |

## 13. 미정 사항과 기술 검증 경계

상세 목록과 결정 이력은 [DECISION-LOG.md](DECISION-LOG.md)를 기준으로 관리한다. 특히 다음을 후속 단계에서 구체화해야 한다.

| 구분 | 남은 사항 |
| --- | --- |
| 추가 정책·표시 기준 | 서비스 시간대, 빈 회차의 처리 시점, 동률 레인 배정·동일 등록 시각의 순서, 공개 전 개별 취소 시 재배정 여부 |
| 일정·운영 경계 | 복수 지연 회차와 같은 예약 시각 처리, 준비 단계 중단 복구, 시작 직전 출품 취소 경계, 재개 예고 필요 여부 |
| 입력·권한·조회 | 입찰 단위 후보·입력 상한, 사진·텍스트 제한, 가입 방식과 운영자 겸용 권한, 비회원 목록 결과 필드, 낙찰자 표시 항목·기록 보존 기간 |
| 설계·검증 | 접수 순서와 마감 판정의 일관성, 중복 요청과 불명확한 응답 복구, 장애 판정·데이터 보존·재개, 실제 시간과 화면 시간의 동기화 |
| 성능 수용 기준 | 4레인·동시 참여자 100명을 대상으로 한 구체적인 입찰 빈도, 시험 시간, 지연·오류 판정 기준과 실행 환경 |

기획 승인 범위에서 확정된 규칙을 구현하기 위한 기술 선택은 별도 세션에서 검토한다. Java·Spring Boot는 우선 고려 사항이고 React는 후보이며, 통신 방식·저장소·분산 구조 등은 이 문서가 결정하지 않는다. 100명은 검증 목표이고 현재 처리 능력이나 운영 안정성이 입증됐다는 의미가 아니다.

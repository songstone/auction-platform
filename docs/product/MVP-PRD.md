- 버전: 1.0
- 요구사항 승인: 2026-10-14, 제품 책임자의 전체 요구사항 승인 응답 `승인`
- 승인 범위: 아래 제품 요구사항·인수 조건·MVP 제외 범위 및 미결정 사항의 후속 처리 방식
- 상태: 승인된 제품 기준선. 상세 설계·기술 선택·구현 완료를 의미하지 않는다.
- 실행 검증: 기능·동시성·장애·브라우저·성능 모두 `NOT_RUN`
- 관련 문서: [제품 개요](PRODUCT-BRIEF.md), [경매 규칙](AUCTION-RULES.md), [결정 기록](../decisions/DECISION-LOG.md)

## 1. 문서 사용 기준

이 문서는 현재 대화에서 다시 확인하고 승인한 요구사항과 인수 조건의 정본이다. 기존 문서는 참고 자료이며, 현재 승인과 다른 과거 정책의 변경 이력은 결정 기록에 남긴다. 모든 `G-01`, `R-01`~`R-52`는 확정 요구사항이다. `AC-*`는 이를 검증할 때 확인해야 하는 기대 결과로, 테스트 통과 기록이 아니다.

경매 규칙 문서는 업무 흐름과 경계를 설명한다. 결정 기록은 승인 이력, 현재 검토 중인 제안(`PROP-*`), 검증할 가설(`HYP-*`), 아직 결정되지 않은 정책(`OPEN-*`), 주요 위험(`RISK-*`)을 구분한다. 미결정 사항은 구현자가 임의로 확정하지 않으며, 관련 상세 설계·검증·실제 운영 단계 전에 제품 책임자가 결정한다.

인수 조건의 수치 예시는 규칙을 확인하기 위한 시험 자료다. 허용 금액 목록이나 제품 상한을 추가로 정하는 의미가 아니다. 접수 순서·동시 사건 판정 등 기술적 정의가 필요한 조건은 해당 정의 승인 후 실행 가능한 시험으로 구체화한다.

## 2. 목적과 사용자 흐름

개인이 실제 중고 물품을 출품하고 여러 구매자가 실시간으로 경쟁하여 가격과 낙찰자를 정한다. 과거 TCP/IP·Swing 기반 중고차 경매 경험을 웹 서비스로 발전시키는 포트폴리오로서, 현재 진행 상태의 이해, 입찰의 정확성, 데이터 정합성과 예외 복구를 핵심으로 삼는다.

| 사용자 | 핵심 흐름 | 연결 요구사항 |
| --- | --- | --- |
| 비회원 | 공개된 상품 목록·상세·실시간 진행·종료 결과 확인 → 출품·입찰 시 가입 및 로그인 | R-37, R-38, R-45 |
| 출품자 | 이메일 검증 가입 → 모집 중 회차에 출품 → 허용 기간 수정·취소 → 내 출품/결과 확인 → 낙찰 시 상대 이메일 확인 → 외부 거래 | R-12, R-16, R-32, R-33, R-35, R-36, R-39, R-51 |
| 입찰자 | 상품 사전 확인 → 로그인 → 여러 레인의 진행·현재가 확인 → 버튼 입찰 → 승인/거절/처리 확인 중 확인 → 결과 및 해당 거래 연락처 확인 | R-02, R-10, R-17~R-23, R-38, R-39, R-51 |
| 운영자 | 사전 지정 계정 사용 → 회차 일정·레인 수·시간 설정 → 자동 진행 확인 → 예외 시 레인 중단/확인/재개 또는 현재 상품 취소 → 회차 자동 완료 확인 | R-06, R-07, R-14, R-15, R-24~R-29, R-31, R-41~R-44, R-52 |

출품자와 입찰자는 한 회원이 수행하는 역할이다. 운영자 화면 및 계정 준비 방식의 기술 구현은 후속 설계 대상이다. 운영자라는 이유만으로 모든 개인 정보에 대한 조회 권한을 부여하지 않는다.

## 3. 요구사항과 인수 조건

### 3.1 제품 목적과 범위

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| G-01 | 웹 실시간 경매의 진행·정확성·정합성·복구를 설명하고 입증하는 개발자 포트폴리오를 만든다. 객체지향 설계, 유지보수성과 테스트 가능성을 중시한다. | **AC-G01-01:** 최종 포트폴리오에서 출품→경매→결과 및 동시 입찰·종료 경계·복구 시나리오를 해당 요구사항, 설계 판단, 구현, 독립 검증 증거에 연결해 설명할 수 있다. 미실행 항목을 통과로 표현하지 않는다. 현재 문서는 제품 기준만 제공한다. |
| R-01 | 개인이 중고 물품을 출품하고 여러 구매자가 경쟁 입찰한다. | **AC-R01-01:** 서로 다른 회원인 출품자 1명과 구매자 2명이 한 상품의 출품·경쟁 입찰·최종 결과 확인 흐름을 수행할 수 있다. |
| R-02 | 실시간 경매 진행 상태 확인과 입찰을 핵심 경험으로 제공한다. | **AC-R02-01:** 진행 화면에서 대상 상품, 진행 단계, 현재 가격, 본인의 입찰 처리 결과, 최종 결과를 구분할 수 있다. `처리 확인 중`과 승인·거절, 최저낙찰가 도달과 최종 낙찰이 서로 다른 상태로 표현된다. |
| R-03 | 실제 출품과 낙찰을 다루며 결제·정산·물품 전달은 서비스 밖에서 처리한다. | **AC-R03-01:** 서비스 내부 결제·정산·배송 절차를 거치지 않아도 경매 결과가 확정되고 당사자가 이를 조회할 수 있다. 낙찰 또는 회차 완료를 외부 대금 지급·물품 전달 완료로 표시하지 않는다. |
| R-04 | 각 레인은 한 번에 상품 하나를 경매하고 종료 후 다음 상품으로 독립 전환한다. | **AC-R04-01:** 4개 레인에서 한 레인의 경쟁이 연장되거나 중단되어도 다른 레인의 상품·가격·마감·전환은 해당 레인의 규칙대로 진행한다. 한 레인에서 두 상품의 입찰을 동시에 접수하지 않는다. |
| R-05 | 결제·정산의 향후 확장이 가능하도록 고려하되 현재 MVP에 구현하지 않는다. | **AC-R05-01:** 후속 설계 검토에서 낙찰 결과와 향후 결제·정산의 책임 경계 및 연결 시 고려사항을 설명하고, 현재 경매가 결제 모듈 없이 동작함을 확인한다. 이번 문서에는 결제 테이블·클래스·연동 기술을 확정하지 않는다. |
| R-06 | 상품 준비·입찰 개시·종료·다음 상품 전환은 자동이며 운영자는 예외에 개입한다. | **AC-R06-01:** 정상 회차에서 운영자의 상품별 시작·마감 버튼 조작 없이 준비→입찰→결과→다음 상품 준비가 이어진다. 예외 중단·보류 중에는 자동 진행이 해당 규칙을 우회하지 않는다. |
| R-07 | 모집 기간과 예약 시작 시각을 가진 회차로 운영한다. | **AC-R07-01:** 운영자가 회차의 모집 일정과 예약 시작 시각을 준비할 수 있고, 출품은 모집 중 회차에 귀속되며 예약 시각 및 선행 회차 조건에 따라 자동 시작한다. |

### 3.2 가격, 입찰 방식과 시간

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-08 | 첫 유효 입찰부터 후속 입찰 대기로 전환하고, 이후 유효 입찰마다 후속 대기 시간을 새로 부여한다. | **AC-R08-01:** 첫 유효 입찰 후 후속 대기 단계가 시작되고, 새 유효 입찰마다 그 회차의 후속 대기 전체 시간이 적용된다. **AC-R08-02:** 거절 요청 전후에 최고가·최고입찰자·마감이 변하지 않으며, 추가 유효 입찰 없이 대기가 끝나면 결과를 판정한다. 정확한 시간 기준점의 기술 정의는 후속 설계에서 결정한다. |
| R-09 | 시작가와 최저낙찰가는 별도다. 최종 최고 유효 입찰가가 최저낙찰가 이상이면 낙찰하며, 미달 또는 무입찰이면 유찰한다. | **AC-R09-01:** 유효 입찰 없음, 최저낙찰가 미만, 정확히 같음, 초과의 네 경우 결과가 각각 유찰·유찰·낙찰·낙찰이다. 낙찰자와 낙찰가는 최종 최고 유효 입찰의 회원과 금액이다. |
| R-10 | 첫 입찰은 정확히 시작가, 이후 입찰은 정확히 현재 최고가+입찰 단위의 버튼 입찰이다. | **AC-R10-01:** 시작가 10,000원·단위 1,000원일 때 첫 승인 금액은 10,000원이며, 이후 현재 최고가가 10,000원이면 다음 승인 가능 금액은 11,000원이다. 다른 금액은 거절한다. 자유 금액·자동 대리입찰 기능은 제공하지 않는다. |
| R-11 | 최저낙찰가 금액은 구매자·일반 조회자에게 숨기고 도달 여부만 표시한다. | **AC-R11-01:** 공개 화면과 해당 사용자에게 전달되는 조회 내용에 최저낙찰가 원금액이 없고, 현재 최고가에 따른 도달/미도달을 확인할 수 있다. 도달만으로 경매를 종료하거나 최종 낙찰을 표시하지 않는다. |
| R-12 | 출품자는 시작가·최저낙찰가를 정하고 입찰 단위는 후보 선택을 기본으로 직접 입력도 할 수 있다. | **AC-R12-01:** 동일한 출품 흐름에서 입찰 단위를 제공 후보로 선택하거나 직접 입력하여 저장할 수 있으며, 두 방식 모두 R-46의 가격 조건을 따른다. 후보의 정확한 값은 미정이다. |
| R-13 | 기본 시간은 준비 5초, 최초 입찰 대기 10초, 후속 입찰 대기 5초다. | **AC-R13-01:** 기본 설정에서 준비 중에는 입찰을 승인하지 않고, 준비 5초 종료 후 최초 대기를 시작한다. 최초 대기 10초 동안 유효 입찰이 없으면 유찰한다. 유효 입찰 발생 후에는 후속 대기 5초를 적용한다. |
| R-14 | 준비·최초·후속 대기 시간을 회차별로 조정할 수 있다. | **AC-R14-01:** 운영자가 회차 시작 전에 각 시간 값을 설정하면 그 회차의 준비·최초·후속 단계가 해당 설정값을 따른다. 다른 회차의 설정값을 변경하지 않는다. 허용 입력 범위는 후속 결정한다. |
| R-15 | 회차별 시간 한 세트를 모든 운영 레인에 적용하고 실제 회차 시작 시 고정한다. | **AC-R15-01:** 한 회차의 모든 레인이 같은 시간 설정을 사용한다. 실제 시작 전에는 설정을 바꿀 수 있고, 실제 시작 후에는 중단·재개를 포함하여 원래 확정값이 유지되며 변경 요청을 적용하지 않는다. 공개 일정의 고정과는 별개다. |

### 3.3 입찰 자격, 경쟁과 처리 확인

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-16 | 가입이 완료된 회원은 별도 참가·출품자 승인 없이 출품과 입찰 역할을 모두 수행한다. | **AC-R16-01:** 이메일 검증으로 가입을 완료한 동일 회원이 운영자의 추가 승인 없이 상품을 출품하고 다른 회원의 상품에 입찰할 수 있다. |
| R-17 | 본인 출품 상품에는 입찰할 수 없다. | **AC-R17-01:** 출품자 계정의 본인 상품 입찰을 거절하고 최고가·최고입찰자·마감을 변경하지 않는다. |
| R-18 | 현재 최고입찰자는 다른 사람이 최고입찰자가 될 때까지 재입찰할 수 없다. | **AC-R18-01:** 최고입찰자의 재입찰을 거절하고 가격·마감을 유지하며, 다른 회원이 최고입찰자가 된 후에는 정상 조건의 재입찰을 허용한다. **AC-R18-02:** 시작가가 최저낙찰가 미만이고 한 사람만 입찰한 경우 자기 증액을 허용하지 않으며, 추가 경쟁 없이 마감되면 유찰된다. |
| R-19 | 한 회원의 복수 레인 입찰과 복수 상품 낙찰을 허용한다. | **AC-R19-01:** 다른 상품의 최고입찰자이거나 이미 낙찰받은 회원이 다른 레인 상품에 유효 입찰을 제출하면 그 이유로 제한하지 않는다. 각 상품 조건을 충족하면 여러 상품을 낙찰받는다. |
| R-20 | 사용자는 승인된 입찰을 철회할 수 없다. | **AC-R20-01:** 승인 후 사용자 철회로 가격·최고입찰자·마감을 되돌릴 수 없다. 운영자의 현재 상품 경매 취소는 별도 결과와 이력으로 처리한다. |
| R-21 | 서비스의 공식 접수 순서·시각을 따른다. 동일 금액 경쟁은 먼저 접수된 유효 요청만 승인하고 마감 시각 이상인 요청은 거절한다. 제출 금액을 자동 인상하지 않는다. | **AC-R21-01:** 같은 다음 입찰 금액을 두 회원이 경쟁 제출하면 먼저 접수된 유효 요청 하나만 승인한다. 먼저 접수된 요청이 무효라면 뒤의 유효 요청을 그 이유로 막지 않는다. **AC-R21-02:** 현재 유효 마감 직전 접수된 유효 요청은 승인하여 대기를 갱신하고, 현재 유효 마감 정각·이후 접수는 거절한다. **AC-R21-03:** 오래된 화면의 금액을 제출한 요청은 금액 조건 불충족 시 거절하고, 더 높은 금액으로 바꾸어 승인하지 않는다. 공식 접수의 정의·정밀도·처리 지연 관계는 설계 승인 후 시험한다. |
| R-22 | 개인 연결 끊김은 경매를 멈추거나 승인 입찰을 무효로 하지 않는다. | **AC-R22-01:** 최고입찰자의 연결을 끊어도 다른 참가자의 경매가 진행되고 기존 입찰이 유지된다. 그 입찰이 정상 종료 시 최종 최고이며 최저낙찰가 이상이면 연결 여부와 관계없이 낙찰된다. |
| R-23 | 응답 유실·미확인 결과를 `처리 확인 중`으로 표시하고 기록 확인 전에는 해당 요청을 보낸 회원의 해당 상품 경매 신규 입찰만 막는다. | **AC-R23-01:** 요청 응답을 받지 못하면 승인·실패를 추정하지 않고 처리 확인 중으로 표시한다. 기록된 결과 확인 전 해당 회원의 해당 상품 경매 신규 입찰을 차단한다. 다른 회원의 해당 상품 입찰과 해당 회원의 다른 상품·레인 입찰은 이 사유로 차단하지 않는다. **AC-R23-02:** 재접속 후 최신 경매 상태 및 본인의 미확인 입찰·낙찰 결과를 확인할 수 있다. 기록된 승인·거절을 확인하면 표시가 해당 결과와 일치한다. 미확인 상태의 종료 기준과 중복 요청 판별은 후속 설계한다. |

### 3.4 중단·장애와 복구

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-24 | 전체 서비스 장애로 정상 입찰 접수가 불가능하면 진행 중 상품 결과를 보류하고 기록된 유효 입찰을 유지하며 운영자 확인 후 재개한다. | **AC-R24-01:** 전체 장애가 입찰 진행 중 발생한 시나리오에서 시간 경과만으로 결과를 정상 낙찰·유찰로 확정하지 않는다. 기록된 유효 입찰이 보존되고 운영자 확인 없이 자동 재개하지 않는다. 장애 감지·범위·복원 불가 시 처리는 후속 결정한다. |
| R-25 | 재개 시 가격·최고입찰자를 유지하고 중단된 단계의 전체 설정 시간을 다시 부여한다. | **AC-R25-01:** 준비·최초 대기·후속 대기 각각의 수동 중단과 전체 장애 복구를 검증하여, 같은 회차에 고정된 해당 단계 전체 시간을 재개 시 부여하는지 확인한다. 잔여 시간만 이어가지 않고, 승인된 입찰·가격·최고입찰자를 초기화하지 않는다. 준비/무입찰 단계에서 존재하지 않던 최고입찰자를 생성하지 않는다. |
| R-26 | 운영자는 레인을 즉시 중단·재개하고 현재 상품 경매를 취소할 수 있다. | **AC-R26-01:** 운영자의 중단이 반영되면 현재 상품의 입찰 접수와 타이머가 멈추고 기록은 유지된다. 재개는 R-25를 따른다. **AC-R26-02:** 현재 상품 취소를 유찰과 구분하고 취소 사유·기존 입찰·처리 이력을 보존한다. 취소 후 진행은 R-43을 따른다. 동시 사건의 선후 판정은 후속 결정한다. |

### 3.5 회차·배정·출품

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-27 | 회차별 운영 레인 수는 1~4개 중 선택한다. | **AC-R27-01:** 운영자가 1·2·3·4개 각각의 회차를 구성할 수 있으며 선택된 개수의 레인에서 경매를 진행한다. 0개·5개 설정을 허용하지 않는다. |
| R-28 | 대기 상품 수가 가장 적은 운영 레인에 자동 배정하고 레인 안에서는 최초 출품 등록순으로 진행한다. | **AC-R28-01:** 대기 수의 최솟값이 하나인 조건에서 새 상품이 해당 레인에 배정된다. 동일 레인 상품은 최초 등록순으로 진행하며 수정 시각으로 순서를 바꾸지 않는다. 대기 수·등록 시각 동률의 기대 결과는 후속 승인한다. |
| R-29 | 실제 회차 시작 때 운영 레인들이 첫 상품의 준비를 함께 시작하고 이후 독립 진행한다. | **AC-R29-01:** 상품이 있는 운영 레인들의 첫 준비가 같은 회차 시작 사건에 따라 시작된다. 한 레인의 유효 입찰로 다른 레인의 준비·마감이 함께 연장되지 않는다. 빈 레인은 R-42에 따른다. |
| R-30 | 모집 마감 및 사전 공개는 예약 시작일의 전날 00:00, Asia/Seoul 기준이다. | **AC-R30-01:** 예약 시작이 10월 20일 14:00이면 10월 19일 00:00에 모집이 마감되고 사전 공개가 시작된다. 10월 19일 14:00으로 계산하지 않는다. 사전 공개 중에는 추가 출품을 받지 않는다. 정확히 경계에 겹친 요청 판정은 후속 결정한다. |
| R-31 | 동시에 진행하는 회차는 하나다. 이전 회차가 미완료면 다음 회차는 대기·지연 표시 후 이전 완료 시 자동 시작한다. | **AC-R31-01:** 다음 예약 시각에 이전 회차가 미완료이면 다음 회차 입찰을 시작하지 않고 지연을 표시한다. 이전 회차 완료 후 운영자 시작 조작 없이 시작한다. **AC-R31-02:** 이전 회차가 일찍 완료돼도 다음 회차를 예약 시각보다 먼저 시작하지 않는다. 중단·보류로 미완료인 회차도 이 조건에 포함한다. |
| R-32 | 모집 기간은 서로 겹치지 않으며 새 출품은 현재 모집 중인 회차에 자동 귀속된다. | **AC-R32-01:** 모집 기간이 중복되는 회차 설정을 허용하지 않는다. 모집 중 회차가 하나면 출품을 그 회차에 배정한다. 모집 회차가 없으면 출품을 받지 않고, 설정된 다음 모집 일정이 있으면 안내한다. **AC-R32-02:** 다른 회차가 진행 중이라는 이유만으로 이미 설정된 미래 회차의 모집을 금지하지 않는다. 모집 중 회차와 진행 중 회차는 별개다. |
| R-33 | 사전 공개 전에는 출품자 수정·취소가 가능하다. 공개 후 수정은 금지하고 입찰 접수 개시 전까지만 취소한다. | **AC-R33-01:** 공개 전 수정·취소는 허용하고 공개 후 수정은 거절한다. 공개 후 순서 대기·준비 단계의 취소는 허용한다. **AC-R33-02:** 최초 입찰 대기가 시작되면 아직 유효 입찰이 없어도 출품자 취소를 거절한다. 취소/입찰 개시 동시 사건은 후속 승인 기준으로 검증한다. |
| R-34 | 공개 전 레인 수 변경은 전체 자동 재배정한다. 공개 후 배치를 고정하고 취소 상품만 건너뛴다. | **AC-R34-01:** 공개 전 레인 수를 바꾸면 전체 상품을 다시 배정하며 각 레인 내 최초 등록순을 유지한다. 공개 후 레인 수·배치를 바꾸는 요청은 적용하지 않는다. **AC-R34-02:** 공개 후 하나를 취소해도 다른 상품의 레인 및 상대 순서는 같고 취소 상품의 입찰을 시작하지 않는다. 공개 전 일반 수정·취소 시 재배정 여부는 별도 미정이다. |
| R-35 | 필수 출품 정보는 상품명·설명·사진 1장 이상·시작가·최저낙찰가·입찰 단위다. | **AC-R35-01:** 필수 정보 중 하나가 없거나 사진이 0장이면 출품을 완료할 수 없다. 상품 상태·하자는 설명으로 기재할 수 있으며 별도 카테고리·상태 분류 입력을 강제하지 않는다. 텍스트·사진의 상세 제한은 후속 결정한다. |
| R-36 | 유효한 상품 정보와 가격 조건을 만족하면 운영자 상품 심사 없이 출품된다. | **AC-R36-01:** 모집 중에 필수 정보와 가격 조건을 충족한 출품은 운영자의 승인 대기 단계 없이 해당 회차에 등록·배정된다. 입력 검증과 상품 심사 절차를 혼동하지 않는다. |

### 3.6 조회·결과·운영 권한

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-37 | 비회원은 공개된 목록·상세·실시간을 볼 수 있고 출품·입찰은 로그인이 필요하다. | **AC-R37-01:** 로그아웃 상태에서도 사전 공개된 목록·상세와 실시간 진행을 확인할 수 있다. 미공개 상품을 공개 조회 경로로 노출하지 않는다. **AC-R37-02:** 비회원 출품·입찰을 허용하지 않으며 로그인한 회원은 각 업무 조건에 따라 수행할 수 있다. |

| R-39 | 낙찰된 거래의 출품자와 낙찰자는 상대방의 검증된 가입 이메일을 외부 거래 연락처로 확인한다. | **AC-R39-01:** 낙찰 확정 후 출품자는 해당 낙찰자 이메일을, 낙찰자는 해당 출품자 이메일을 확인할 수 있다. 유찰·취소 또는 무관한 제3자 조회에 이 권한을 부여하지 않는다. **AC-R39-02:** 외부 연락·결제·물품 전달 완료를 별도로 추적하는 기능을 MVP 흐름에 요구하지 않는다. 운영자 이메일 조회 권한은 이 조건으로 확정하지 않는다. |
| R-40 | 유찰 상품은 출품자의 새 신청으로만 재출품하고 새 신청 시각을 적용하며 이전 이력을 유지한다. | **AC-R40-01:** 유찰만으로 다음 회차에 자동 등록하지 않는다. 출품자가 모집 중 회차에 새로 신청하면 새 신청 시각으로 배정·순서를 정하고 이전 유찰 결과를 조회할 수 있다. 상품 복사 편의 기능의 제공을 뜻하지 않는다. |
| R-41 | 공개 후 실제 시작 전 회차의 예약 일정은 임의 변경할 수 없고, 해당 회차를 취소할 수 있다. 취소 이력을 남기고 출품을 자동 이전하지 않는다. | **AC-R41-01:** 공개 후 예약 시작 시각의 임의 변경을 허용하지 않는다. 실제 시작 전 회차 취소 시 취소 이력을 남기고 상품을 다른 회차에 자동 등록하지 않는다. R-31의 선행 회차 지연은 허용된 자동 동작으로 구분한다. 진행 중 회차 전체 강제 취소 권한은 포함하지 않는다. |

### 성능 목표의 해석

- 기본 시험은 동시 연결 100명 중 입찰 역할 20명과 관람 역할 80명이다. 20명 모두가 매초 입찰한다는 뜻은 아니다.
- 클릭→판정 표시는 사용자가 본 승인·거절까지, 상태 전달은 권위 있는 상태 확정→다른 화면까지, 재접속은 연결 재수립→현재 상태 복원까지 측정한다. 각 측정 경계를 혼용하지 않는다.
- p95는 모든 요청이 1초 또는 3초 이내라는 보장이 아니다. 최대 지연 목표는 별도 미정이다.
- 공식 접수·상태 확정의 정확한 정의, 시험 환경/네트워크/빈도/기간/집중 패턴/반복 횟수, 실패·미확인·시간초과 표본의 처리와 측정 방법을 실행 전에 결정한다. 불리한 표본을 임의로 제외하고 합격을 선언하지 않는다.
- 정확성 0건은 합의된 시험에서 정책과 다른 승인·거절, 중복 효과, 오낙찰을 관찰하지 않아야 한다는 목표다. 모든 운영 조건에 대한 무결함 보장은 아니다.

## 7. 남은 결정과 승인 경계

남은 항목의 ID·담당·결정 시점·위험은 [결정 기록](../decisions/DECISION-LOG.md)을 따른다. 이번 승인은 해당 내용을 임의 결정할 권한이 아니라, 미정으로 남겨 적절한 단계 전에 다시 결정하는 방식에 대한 승인이다.

| 결정 시점 | 남은 범위 |
| --- | --- |
| 상세 기능 설계 전 | 단위 후보, 가격·시간 입력 제한, 사진·텍스트 제한, 배정/등록 동률, 공개 전 일반 수정·취소 재배정, 일정 경계 |
| 입찰·복구 설계 승인 전 | 공식 접수 및 처리 순서 보장, 중복 판별, 입찰/개시/중단/취소/마감 경쟁, 장애 감지·영향 범위·복구 불가 처리 |
| 계정·조회 설계 승인 전 | 이메일 변경 등 계정 수명 정책, 인증·재설정 세부, 개인 입찰 이력 접근, 낙찰자 표시 필드, 운영자 거래 연락처 조회 |
| 시험 실행 전 | 부하·환경·측정 및 실패 표본 처리, 브라우저·화면 크기 |
| 실제 운영 전 별도 검토 | 거래 금지 품목, 외부 거래 불이행·분쟁과 플랫폼 책임, 개인정보 제공·보존, 향후 내부 결제·정산 도입 시 별도 검토 |

기본 시간의 사용성, 상품 수 기준 배정의 적절성, 목표 성능의 실현 가능성은 검증할 가설이다. Java/Spring Boot와 React/TypeScript는 현재 검토 중인 후보다. 통신 기술, DB 테이블, 구체적인 클래스, API, 배포 구조는 이번 문서에서 확정하지 않는다.

제품 책임자는 요구사항 및 중요한 기술 의사결정의 최종 승인자다. 후속 AI 에이전트 작업은 승인된 기준과 계약에 따라 책임을 나누고 독립 검증·병렬 개발·통합을 진행한다. 이번 산출물은 제품 요구사항이며 개발 착수·운영 배포 승인 또는 실제 운영 검증 완료를 대신하지 않는다.

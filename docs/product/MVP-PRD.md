## 1. 문서 사용 기준

이 문서는 현재 대화에서 다시 확인하고 승인한 요구사항과 인수 조건의 정본이다. 기존 문서는 참고 자료이며, 현재 승인과 다른 과거 정책의 변경 이력은 결정 기록에 남긴다. 모든 `G-01`, `R-01`~`R-52`는 확정 요구사항이다. `AC-*`는 이를 검증할 때 확인해야 하는 기대 결과로, 테스트 통과 기록이 아니다.

경매 규칙 문서는 업무 흐름과 경계를 설명한다. 결정 기록은 승인 이력, 현재 검토 중인 제안(`PROP-*`), 검증할 가설(`HYP-*`), 아직 결정되지 않은 정책(`OPEN-*`), 주요 위험(`RISK-*`)을 구분한다. 미결정 사항은 구현자가 임의로 확정하지 않으며, 관련 상세 설계·검증·실제 운영 단계 전에 제품 책임자가 결정한다.

인수 조건의 수치 예시는 규칙을 확인하기 위한 시험 자료다. 허용 금액 목록이나 제품 상한을 추가로 정하는 의미가 아니다. 공식 접수·후속 시간은 D-055~D-057, 같은 회차·레인의 외부 요청 순번과 개시·마감 경계는 D-063~D-066을 따른다. 같은 경매의 기존 입찰 상대 순서는 보존한다. 새 준비·재개 기준점과 입찰 하한, 기존 자동 경계 유지는 D-067~D-070을 따른다. 장애·복구·운영 명령·공유 의도·회차 생명주기·배정은 D-071~D-090을 따른다. 시간 정밀도·순서 보장·동기화·복구 기술과 남은 수치·권한·운영 정책은 후속 결정 후 실행 가능한 시험으로 구체화한다. 아래 추가 AC도 검증 계획이며 실행은 NOT_RUN이다.

## 2. 목적과 사용자 흐름

개인이 실제 중고 물품을 출품하고 여러 구매자가 실시간으로 경쟁하여 가격과 낙찰자를 정한다. 과거 TCP/IP·Swing 기반 중고차 경매 경험을 웹 서비스로 발전시키는 포트폴리오로서, 현재 진행 상태의 이해, 입찰의 정확성, 데이터 정합성과 예외 복구를 핵심으로 삼는다.

| 사용자 | 핵심 흐름 | 연결 요구사항 |
| --- | --- | --- |
| 비회원 | 공개된 상품 목록·상세·실시간 진행·종료 결과 확인 → 출품·입찰 시 가입 및 로그인 | R-37, R-38, R-45 |
| 출품자 | 이메일 검증 가입 → 모집 중 회차에 출품 → 허용 기간 수정·취소 → 내 출품/결과 확인 → 낙찰 시 상대 이메일 확인 → 외부 거래 | R-12, R-16, R-32, R-33, R-35, R-36, R-39, R-51 |
| 입찰자 | 상품 사전 확인 → 로그인 → 여러 레인의 진행·현재가 확인 → 버튼 입찰 → 승인/거절/처리 확인 중 확인 → 결과 및 해당 거래 연락처 확인 | R-02, R-10, R-17~R-23, R-38, R-39, R-51 |
| 운영자 | 사전 지정 계정 사용 → 회차 일정·레인 수·시간 설정 → 자동 진행 확인 → 예외 시 레인 중단/확인/재개 또는 현재 상품 취소 → 회차 자동 완료 확인 | R-06, R-07, R-14, R-15, R-24~R-29, R-31, R-41~R-44, R-52 |

출품자와 입찰자는 한 일반회원이 수행하는 역할이다. 운영자 계정은 운영 전용이며 회원 기능은 별도 일반회원 계정을 사용한다(D-092). 같은 사람이 별도 일반회원 계정으로 참여하는 것은 금지하지 않으며 같은 이메일의 계정 구분 정책은 이번에 정하지 않았다. 운영자 화면 및 계정 준비 방식의 기술 구현은 후속 설계 대상이다. 운영자라는 이유만으로 모든 개인 정보에 대한 조회 권한을 부여하지 않는다.

## 3. 요구사항과 인수 조건

### 3.1 제품 목적과 범위

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| G-01 | 웹 실시간 경매의 진행·정확성·정합성·복구를 설명하고 입증하는 개발자 포트폴리오를 만든다. 객체지향 설계, 유지보수성과 테스트 가능성을 중시한다. | **AC-G01-01:** 최종 포트폴리오에서 출품→경매→결과 및 동시 입찰·종료 경계·복구 시나리오를 해당 요구사항, 설계 판단, 구현, 독립 검증 증거에 연결해 설명할 수 있다. 미실행 항목을 통과로 표현하지 않는다. 현재 문서는 제품 기준만 제공한다. |
| R-01 | 개인이 중고 물품을 출품하고 여러 구매자가 경쟁 입찰한다. | **AC-R01-01:** 서로 다른 회원인 출품자 1명과 구매자 2명이 한 상품의 출품·경쟁 입찰·최종 결과 확인 흐름을 수행할 수 있다. |
| R-02 | 실시간 경매 진행 상태 확인과 입찰을 핵심 경험으로 제공한다. | **AC-R02-01:** 진행 화면에서 대상 상품, 진행 단계, 현재 가격, 본인의 입찰 처리 결과, 최종 결과를 구분할 수 있다. `처리 확인 중`과 승인·거절, 최저낙찰가 도달과 최종 낙찰이 서로 다른 상태로 표현된다. |
| R-03 | 실제 출품과 낙찰을 다루며 결제·정산·물품 전달은 서비스 밖에서 처리한다. | **AC-R03-01:** 서비스 내부 결제·정산·배송 절차를 거치지 않아도 경매 결과가 확정되고 당사자가 이를 조회할 수 있다. 낙찰 또는 회차 완료를 외부 대금 지급·물품 전달 완료로 표시하지 않는다. |
| R-04 | 각 레인은 한 번에 상품 하나를 경매하고 종료 후 다음 상품으로 독립 전환한다. | **AC-R04-01:** 4개 레인에서 한 레인의 경쟁이 연장되거나 중단되어도 다른 레인의 상품·가격·마감·전환은 해당 레인의 규칙대로 진행한다. 한 레인에서 두 상품의 입찰을 동시에 접수하지 않는다. |
| R-05 | 결제·정산의 향후 확장이 가능하도록 고려하되 현재 MVP에 구현하지 않는다. | **AC-R05-01:** 후속 설계 검토에서 낙찰 결과와 향후 결제·정산의 책임 경계 및 연결 시 고려사항을 설명하고, 현재 경매가 결제 모듈 없이 동작함을 확인한다. 이번 문서에는 결제 테이블·클래스·연동 기술을 확정하지 않는다. |
| R-06 | 상품 준비·입찰 개시·종료·다음 상품 전환은 자동이며 운영자는 예외에 개입한다. | **AC-R06-01:** 정상 회차에서 운영자의 상품별 시작·마감 버튼 조작 없이 준비→입찰→결과→다음 상품 준비가 이어진다. 예외 중단·보류 중에는 자동 진행이 해당 규칙을 우회하지 않는다. |
| R-07 | 모집 기간과 예약 시작 시각을 가진 회차로 운영한다. | **AC-R07-01:** 운영자가 회차의 모집 일정과 예약 시작 시각을 준비할 수 있고, 출품은 모집 중 회차에 귀속되며 예약 시각 및 선행 회차 조건에 따라 자동 시작한다. **AC-R07-02:** 새 회차는 생성 시점의 현재 서버 시각 ≤ 모집 시작 < 공개 시각 < 예약 시작을 만족해야 한다. 이미 모집 시작·공개 시각이 지난 일정으로 소급 생성하지 않는다. 현재가 10월 15일 10:00이면 공개가 15일 00:00인 16일 시작 회차를 새로 만들지 않는다. 정확한 입력 정밀도·허용 상한은 별도 결정한다. |

### 3.2 가격, 입찰 방식과 시간

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-08 | 첫 유효 입찰부터 후속 입찰 대기로 전환하고, 이후 유효 입찰마다 공식 접수 시각에 회차 고정 후속 대기 시간을 더하여 새 마감을 정한다. | **AC-R08-01:** 첫 유효 입찰 후 후속 대기 단계가 시작되고, 새 유효 입찰의 공식 접수 시각 + 그 회차의 후속 대기 전체 시간으로 마감을 갱신한다. 판정 시각을 시간 기준점으로 대신하지 않는다. **AC-R08-02:** 거절 요청 전후에 최고가·최고입찰자·마감이 변하지 않으며, 추가 유효 입찰 없이 대기가 끝나면 결과를 판정한다. **AC-R08-03:** 현재 마감 10.000초, 유효 요청 공식 접수 9.950초, 판정 10.080초, 회차 고정 후속 시간 5초인 상대 시각 예시에서 새 마감은 14.950초다. 판정 시각에 5초를 더한 15.080초로 바꾸지 않는다. 예시의 소수 자릿수는 제품 시각 정밀도 승인이 아니다. |
| R-09 | 시작가와 최저낙찰가는 별도다. 최종 최고 유효 입찰가가 최저낙찰가 이상이면 낙찰하며, 미달 또는 무입찰이면 유찰한다. | **AC-R09-01:** 유효 입찰 없음, 최저낙찰가 미만, 정확히 같음, 초과의 네 경우 결과가 각각 유찰·유찰·낙찰·낙찰이다. 낙찰자와 낙찰가는 최종 최고 유효 입찰의 회원과 금액이다. |
| R-10 | 첫 입찰은 정확히 시작가, 이후 입찰은 정확히 현재 최고가+입찰 단위의 버튼 입찰이다. | **AC-R10-01:** 시작가 10,000원·단위 1,000원일 때 첫 승인 금액은 10,000원이며, 이후 현재 최고가가 10,000원이면 다음 승인 가능 금액은 11,000원이다. 다른 금액은 거절한다. 자유 금액·자동 대리입찰 기능은 제공하지 않는다. |

A의 옛 마감부터 소급하여 15초에 개시하지 않는다. 진행 중 허용된 현재 상품 취소 후 다음 준비도 취소 결과를 확인한 실제 준비 진입 확정 시각부터 전체 시간을 부여한다. 아직 시작하지 않은 다음 상품의 시간을 과거 마감부터 소진하지 않는다. **AC-R13-03:** 정상 처리에서 유효 입찰 개시 경계 O가 17초이고 최초 대기가 10초라면, 자동 개시 작업이 17.2초에 실행돼도 개시는 17초, 최초 마감은 27초다. 선행 유효 입찰·중단·취소가 경계를 바꿨으면 이를 먼저 반영하며 장애 보류·기록 불명에는 정상 지연 결과를 강제하지 않는다. **AC-R13-04:** 같은 서버 준비 시작·개시·마감을 서로 다른 화면에서 늦게 표시하거나 확인 응답이 늦어도 개시·마감을 다시 부여하지 않는다. 모든 화면에 준비 전체 시간이 보인다고 주장하지 않으며 상태 전파 지연은 R-49에 따라 별도로 검증한다. |

| R-15 | 회차별 시간 한 세트를 모든 운영 레인에 적용하고 실제 회차 시작 시 고정한다. | **AC-R15-01:** 한 회차의 모든 레인이 같은 시간 설정을 사용한다. 실제 시작 전에는 설정을 바꿀 수 있고, 실제 시작 후에는 중단·재개를 포함하여 원래 확정값이 유지되며 변경 요청을 적용하지 않는다. 공개 일정의 고정과는 별개다. |

### 3.3 입찰 자격, 경쟁과 처리 확인

| R-21 | 인증·기본 형식 확인 후 공식 접수 기록에 넣은 시점을 공식 접수로 인정한다. 같은 회차·레인 진행에 영향을 주는 외부 요청은 공통 증가 순번으로 판정하며 기존 동일 경매 입찰의 상대 순서를 보존한다. 동일 금액 경쟁은 먼저 접수된 유효 요청만 승인한다. 최초·후속 대기 실제 재개 전 공식 접수 입찰은 뒤 순번이어도 거절하며 재개 정각은 유효 재개 뒤 순번과 나머지 조건을 확인한다. 준비 재개는 새 개시부터 입찰 가능하다. 선행 요청을 반영한 현재 유효 마감과 같거나 늦게 공식 접수된 입찰 요청은 거절하며 제출 금액을 자동 인상하지 않는다. | **AC-R21-01:** 같은 다음 입찰 금액을 두 회원이 경쟁 제출하면 접수 순번이 앞선 유효 요청 하나만 승인한다. 선행 요청이 무효라면 뒤의 유효 요청을 그 이유로 막지 않는다. **AC-R21-02:** 자신의 판정 차례에 적용되는 현재 유효 마감 직전 공식 접수된 유효 요청은 승인하여 대기를 갱신하고, 그 마감 정각·이후 접수는 거절한다. **AC-R21-03:** 오래된 화면의 금액을 제출한 요청도 공식 순번에 따라 판정하며 그 차례의 금액 조건에 맞지 않으면 거절한다. 공식 접수 전 오래된 업무 금액·마감으로 선거절하거나 제출 금액을 더 높게 바꾸어 승인하지 않는다. **AC-R21-04:** 인증·기본 형식 확인을 통과한 요청 A와 B가 같은 경매의 공통 접수 기록에 A, B 순으로 기록되면 증가 순번에 따라 A를 먼저 판정한다. 두 요청의 기록 시각이 같아도 순번을 따른다. 다른 레인 사이에 전역 입찰 순서를 추가하지 않는다. **AC-R21-05:** 현재 마감 전에 공식 접수된 요청이 그 마감 후 판정되더라도, 선행 요청을 반영한 상태에서 유효하면 처리 지연만을 이유로 거절하거나 마감 처리에서 누락하지 않는다. 선행 요청이 무효인 경우 그 요청 때문에 뒤의 유효 요청을 막지 않는다. 선행 요청을 정리한 뒤에도 해당 유효 입찰로 계산되는 새 마감이 이미 지난 장기 지연이면 원시각·순번으로 입찰을 판정하되 결과 확정·자동 진행을 보류한다. 지연 자체를 입찰의 최종 거절 사유로 사용하지 않는다(D-072). **AC-R21-06:** 기존 마감 직전의 선행 유효 요청이 마감을 갱신한 뒤에는 기존 마감 정각에 접수된 후행 요청도 갱신된 현재 마감·금액·자격으로 판정하고, 조건을 모두 만족하면 승인한다. 선행 요청이 무효여서 마감이 갱신되지 않았다면 기존 마감 정각의 후행 요청은 거절한다. **AC-R21-07:** 같은 회차·레인 진행에 영향을 주는 입찰·출품자 취소·운영자 중단/재개/상품 취소는 인증·기본 형식 확인 후 공식 접수된 공통 증가 순번으로 판정한다. 동일 기록 시각에도 순번을 따르고 요청 종류에 우선권을 주지 않으며 기존 같은 경매 입찰의 상대 순서를 보존한다. 다른 레인까지 전역 순서를 요구하지 않는다. **AC-R21-08:** 기존 마감 10.000초 직전인 9.950초의 선행 유효 입찰이 후속 5초에 따라 현재 마감을 14.950초로 바꾸면, 10.000초에 공식 접수된 운영자 상품 취소는 새 마감 전 요청으로서 나머지 조건을 만족할 때 허용한다. 옛 10.000초 타이머가 이를 먼저 종료시켜서는 안 된다. 선행 입찰이 무효여서 마감이 그대로면 10.000초 취소는 정상 종료 후 거절한다. **AC-R21-09:** 최초 또는 후속 대기 재개 요청이 20.0초·순번100에 공식 접수되고 실제 재개가 20.8초에 확정된 자료에서, 입찰이 20.1초·순번101에 공식 접수되면 판정이 20.8초 뒤로 늦어져도 재개 전 입찰로 거절하고 가격·마감을 바꾸지 않는다. 이 상태에서 거절한다. 준비 재개 시에는 실제 재개 정각이 아니라 새 개시 O = 실제 재개 시각 + 준비 전체 시간부터 D-064의 개시 우선 규칙을 적용한다. 모든 경우 현재 유효 마감 정각은 제외하며 선행 유효 제어와 기존 원판정 유지 규칙을 함께 적용한다. **AC-R21-11:** 마감 10초 직전인 9.9초에 접수된 입찰이 나머지 조건상 유효하고 후속 시간이 5초라면 새 마감은 14.9초다. 선행 요청을 정리한 뒤에도 16초에야 이 입찰을 판정할 수 있다면 원접수 시각·순번으로 판정하되 바로 낙찰·유찰하거나 다음 상품으로 진행하지 않고 보류한다. 지연만으로 최종 거절하거나 판정 시각부터 5초를 다시 주지 않는다. 정상 접수·판정이 계속됐고 타이머 콜백만 늦은 별도 자료는 현재 유효 마감을 유지한다. | R-22 | 개인 연결 끊김은 경매를 멈추거나 승인 입찰을 무효로 하지 않는다. | **AC-R22-01:** 최고입찰자의 연결을 끊어도 다른 참가자의 경매가 진행되고 기존 입찰이 유지된다. 그 입찰이 정상 종료 시 최종 최고이며 최저낙찰가 이상이면 연결 여부와 관계없이 낙찰된다. |
| R-23 | 입찰 전 회원×상품 경매마다 동시에 한 미확인 의도를 서버에 공유 등록하고 등록 확인 후 실제 입찰을 보낸다. 원최종 판정 확인 후에는 다른 업무 조건 안에서 새 의도를 등록할 수 있다. 미확인 결과는 처리 확인 중으로 유지하며 어느 기기든 원최종 판정의 수신·반영이 확인되어야 해당 신규 제한을 해제한다. 동일 회원·요청번호에 원경매·금액을 거절로 취급하지 않는다. **AC-R23-05:** 원요청이 서버에 도달하지 않아 같은 번호·원경매·원금액의 재전송으로 처음 공식 접수되면 그 최초 기록 시각·순번과 당시 판정 차례의 업무 상태를 기준으로 판정한다. 과거 클릭·전송 시각으로 소급하지 않는다. **AC-R23-06:** 원요청의 최종 거절이 기록된 뒤 경매 상태가 달라져 같은 금액이 허용될 수 있더라도 동일 요청의 조회·재전송은 원거절을 유지한다. 현재 상태로 원요청을 다시 승인하지 않는다. **AC-R23-07:** 원요청의 최종 승인·최종 거절을 앱이 수신·반영했음이 확인되면 그 미확인 요청 때문에 적용한 회원×상품 경매 신규 제한을 해제한다. 앱의 자동 확인을 사용하며 사람이 읽었음을 증명하거나 수동 확인 버튼을 누를 것을 요구하지 않는다. 해제 후에도 최고입찰자 재입찰 금지·마감·종료 등 다른 업무 조건은 계속 적용한다. **AC-R23-08:** 시간초과, 조회의 기록 없음(NOT_FOUND), 인증 실패, 내용 충돌 응답 또는 경매 종료만으로 원요청을 최종 거절·실패로 확정하거나 미확인 제한을 해제하지 않는다. 원요청의 기록된 최종 판정과 앱 확인을 구분한다. **AC-R23-09:** 레인이 다음 상품으로 이동한 뒤에도 원요청 조회·재전송은 원경매·원금액을 유지하며 새 상품 입찰로 바꾸지 않는다. 원승인 확인은 그 입찰의 승인 사실을 뜻하고 현재 최고입찰자·최종 낙찰 여부는 최신 상태·경매 결과로 별도 표시한다. **AC-R23-10:** 같은 회원이 PC와 모바일에서 같은 상품 경매에 새 의도를 동시에 등록해도 미확인 공유 의도는 하나만 유지한다. 등록 확인을 받은 의도만 실제 입찰을 전송하며 다른 기기는 그 의도를 조회·재전송한다. 등록 자체가 미도달·실패·불명확하면 실제 입찰을 보내거나 입찰의 최종 거절로 표시하지 않는다. **AC-R23-11:** 공유 의도 등록 시각은 공식 입찰 접수 시각이 아니다. 등록 뒤 실제 입찰이 처음 공식 접수되는 시각·순번으로 금액·상태·마감을 판정하며 등록 시각으로 소급하지 않는다. 등록된 원경매·원금액·요청번호를 다른 상품이나 새 의도로 바꾸지 않고 등록 충돌을 원입찰의 최종 거절로 취급하지 않는다. **AC-R23-12:** PC가 등록·전송한 원입찰의 최종 승인·거절을 모바일 앱이 수신·반영한 사실이 확인되어도 회원×경매 신규 제한을 해제할 수 있다. 모든 기기의 확인이나 사람의 읽음을 요구하지 않는다. 시간초과·기록 없음·인증 오류·내용 충돌·경매 종료만으로 해제하지 않고 다른 입찰 자격은 계속 적용한다. **AC-R23-13:** 진행·보류·미확인 동안 원판정과 중복 식별 관련 기록을 만료시키지 않으며 MVP에 해당 기록의 자동 만료를 두지 않는다. 등록 후 시간초과로 의도를 버리거나 미확인 제한을 해제하지 않고 EX-09의 별도 미접수 종료도 제공하지 않는다. 실제 운영 보존 기간은 별도 결정하며 사진·개인정보 전체의 영구 보존을 뜻하지 않는다. |

R-21의 새 공식 접수 시각·순번은 처음 접수되는 논리 요청에 부여한다. 이미 접수된 동일 요청의 조회·재전송은 R-23에 따라 원기록을 사용한다. 원요청이 아직 처리 중이라면 최종 판정을 새로 추정하지 않는다. 원판정·완전한 접수와 선행 이력·불명확 기록은 D-073에 따라 구분하며 이를 입증할 저장·복구 기술은 잔여 OPEN-09/10이다.

| R-25 | 재개 시 가격·최고입찰자를 유지하고 허용된 실제 재개 확정 서버 시각부터 중단된 단계의 전체 설정 시간을 다시 부여한다. 중단 중 현재 상품 취소 후 다음 상품은 실제 재개 시 준비 전체 시간을 시작한다. | **AC-R25-01:** 준비·최초 대기·후속 대기 각각의 수동 중단과 전체 장애 복구를 검증하여, 같은 회차에 고정된 해당 단계 전체 시간을 재개 시 부여하는지 확인한다. 잔여 시간만 이어가지 않고, 승인된 입찰·가격·최고입찰자를 초기화하지 않는다. 준비/무입찰 단계에서 존재하지 않던 최고입찰자를 생성하지 않는다. **AC-R25-02:** 허용된 실제 재개가 20.8초에 확정된 독립 자료에서 준비 5초는 개시 25.8초, 최초 대기 10초는 마감 30.8초, 후속 대기 5초는 마감 25.8초를 부여한다. 재개 요청 접수 시각으로 소급하지 않고 원래 단계·입찰·가격·최고입찰자를 보존한다. 최초 대기 재개 후 21.8초에 첫 유효 입찰이 접수되고 후속 시간이 5초라면 D-057에 따라 새 마감은 26.8초이며, 재개 마감 30.8초와 더 큰 값을 택하지 않는다. **AC-R25-03:** 중단 중 A를 취소하고 B가 남아도 레인 중단과 A의 취소·입찰 기록을 유지한다. 허용된 실제 재개가 20.8초에 확정되면 B는 그때부터 준비 전체 5초를 받아 개시 25.8초가 된다. 취소 시점부터 B 시간을 소진하거나 A의 옛 단계·최고입찰을 B로 옮기지 않는다. 남은 상품·보류가 모두 없으면 R-42에 따라 종료한다. |
| R-26 | 운영자는 레인을 즉시 중단·재개하고 현재 상품 경매를 취소할 수 있다. | **AC-R26-01:** 운영자의 중단이 반영되면 현재 상품의 입찰 접수와 타이머가 멈추고 기록은 유지된다. 재개는 R-25를 따른다. **AC-R26-02:** 현재 상품 취소를 유찰과 구분하고 취소 사유·기존 입찰·처리 이력을 보존한다. 취소 후 진행은 R-43을 따른다. 외부 요청의 순번과 자동 경계의 선후 판정은 D-063~D-066을 따른다. **AC-R26-03:** 정상 진행 중이고 각 요청이 현재 유효 마감 전인 입찰/중단 경쟁에서, 공통 순번이 입찰→중단이면 유효 입찰·갱신 마감을 반영한 뒤 중단도 유효할 때 해당 단계와 입찰을 보존하여 중단한다. 유효 중단→입찰이면 해당 경매의 입찰 가능 상태를 닫는 중단을 적용하고 후행 입찰을 거절한다. 무효·거절된 중단은 후행 유효 입찰을 막지 않는다. 그 사이 다른 유효 사건이 있으면 이를 함께 반영하며 요청 종류로 순서를 뒤집지 않는다. **AC-R26-04:** 정상 진행 중 현재 유효 마감 전 입찰/운영자 상품 취소 경쟁에서, 입찰→취소이면 유효 입찰을 먼저 기록하고 유효 취소를 적용하여 입찰·취소 사유·처리 이력을 보존한다. 유효 취소→입찰이면 해당 원경매의 취소를 먼저 적용하고 후행 입찰을 거절한다. 무효·거절된 취소는 후행 유효 입찰을 막지 않는다. 승인 입찰 기록과 최종 취소 결과를 구분한다. **AC-R26-05:** A 종료 후 B 준비 중 해당 회차·레인에 대한 중단은 B의 진행을 멈추고 A의 확정 결과를 보존한다. A를 대상으로 한 입찰·출품자/운영자 상품 취소를 B 대상으로 바꾸지 않는다. A의 종료 후 취소 요청이 먼저 거절됐다는 이유로 뒤의 B 유효 입찰을 막지 않는다. 중단·재개도 원래 지정한 회차·레인을 유지한다. **AC-R26-06:** 선행 유효 사건을 반영한 입찰 개시 시각 직전 공식 접수된 중단은 판정이 개시 이후로 늦어져도 준비 단계에서 중단한다. 개시 정각 중단은 유효한 자동 개시를 먼저 적용한 다음 최초 대기 단계에서 중단한다. 보존된 단계의 전체 시간과 실제 재개 기준점은 R-25 및 D-068을 따른다. **AC-R26-07:** 보류 상품의 운영자 취소는 확정 결과가 없고 선행 요청·현재 상태를 확인할 수 있을 때만 사유를 남겨 허용한다. 확정 결과 존재 여부조차 알 수 없으면 취소도 보류하며 확정 결과를 취소로 덮지 않는다. 허용된 취소 후 진행은 기존 레인 중단·보류와 R-43을 따른다. **AC-R26-08:** 동일 운영자·요청번호는 명령 종류·대상·제출 사유에 고정한다. 같은 명령의 조회·재전송은 원결과를 반환하고 효과를 중복 적용하지 않는다. 같은 번호의 내용 충돌은 원명령을 바꾸지 않으며 원명령의 실패로 대체하지 않는다. **AC-R26-09:** 실제 재개 R이 이미 확정된 뒤 응답이 유실돼 같은 명령을 재전송하면 원성공·원R을 반환하고 시간을 다시 부여하지 않는다. 이후 새 중단이 생겼더라도 옛 재개 명령의 재전송은 원결과 확인일 뿐 새 중단을 해제하지 않는다. **AC-R26-10:** 재개는 해당 회차·레인과 해제하려는 중단 발생건을 대상으로 한다. 옛 중단에 대한 재개가 새로운 중단을 해제하지 않으며, 이미 진행 중인 레인에 새 요청번호로 재개를 보내도 시간을 갱신하지 않는다. 재개 명령의 원결과와 현재 레인 상태를 구분한다. |

### 3.5 회차·배정·출품

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-27 | 회차별 운영 레인 수는 1~4개 중 선택한다. | **AC-R27-01:** 운영자가 1·2·3·4개 각각의 회차를 구성할 수 있으며 선택된 개수의 레인에서 경매를 진행한다. 0개·5개 설정을 허용하지 않는다. |
| R-28 | 취소되지 않은 대기 상품 수가 가장 적은 운영 레인에 자동 배정하고 동률이면 작은 레인 번호를 선택한다. 유효 등록은 회차 최초 공식 출품 접수 순번으로 처리하며 레인 안에서는 최초 등록순을 유지한다. | **AC-R28-01:** 대기 수의 최솟값이 하나인 조건에서 새 상품이 해당 레인에 배정된다. 동일 레인 상품은 최초 등록순으로 진행하며 수정 시각으로 순서를 바꾸지 않는다. 대기 수 동률은 작은 레인 번호, 같은 기록 시각의 유효 등록은 회차 최초 공식 출품 접수 순번을 따른다. **AC-R28-02:** 대기 수가 같은 최소 레인들 중 번호가 가장 작은 운영 레인을 선택하며 취소된 상품은 대기 수에 넣지 않는다. 대기 수 (2,2,2,2)에 유효 등록 두 개를 순서대로 반영하면 첫 출품은 1번, 다음은 반영된 수 (3,2,2,2)를 보고 2번 레인에 배정한다. **AC-R28-03:** 같은 회차의 유효 등록은 최초 공식 출품 접수 순번으로 처리하며 같은 기록 시각에도 순번을 따른다. 선행 무효 등록은 상품 수를 늘리거나 후행 유효 등록의 배정을 막지 않는다. 동시 등록들이 모두 같은 과거 대기 수를 사용하여 잘못 배정되지 않도록 각 선행 효과를 반영하고 정보 수정으로 최초 등록순을 바꾸지 않는다. |
| R-29 | 실제 회차 시작 때 운영 레인들이 첫 상품의 준비를 함께 시작하고 이후 독립 진행한다. | **AC-R29-01:** 상품이 있는 운영 레인들의 첫 준비가 같은 회차 시작 사건에 따라 시작된다. 한 레인의 유효 입찰로 다른 레인의 준비·마감이 함께 연장되지 않는다. 빈 레인은 R-42에 따른다. **AC-R29-02:** 상품이 있는 운영 레인들의 첫 준비는 같은 실제 회차 시작 사건에 기록된 서버 시각을 공유한다. 실제 시작 시각이 12초이고 준비가 5초라면 모두 개시 17초를 사용하며 각 레인의 별도 처리 완료·화면 표시 시각으로 나누지 않는다. 이후 상품 전환·재개는 각 레인의 실제 전이 시각에 따라 독립적으로 진행하고 빈 레인은 R-42에 따른다. |
| R-30 | 모집 마감 및 사전 공개는 예약 시작일의 전날 00:00, Asia/Seoul 기준이다. 모집 시작은 포함하고 마감은 제외하며 공개 직전 공식 접수된 유효 변경을 반영한 뒤 배치를 고정한다. | **AC-R30-01:** 예약 시작이 10월 20일 14:00이면 10월 19일 00:00에 모집이 마감되고 사전 공개가 시작된다. 10월 19일 14:00으로 계산하지 않는다. 사전 공개 중에는 추가 출품을 받지 않는다. 정확한 모집·공개 경계는 D-081의 시작 포함·마감 제외와 공개 전 공식 접수 반영 기준을 따른다. **AC-R30-02:** 모집 시작 정각의 공식 접수 출품은 해당 모집 조건으로 판정하고 시작 전 접수는 처리 지연으로 유효하게 바꾸지 않는다. 모집 마감·공개 정각에는 해당 회차의 추가 출품을 받지 않는다. 직전 공식 접수된 유효 출품은 지연 처리돼도 원회차에 반영하며 그때 모집 중인 다른 회차로 옮기지 않는다. **AC-R30-03:** 공개 직전 공식 접수된 유효 출품·수정·레인 수 변경을 반영한 뒤 공개 배치를 고정한다. 공개 정각의 새 출품·수정·레인 수 변경은 해당 회차에 적용하지 않지만, 입찰 개시 전 출품자 취소까지 금지하지는 않는다. 회차의 단계 시간 설정은 공개가 아니라 실제 시작 때 고정하는 R-15를 유지한다. |
| R-31 | 동시에 진행하는 회차는 하나다. 여러 대기 회차는 취소되지 않은 예약시각 오름차순으로 처리하고 이전 회차가 미완료이면 대기·지연 표시 후 이전 완료 시 자동 시작한다. | **AC-R31-01:** 다음 예약 시각에 이전 회차가 미완료이면 다음 회차 입찰을 시작하지 않고 지연을 표시한다. 이전 회차 완료 후 운영자 시작 조작 없이 시작한다. **AC-R31-02:** 이전 회차가 일찍 완료돼도 다음 회차를 예약 시각보다 먼저 시작하지 않는다. 중단·보류로 미완료인 회차도 이 조건에 포함한다. **AC-R31-03:** 취소되지 않은 여러 지연 회차는 예약시각 오름차순으로 기다리며 앞선 회차의 중단·보류를 건너뛰지 않는다. 빈 회차도 자기 차례와 시작 조건을 만족한 뒤 실제 시작·즉시 완료한다. 취소된 회차는 시작하지 않고 예약시각을 실제 지연 시각으로 덮어쓰지 않는다. |
| R-32 | 모집 기간은 서로 겹치지 않으며 새 출품은 현재 모집 중인 회차에 자동 귀속된다. | **AC-R32-01:** 모집 기간이 중복되는 회차 설정을 허용하지 않는다. 모집 중 회차가 하나면 출품을 그 회차에 배정한다. 모집 회차가 없으면 출품을 받지 않고, 설정된 다음 모집 일정이 있으면 안내한다. **AC-R32-02:** 다른 회차가 진행 중이라는 이유만으로 이미 설정된 미래 회차의 모집을 금지하지 않는다. 모집 중 회차와 진행 중 회차는 별개다. **AC-R32-03:** 같은 예약 시작일의 두 회차는 모집 종료·공개 시각이 같으므로 각각 양수 모집기간을 두면 기간이 겹쳐 신규 설정을 거절한다. 동일 예약시각 회차를 만들기 위한 별도 동률 우선순위를 추가하지 않는다. 이 조건을 서로 다른 예약일의 지연 회차가 같은 실제 날짜에 차례로 진행하는 것까지 금지하는 규칙으로 확대하지 않는다. |
| R-33 | 사전 공개 전에는 출품자 수정·취소가 가능하다. 공개 후 수정은 금지하고 입찰 접수 개시 전까지만 취소한다. | **AC-R33-01:** 공개 전 수정·취소는 허용하고 공개 후 수정은 거절한다. 공개 후 순서 대기·준비 단계의 취소는 허용한다. **AC-R33-02:** 최초 입찰 대기가 시작되면 아직 유효 입찰이 없어도 출품자 취소를 거절한다. 취소/입찰 개시 경계는 D-063/064를 따른다. **AC-R33-03:** 선행 유효 사건을 반영한 입찰 개시 직전 공식 접수된 출품자 취소는 나머지 조건을 만족하면 판정이 개시 이후로 늦어져도 허용한다. 같은 직전 시점의 입찰은 지연 처리되어도 미개시로 거절한다. 유효한 개시 정각에는 자동 개시를 먼저 적용하여 출품자 취소는 거절하고 입찰은 나머지 조건으로 판정한다. 선행 유효 중단·취소가 개시 조건을 바꾸었으면 그 결과를 먼저 반영한다. |
| R-34 | 공개 전 일반 수정·취소는 다른 상품을 재배정하지 않고 레인 수 변경 때만 전체 자동 재배정한다. 공개 후 배치·공개 번호·상대 순서를 고정하고 취소 자리를 표시하며 진행에서 건너뛴다. | **AC-R34-01:** 공개 전 레인 수를 바꾸면 전체 상품을 다시 배정하며 각 레인 내 최초 등록순을 유지한다. 공개 후 레인 수·배치를 바꾸는 요청은 적용하지 않는다. **AC-R34-02:** 공개 후 하나를 취소해도 다른 상품의 레인 및 상대 순서는 같고 취소 상품의 입찰을 시작하지 않는다. 공개 전 일반 수정·개별 취소로 다른 상품을 재배정하지 않는다. 레인 수 변경에 따른 전체 재배정은 유지한다. **AC-R34-03:** 공개 전 일반 수정은 기존 배정·최초 등록순을 유지하고 개별 취소는 대기 수에서 제외하되 다른 상품을 옮기지 않는다. 이후 신규 출품은 변경된 최소 대기 수로 배정한다. 공개 전 레인 수 변경 때는 취소 상품을 되살리지 않고 남은 유효 출품을 최초 등록순과 동일 최소/동률 규칙으로 전체 재배정한다. **AC-R34-04:** 공개 목록의 2번 상품이 취소되면 1번→2번(취소)→3번을 유지하고 진행만 2번을 건너뛴다. 뒤 상품의 번호·레인·상대 순서를 바꾸지 않는다. 공개 전 취소된 비공개 상품을 이 표시 규칙 때문에 일반 공개하지 않는다. |
| R-35 | 필수 출품 정보는 상품명·설명·사진 1장 이상·시작가·최저낙찰가·입찰 단위다. | **AC-R35-01:** 필수 정보 중 하나가 없거나 사진이 0장이면 출품을 완료할 수 없다. 상품 상태·하자는 설명으로 기재할 수 있으며 별도 카테고리·상태 분류 입력을 강제하지 않는다. 텍스트·사진의 상세 제한은 후속 결정한다. |
| R-36 | 유효한 상품 정보와 가격 조건을 만족하면 운영자 상품 심사 없이 출품된다. | **AC-R36-01:** 모집 중에 필수 정보와 가격 조건을 충족한 출품은 운영자의 승인 대기 단계 없이 해당 회차에 등록·배정된다. 입력 검증과 상품 심사 절차를 혼동하지 않는다. |

### 3.6 조회·결과·운영 권한

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |
| --- | --- | --- |
| R-37 | 비회원은 공개된 목록·상세·실시간을 볼 수 있고 출품·입찰은 로그인이 필요하다. | **AC-R37-01:** 로그아웃 상태에서도 사전 공개된 목록·상세와 실시간 진행을 확인할 수 있다. 미공개 상품을 공개 조회 경로로 노출하지 않는다. **AC-R37-02:** 비회원 출품·입찰을 허용하지 않으며 로그인한 회원은 각 업무 조건에 따라 수행할 수 있다. |
| R-38 | 상품과 낙찰·유찰·취소 결과 및 낙찰가를 공개 조회 가능하게 남기고 낙찰자 식별 정보는 당사자·운영자에게만 허용한다. 유찰 종료 응답·결과 화면에는 최고입찰가를 제공하지 않는다. | **AC-R38-01:** 종료 후 비회원도 공개 상품 및 결과와 낙찰가를 조회할 수 있으나 최저낙찰가 금액은 계속 숨긴다. **AC-R38-02:** 낙찰자 식별 정보는 해당 출품자·낙찰자 본인·운영자만 조회하고 제3자는 조회할 수 없다. 식별 필드의 상세 범위, 운영자 연락 이메일 권한, 전체 입찰 이력 공개는 별도 미정이다. **AC-R38-03:** 무입찰 유찰과 최저낙찰가 미달 유찰의 종료 응답·결과 화면 모두 최고입찰가를 제공하지 않는다. 종료 이벤트의 결과에도 같은 경계를 적용한다. 진행 중 이미 공개된 가격을 삭제·회수하거나 본인의 원입찰·원판정 기록을 삭제하지 않으며, 본인 원기록 조회와 일반 종료 결과 조회를 구분한다(D-094). |
| R-39 | 낙찰된 거래의 출품자와 낙찰자는 상대방의 검증된 가입 이메일을 외부 거래 연락처로 확인한다. | **AC-R39-01:** 낙찰 확정 후 출품자는 해당 낙찰자 이메일을, 낙찰자는 해당 출품자 이메일을 확인할 수 있다. 유찰·취소 또는 무관한 제3자 조회에 이 권한을 부여하지 않는다. **AC-R39-02:** 외부 연락·결제·물품 전달 완료를 별도로 추적하는 기능을 MVP 흐름에 요구하지 않는다. 운영자 이메일 조회 권한은 이 조건으로 확정하지 않는다. |
| R-40 | 유찰 상품은 출품자의 새 신청으로만 재출품하고 새 신청 시각을 적용하며 이전 이력을 유지한다. | **AC-R40-01:** 유찰만으로 다음 회차에 자동 등록하지 않는다. 출품자가 모집 중 회차에 새로 신청하면 새 신청 시각으로 배정·순서를 정하고 이전 유찰 결과를 조회할 수 있다. 상품 복사 편의 기능의 제공을 뜻하지 않는다. |
| R-41 | 공개 후 실제 시작 전 회차의 예약 일정은 임의 변경할 수 없고 해당 회차를 취소할 수 있다. 자동 시작 사건과 취소는 회차 공통 판정순서로 처리한다. 회차 취소 이력과 상품의 미진행 사유를 보존하고 출품을 자동 이전하지 않는다. | **AC-R41-01:** 공개 후 예약 시작 시각의 임의 변경을 허용하지 않는다. 실제 시작 전 회차 취소 시 취소 이력을 남기고 상품을 다른 회차에 자동 등록하지 않는다. R-31의 선행 회차 지연은 허용된 자동 동작으로 구분한다. 진행 중 회차 전체 강제 취소 권한은 포함하지 않는다. **AC-R41-02:** 시작 자격이 성립한 자동 시작 사건과 공개 후 회차 취소를 회차 단위 공통 판정순서로 처리하고 같은 기록 시각도 순번을 따른다. 자기 차례에 예약시각·선행 완료·기록 정합성·미취소 조건을 재확인하여 첫 유효 전이만 적용한다. 취소가 먼저 유효하면 시작하지 않고 시작이 먼저 유효하면 뒤 취소를 거절한다. 예약시각만 지났고 선행 회차 때문에 대기 중이면 취소를 일괄 금지하지 않으며 실제 시작 시각은 D-067을 따른다. **AC-R41-03:** 회차 취소 당시 유효한 소속 출품은 회차 취소로 경매 미진행임을 표시하고 회차 취소 사유·이력에 연결한다. 이미 개별 취소된 상품은 원사유를 유지한다. 상품을 유찰·낙찰로 만들거나 발생하지 않은 개별 운영자 취소로 기록하지 않고 자동 이전도 하지 않는다. |
| R-42 | 처리할 상품과 보류 결과가 없는 레인은 종료하고 모든 운영 레인 종료 및 보류 없음이면 회차를 자동 완료한다. | **AC-R42-01:** 빈 레인과 마지막 상품 처리가 끝난 레인은 미결 결과가 없으면 종료한다. 보류 결과가 남아 있으면 완료로 처리하지 않는다. **AC-R42-02:** 모든 운영 레인의 처리가 끝나고 보류가 없으면 운영자 완료 승인 없이 회차를 완료한다. 운영하지 않는 레인이나 외부 거래 완료를 기다리지 않는다. |
| R-43 | 운영자는 입찰 금액·낙찰자를 임의 수정하거나 확정된 낙찰·유찰 결과를 변경·취소할 수 없다. 현재 상품 취소 후 기존 레인 상태를 따른다. | **AC-R43-01:** 운영자도 입찰 금액 변경·임의 낙찰자 지정·확정 결과 변경/취소를 수행할 수 없다. 외부 거래 불이행으로 원 경매 결과를 바꾸지 않는다. **AC-R43-02:** 진행 레인에서 현재 상품을 취소하면 다음 상품 준비로 이동한다. 중단 레인에서는 다음 상품이 있어도 중단을 유지한다. 남은 상품과 보류가 전혀 없으면 R-42에 따라 종료한다. **AC-R43-03:** 선행 유효 입찰·중단·취소를 반영하고 정상 종료가 가능한 현재 유효 마감 직전 공식 접수된 운영자 상품 취소는 나머지 조건을 만족하면 판정 지연에도 마감보다 먼저 적용한다. 그 마감 정각·이후의 취소는 낙찰·유찰을 먼저 확정하는 규칙에 따라 거절하며, 타이머 호출이나 물리적 저장이 늦어도 취소가 앞서지 않는다. 장애 보류·기록 확정 여부 불명에는 D-071~D-075를 적용하며 그 증거 확보·복구 기술은 별도 검증한다. |
| R-44 | 상품이 없는 회차도 이전 회차를 기다리고 실제 시작 시 즉시 완료한다. | **AC-R44-01:** 무출품 또는 전부 취소된 회차의 예약 시각에 이전 회차가 미완료이면 빈 회차도 대기한다. 실제 시작 조건 충족 시 상품 입찰 없이 바로 완료한다. 이전 회차가 일찍 끝나도 예약 시각 전에 완료 처리하지 않는다. |

### 3.7 계정·지원 범위·검증 목표

| ID | 확정 요구사항 | 검증 가능한 인수 조건 |

| R-45 | 이메일 검증으로 가입을 완료하고 이메일·비밀번호로 로그인한다. 검증된 가입 이메일을 거래 연락처로 사용한다. | **AC-R45-01:** 이메일 검증 전에는 가입 완료 회원의 출품·입찰 권한을 부여하지 않는다. 검증을 마친 회원은 이메일·비밀번호로 로그인하고 R-39의 거래 연락에 검증된 이메일을 사용한다. 이메일 소유 확인을 실명·개인 신원 확인 완료로 표시하지 않는다. |
| R-46 | 금액은 원화 정수, 서비스 시간은 Asia/Seoul을 사용한다. 시작가·최저낙찰가·단위는 양수이고 최저낙찰가는 시작가 이상이다. 최저낙찰가의 입찰 단위 정렬은 요구하지 않는다. | **AC-R46-01:** 0·음수·소수 금액 및 시작가보다 낮은 최저낙찰가를 거절한다. 최저낙찰가=시작가인 양의 정수 조건은 허용한다. **AC-R46-02:** 회차 일정·공개 시점을 Asia/Seoul로 해석하고 표시한다. 금액 상한·입력 정밀도 세부는 임의로 추가하지 않는다. **AC-R46-03:** 시작가 10,000원·입찰 단위 1,000원·최저낙찰가 10,500원의 조건을 정렬되지 않았다는 이유로 거절하지 않는다. 실제 유효 입찰 금액은 10,000원→11,000원이며 11,000원부터 최저낙찰가에 도달한다. 첫 입찰·후속 입찰의 정확한 버튼 금액을 바꾸거나 제출 금액을 자동 보정하지 않는다. 예시는 후보/상한 추가가 아니다(D-093). |
| R-47 | PC는 전체 기능, 모바일은 일반회원 기능을 지원한다. 운영자 기능의 대상은 PC다. | **AC-R47-01:** 합의할 PC 브라우저 환경에서 회원·운영자 흐름을 수행할 수 있다. 합의할 모바일 환경에서 가입·로그인·비밀번호 재설정·출품·조회·입찰·본인 결과·해당 거래 연락처 확인을 수행할 수 있다. 모바일 운영자 화면 지원은 필수 인수 범위에 넣지 않는다. 브라우저·화면 크기는 검증 전 결정한다. |
| R-48 | 초기 검증은 4개 운영 레인과 동시 연결 100명을 대상으로 하며 기본 구성은 입찰자 20명·관람자 80명이다. 집중 입찰 시나리오를 별도로 확인한다. | **AC-R48-01:** 시험 보고서에 4레인·동시 연결 100명·입찰 역할 20명/관람 역할 80명의 실제 시험 구성을 기록하고 기본 부하 시나리오와 집중 입찰 시나리오의 결과를 구분한다. 초당 입찰 수·시험 시간·집중 인원과 빈도·환경은 승인 후 실행한다. 100명을 가입자 수 제한으로 구현하지 않는다. |
| R-49 | 응답·상태 전달·재접속 지연 목표와 입찰·낙찰 정확성 목표를 충족한다. | **AC-R49-01:** 합의한 시험 조건에서 클릭→본인 승인/거절 표시의 p95 ≤ 1초다. **AC-R49-02:** 서비스의 권위 있는 상태 확정→다른 참가자 화면 상태 반영의 p95 ≤ 1초다. **AC-R49-03:** 연결 재수립→현재 상태 복원의 p95 ≤ 3초다. 현재 상태가 중단·보류이면 그대로 복원하며 자동 재개로 해석하지 않는다. **AC-R49-04:** 합의한 시나리오에서 정책과 다른 승인·거절, 중복 처리 효과, 잘못된 낙찰은 각각 0건이다. 실패·시간초과 표본 취급을 포함한 측정 방법은 실행 전 승인한다. |
| R-50 | 검증된 이메일을 통한 비밀번호 재설정을 제공한다. | **AC-R50-01:** 가입 시 검증된 이메일의 재설정 절차를 완료한 회원은 새 비밀번호로 로그인할 수 있고 기존 비밀번호로는 로그인할 수 없다. 해당 절차를 완료하지 않은 요청은 비밀번호를 바꾸지 못한다. 절차의 만료·재사용·기존 세션 처리는 보안 설계에서 결정한다. |

검증 결과에는 대상 버전, 환경, 데이터, 수행 조건, 관찰 결과, 해당 AC, 실행하지 않은 범위와 독립 검토 결과를 남긴다. 기능·동시성·장애 복구·실제 브라우저·성능 결과를 구분한다. 정적 문서 검사나 테스트 계획을 실제 서비스의 정확성·처리 성능 증거로 대신하지 않는다.

### 성능 목표의 해석

- 기본 시험은 동시 연결 100명 중 입찰 역할 20명과 관람 역할 80명이다. 20명 모두가 매초 입찰한다는 뜻은 아니다.
- 클릭→판정 표시는 사용자가 본 승인·거절까지, 상태 전달은 권위 있는 상태 확정→다른 화면까지, 재접속은 연결 재수립→현재 상태 복원까지 측정한다. 각 측정 경계를 혼용하지 않는다.
- p95는 모든 요청이 1초 또는 3초 이내라는 보장이 아니다. 최대 지연 목표는 별도 미정이다.
- 공식 접수·후속 마감은 D-055~D-057, 외부 요청 공통 순번·개시/마감 경합은 D-063~D-066, 새 준비·재개 기준점과 입찰 구간은 D-067~D-070을 따른다. 기록의 시각 정밀도·저장/순서 보장 기술·상태 확정 증거, 시험 환경/네트워크/빈도/기간/집중 패턴/반복 횟수, 실패·미확인·시간초과 표본의 처리와 측정 방법은 후속 결정한다. 불리한 표본을 임의로 제외하고 합격을 선언하지 않는다.
- 정확성 0건은 합의된 시험에서 정책과 다른 승인·거절, 중복 효과, 오낙찰을 관찰하지 않아야 한다는 목표다. 모든 운영 조건에 대한 무결함 보장은 아니다.

## 7. 남은 결정과 승인 경계

남은 항목의 ID·담당·결정 시점·위험은 [결정 기록](../decisions/DECISION-LOG.md)을 따른다. D-055~D-057로 공식 접수·동일 경매 순번·후속 시간 기준점, D-058~D-062로 요청 식별·원판정 유지·조회/재전송·앱 최종 판정 확인 후 제한 해제·별도 미접수 종료 기능 제외, D-063~D-066으로 외부 요청 공통 순번·개시/마감 경계·대상 고정, D-067~D-070으로 새 준비·재개 기준점·입찰 하한·기존 자동 경계 유지를 결정했다. D-071~D-080으로 장애·복구·재개 확인·운영 명령 중복·중단 발생건·공유 의도·기기 확인·요청 원기록 보존, D-081~D-090으로 모집/공개 경계·일정 유효성·회차 진행/취소·배정 동률·재배정과 취소 표시를 결정했다. D-092~D-094로 운영자 운영 전용·회원 계정 분리, 최저낙찰가 단위 정렬 불필요, 유찰 종료 최고입찰가 미노출을 확정했다. OPEN-05/06/07은 이 세 범위를 제외한 잔여 사항을 유지한다. 이후 D-095로 현재 시스템 설계와 정의된 API·이벤트를 구현 기준선으로 승인했으며, 다른 CR·SEC의 미선택 제안값·deferred와 미검증 위험은 제외했다. OPEN-04의 출품자 취소·개시 경합은 D-063/064로 해결했다. 이 승인이 나머지 OPEN을 임의 결정할 권한을 부여하지 않으며 남은 사항은 적절한 단계 전에 다시 결정한다.

| 결정 시점 | 남은 범위 |
| --- | --- |
| 상세 기능 설계 전 | 단위 후보, 가격·시간 입력 제한, 사진·텍스트 제한, 구체 UX |
| 입찰·복구의 미선택 상세 구현 전 | 승인된 접수·순번·개시/마감·준비/재개·회차 시작/취소·배정·요청 식별·공유 의도·기기 확인·복구 정책의 저장/순서 보장과 동기화/확인 프로토콜, 시각 정밀도, 재시도 간격·횟수, 장애 감지 수치·영향 및 선후 증거 수집·기록 복구 기술 |
| 계정·조회의 미선택 상세 구현 전 | 이메일 변경 등 계정 수명 정책, 인증·재설정 세부, 개인 입찰 이력 접근, 낙찰자 표시 필드, 운영자 거래 연락처 조회 |
| 시험 실행 전 | 부하·환경·측정 및 실패 표본 처리, 브라우저·화면 크기 |
| 실제 운영 전 별도 검토 | 거래 금지 품목, 외부 거래 불이행·분쟁과 플랫폼 책임, 개인정보 제공·보존, 요청 원판정·중복 식별 관련 기록의 실제 운영 보존 기간, 향후 내부 결제·정산 도입 시 별도 검토 |

기본 시간의 사용성, 상품 수 기준 배정의 적절성, 목표 성능의 실현 가능성은 검증할 가설이다. D-095로 SYSTEM-DESIGN·ADR의 Java/Spring·React/TypeScript 조합과 통신·정의된 API/이벤트·초기 배포 구조를 구현 기준선으로 채택했다. 이 제품 문서가 구조의 별도 원본은 아니며 정확 라이브러리 버전·DDL·클래스·운영 설정과 잔여 OPEN은 별도로 구체화한다.

제품 책임자는 요구사항 및 중요한 기술 의사결정의 최종 승인자다. 후속 AI 에이전트 작업은 승인된 기준과 계약에 따라 책임을 나누고 독립 검증·병렬 개발·통합을 진행한다. 이번 산출물은 제품 요구사항이며 개발 착수·운영 배포 승인 또는 실제 운영 검증 완료를 대신하지 않는다.

# PRODUCT BRIEF — 최대 4레인 실시간 경매 플랫폼

## 1. 문서 상태와 사용 기준

- 기획 승인일: 2026-10-14
- 기획 상태: 이 문서에 정리한 서비스 방향과 운영 정책은 제품 책임자가 대화에서 승인했다.
- 문서 상태: 승인된 기획을 옮긴 초안이다. 문서 자체의 최종 검토, 상세 설계, 구현, 검증, 병합이 완료됐다는 뜻은 아니다.
- 최종 제품 책임자 및 기술 승인자: 사용자

세 문서는 같은 승인 내용을 서로 다른 관점에서 설명한다. 상세 경매 규칙과 경계 상황은 [AUCTION-RULES.md](AUCTION-RULES.md), 결정 이유·대안·미확정 사항·검증 위험은 [DECISION-LOG.md](DECISION-LOG.md)를 함께 참조한다. 문서 사이의 불일치를 발견하면 임의로 정책을 선택하지 않고 제품 책임자에게 확인한다.

아래의 확정 내용과 별도로 표시한 미정 항목을 구분한다. 기술 후보나 확장 방향을 이미 승인된 상세 설계로 해석하지 않는다.

## 2. 서비스 목적과 해결할 문제

개인이 중고 물품을 등록하고, 정해진 회차에 여러 경매를 동시에 보면서 입찰할 수 있는 웹 서비스를 만든다. 회차마다 1~4개의 레인을 운영하며, 각 레인은 자기 상품들을 순서대로 자동 진행한다.

출품자는 판매할 물품과 가격 조건을 등록하고, 입찰자는 사전 공개 기간에 상품을 살펴본 뒤 실시간 가격 경쟁에 참여한다. 운영자는 회차와 레인 구성을 준비하고 예외 상황에 개입한다. 입찰 경쟁이 멈추면 서비스가 승인된 규칙에 따라 낙찰 또는 유찰 결과를 기록한다.

프로젝트는 실제 서비스에 가까운 제품 흐름과 입찰 정확성을 보여주는 포트폴리오를 목표로 한다. **실제 물품의 출품과 낙찰을 허용한다.** MVP에서는 결제·정산·물품 전달을 서비스 밖에서 처리하며, 서비스에 기록된 낙찰 결과만으로 대금 지급이나 물품 전달이 완료됐다고 판단하지 않는다.

초기에는 전문 검수와 분쟁 처리 기능보다 출품부터 결과 확인까지의 경매 흐름에 집중한다.

## 3. 대상 사용자와 권한

출품자와 입찰자는 별도의 가입 유형이 아니다. 가입한 회원은 운영자의 참가 승인 없이 두 역할을 수행할 수 있다.

| 사용자 | 주요 목적과 허용 범위 |
| --- | --- |
| 비회원 | 공개된 출품 목록을 조회한다. 상품 상세 조회에는 로그인이 필요하다. |
| 회원 / 출품자 | 모집 중인 회차에 상품을 등록하고 가격 조건을 설정한다. 허용된 기간에 수정·취소하며, 결과를 확인하고 유찰 상품을 다시 출품할 수 있다. |
| 회원 / 입찰자 | 상품 상세를 확인하고 여러 레인에 동시에 입찰한다. 여러 상품을 낙찰받을 수 있으며, 본인 출품 상품에는 입찰할 수 없다. |
| 운영자 | 회차 일정·운영 레인 수·시간 설정을 준비한다. 레인을 중단·재개하고, 허용된 범위에서 회차나 진행 중 상품의 경매를 취소한다. |

낙찰자 정보는 해당 상품의 출품자·낙찰자 본인·운영자만 확인한다. 희망가 금액은 일반 참가자에게 숨기며 출품자 본인은 자신의 희망가를 확인할 수 있다. 낙찰자 정보의 구체적인 필드, 운영자 계정 부여 방식과 로그인 수단은 아직 정하지 않았다.

종료 결과와 낙찰가는 조회할 수 있도록 남긴다. 다만 비회원에게는 목록까지만 허용한다는 정책이 우선이며, 비회원 목록에 결과·가격 중 어떤 필드를 노출할지는 상세 화면 정책에서 확인해야 한다.

## 4. 회차와 레인의 운영 개념

### 4.1 회차별 모집과 공개

- 운영자가 회차별 모집 기간, 예약 시작 시각, 운영 레인 수를 등록한다. 주간 운영을 염두에 두되, 정기 반복 회차를 자동 생성하는 기능은 MVP에 포함하지 않는다.
- 모집 기간은 회차끼리 겹치지 않는다. 상품은 등록 시점에 모집 중인 회차로 들어간다.
- 모집 중인 회차가 없으면 출품 신청을 받지 않고 다음 모집 일정을 안내한다.
- 해당 회차 시작 전날 0시에 출품 목록과 상세 정보를 사전 공개하며, 그 직전에 모집을 마감한다.
- 사전 공개 후에는 회차의 예약 일정을 고정한다. 아직 시작하지 않은 회차 전체를 취소할 수 있으며, 취소 기록을 남기고 상품을 다른 회차로 자동 이동시키지 않는다.
- 사전 공개는 시작 전에 상품을 확인하는 기회다. 종료 후에는 상품 목록·상세와 경매 결과를 보존한다.

요일과 시각은 운영자가 회차별로 지정한다. 서비스 기준 시간대와 일정 입력의 상세 제한은 미정이다.

### 4.2 운영 레인과 상품 배정

- 운영자는 사전 공개 전까지 회차의 운영 레인 수를 1~4개 중 선택·수정한다. N개를 선택하면 1번부터 N번 레인을 사용한다.
- 상품은 대기 상품 수가 가장 적은 운영 레인에 자동 배정한다. 레인 안에서는 최초 출품 등록 시각 순서로 진행한다.
- 공개 전 레인 구성이 바뀌면 전체 상품을 다시 자동 배정한다. 상품 정보 수정으로 최초 등록 순서를 바꾸지 않는다.
- 공개 후 취소가 생겨도 다른 상품의 레인과 상대적인 순서를 유지하고 취소 상품만 건너뛴다.
- 회차의 운영 레인들은 함께 시작하지만, 각 레인의 입찰과 다음 상품 전환은 독립적으로 진행한다. 상품별 실제 시작 시각과 레인별 종료 시각은 입찰 경쟁에 따라 달라진다.

### 4.3 예약 시작과 회차 종료

- 예약 시각에 회차를 자동 시작한다. 동시에 진행하는 회차는 하나다.
- 예약 시각에 이전 회차가 끝나지 않았다면 다음 회차를 대기시키고 시작 지연 상태를 표시한다. 이후 이전 회차가 완료되면 다음 회차를 자동 시작한다. 이전 회차가 일찍 끝나도 다음 회차를 예약 시각보다 앞당겨 시작하지 않는다.
- 각 레인은 처리할 상품과 보류된 결과가 모두 없어지면 종료한다.
- 모든 운영 레인이 종료되고 보류 상품이 없으면 회차를 자동 완료한다. 여기서 완료는 경매 진행과 결과 기록의 완료이며, 외부 결제·물품 전달의 완료와는 다르다.

## 5. 핵심 사용자 흐름

### 5.1 출품자가 상품을 등록하고 결과를 확인한다

1. 회원이 모집 중인 회차에 상품명·설명·사진 1장 이상과 가격 조건을 등록한다.
2. 시작가와 희망가를 별도로 정하고, 입찰 단위는 제공된 후보를 선택하거나 직접 입력한다.
3. 서비스가 운영 레인에 배정한다. 공개 전에는 출품자가 정보를 수정하거나 출품을 취소할 수 있다.
4. 공개 후부터 해당 상품의 경매 시작 전까지는 취소만 가능하다. 정보 수정이 필요하면 취소 후 다음 회차에 다시 등록한다.
5. 경매 종료 후 낙찰·유찰·취소 결과를 확인한다. 유찰된 상품은 출품자가 다시 신청해야 하며, 재출품 신청 시각으로 새 순서를 받는다. 이전 결과는 보존한다.

가격은 원화 정수로 입력한다. 시작가·희망가·입찰 단위는 양수이며 희망가는 시작가 이상이다. 금액 상한과 입찰 단위 후보의 정확한 값은 미정이다.

### 5.2 입찰자가 사전에 상품을 보고 실시간으로 경쟁한다

1. 공개 목록에서 상품을 살펴보고 로그인 후 상세 정보를 확인한다.
2. 회차 시작 후 원하는 레인들의 경매에 참여한다. 한 회원의 복수 레인 입찰과 복수 상품 낙찰을 허용한다.
3. 준비 시간 이후 첫 입찰을 시작가에 제출한다. 이후 입찰은 현재 최고가에 해당 상품의 입찰 단위를 더한 금액으로 제출한다.
4. 현재 최고가를 공개하고, 희망가에 도달하면 UI에 낙찰 가능 상태를 표시한다. 이는 최종 낙찰 확정 표시와 구분한다.
5. 경쟁이 끝나면 결과를 확인한다. 낙찰된 경우 결제와 물품 전달은 서비스 밖에서 진행한다.

현재 최고입찰자는 연속해서 입찰할 수 없고, 승인된 입찰을 사용자가 취소할 수 없다. 같은 금액으로 경쟁하면 먼저 접수된 유효 입찰만 승인한다. 서비스가 참가자의 제출 금액을 자동으로 올려 승인하지 않는다.

### 5.3 자동으로 상품을 진행하고 결과를 기록한다

| 단계 | 기본 시간과 동작 |
| --- | --- |
| 상품 준비 | 상품으로 전환한 후 기본 5초 대기한다. |
| 최초 입찰 대기 | 경매 시작 후 기본 10초 안에 첫 유효 입찰이 없으면 유찰한다. |
| 입찰 경쟁 | 첫 유효 입찰부터 기본 5초의 후속 입찰 대기를 시작하고, 유효한 입찰이 들어올 때마다 그 시간을 새로 부여한다. 거절된 요청은 시간을 갱신하지 않는다. |
| 결과 처리 | 후속 입찰 없이 대기 시간이 끝나면 최고가가 희망가 이상일 때 낙찰하고, 미달하면 유찰한다. 결과 처리 후 다음 상품으로 진행한다. |

시간은 회차별 한 세트로 설정하고 해당 회차의 모든 레인에 적용한다. 회차 시작 시 적용값을 확정하여 중단·재개에도 유지한다. 마감 시각보다 먼저 서비스에 도착한 유효 입찰만 승인하며, 마감 시각과 같거나 늦으면 거절한다.

### 5.4 연결 문제와 운영 예외에 대응한다

- 개인의 연결이 끊겨도 경매와 승인된 입찰은 유지한다. 재접속하면 현재 경매 화면과 본인의 미확인 입찰·낙찰 결과를 확인할 수 있도록 한다.
- 응답을 받지 못한 입찰을 곧바로 실패로 단정하지 않는다. 기록된 결과를 확인하고, 확인되지 않은 동안에는 처리 확인 중으로 구분한다.
- 서비스 전체 장애에서는 진행 중인 상품의 결과 확정을 보류하고, 기록된 유효 입찰을 유지한 채 운영자 확인 후 재개한다.
- 운영자의 수동 중단은 현재 상품의 입찰 접수와 타이머를 즉시 멈춘다. 입찰 단계 재개 시 기존 유효 입찰을 유지하고 최초 또는 후속 입찰 대기 시간을 새로 부여한다. 준비 단계 중단의 세부 복구 방식은 미정이다.
- 운영자가 진행 중 상품을 취소하면 사유와 기존 입찰 기록을 남긴다. 진행 중인 레인은 다음 상품 준비로 이동하고, 중단된 레인은 중단을 유지한다.
- 운영자는 입찰 금액을 수정하거나 낙찰자를 임의로 지정하지 않는다.

장애의 감지·영향 범위 판단과 접수·마감 순서의 기술적 보장은 별도 설계 및 검증 대상이다.

## 6. MVP 범위

### 포함

- 회원의 출품·입찰과 운영자 역할 구분, 권한에 따른 목록·상세·결과 접근
- 상품 필수 정보와 가격 조건 등록, 허용된 기간의 수정·취소
- 회차별 모집·사전 공개·예약 시작과 단일 진행 회차의 대기 처리
- 회차별 1~4개 레인 구성, 자동 상품 배정·순서·전환
- 최고가 공개, 정해진 단위의 입찰, 희망가 충족 UI 표시
- 동시 입찰·마감 경계·재접속에서의 일관된 승인 결과
- 낙찰·유찰·취소 기록, 제한된 낙찰자 정보 조회, 수동 재출품
- 운영자 중단·재개·취소와 서비스 전체 장애의 결과 보류·복구 흐름
- 4레인·동시 참여자 100명 규모를 목표로 하는 검증

### 제외 또는 향후 확장

- 서비스 내부 결제·정산·환불과 대금 지급 완료 관리
- 물품 전달·배송·인도 완료 관리
- 전문 검수와 분쟁 중재 업무 기능
- 자동 대리입찰, 자유 금액 입찰, 승인된 입찰의 사용자 취소
- 유찰 상품의 자동 반복 출품, 주간 반복 회차 자동 생성
- 여러 회차의 동시 진행
- 상품 카테고리·상태의 별도 필수 분류 관리

외부 결제·전달 과정의 결과를 추측하여 경매 기록을 바꾸지 않는다. 향후 확장 시 낙찰 기록을 어떻게 후속 업무와 연결할지는 별도 승인과 설계로 결정한다.

## 7. 성공 여부를 확인할 기준

아래는 합의한 요구사항의 확인 기준이다. **현재는 기획 문서 초안만 작성했으며 구현·실행 검증·성능 측정은 수행하지 않았다.**

| 확인 대상 | 확인할 결과 |
| --- | --- |
| 전체 흐름 | 회차 준비, 상품 등록, 사전 공개, 자동 시작, 입찰, 결과 조회, 재출품 흐름을 사용자 역할별로 완료할 수 있다. |
| 레인 독립성 | 최대 4개 레인의 상품·최고가·시간·결과가 다른 레인의 진행과 섞이지 않으며 각자 다음 상품으로 진행한다. |
| 가격·낙찰 규칙 | 첫 입찰, 입찰 단위, 본인 출품·최고입찰자 제한, 희망가 이상 낙찰, 무입찰·미달 유찰이 합의된 규칙과 일치한다. |
| 경쟁과 종료 경계 | 같은 금액의 경쟁, 마감 직전·정각·이후 요청에서 승인·거절과 최종 결과가 정해진 기준과 일치한다. |
| 사용자 경험 | 최신 최고가·진행 상태·낙찰 가능 여부를 이해할 수 있고, 재접속 후 본인의 처리 결과를 확인할 수 있다. |
| 예외 복구 | 개인 연결 끊김, 운영자 중단·재개, 상품 취소, 서비스 장애의 보류·재개에서 유효 입찰과 결과 기록이 유지된다. |
| 회차 운영 | 공개 후 배치 유지, 회차 간 시작 지연, 보류 결과가 있는 회차의 완료 방지 등 운영 규칙이 일치한다. |
| 접근 권한 | 비회원의 상세 접근과 권한 없는 낙찰자 정보 노출을 막고, 공개 범위와 본인 조회 권한을 지킨다. |
| 규모 | 4레인·동시 참여자 100명을 목표로 입찰 정확성과 이용 흐름을 검증한다. 시험 구성·요청 빈도·응답 시간·오류율의 구체적인 합격 기준은 아직 정하지 않았다. |

구현 완료, 기능 검증 완료, 장애·성능 검증 완료, 병합 완료는 각각 별도로 보고한다. 테스트 계획이나 문서 검토를 실제 통과 증거로 대신하지 않는다.

## 8. 기술 후보와 향후 작업 원칙

- 백엔드는 Java·Spring Boot를 우선 고려하고, 프런트엔드는 React를 후보로 검토한다. 최종 기술 선택과 상세 아키텍처는 별도 세션에서 근거를 확인하고 승인한다.
- 객체지향 설계, 유지보수성, 테스트 가능성과 실시간 입찰의 정확성·데이터 정합성을 중시한다.
- 처음부터 복잡한 분산 시스템을 전제하지 않는다. 규모 목표와 실패 상황을 검증할 수 있는 범위에서 설계를 결정한다.
- 결제·정산 확장을 고려하되 현재 MVP에 후속 업무의 구현을 포함하지 않는다.
- 다중 에이전트 작업은 책임과 완료 기준을 나눈다. 승인된 API 계약과 도메인 규칙을 공유하고, 같은 계약·코드를 임의로 동시에 변경하지 않도록 한다.

## 9. 미확정 사항과 다음 단계

현재 승인으로 확정되지 않은 세부 항목은 [DECISION-LOG.md](DECISION-LOG.md)에 모아 관리한다. 대표적으로 다음이 남아 있다.

- 로그인·가입 수단, 운영자 권한 부여와 낙찰자 정보의 구체적인 표시 필드
- 비회원 목록과 회원 화면 각각의 결과·가격 표시 범위
- 표준 시간대, 일정 입력 제한, 모집·출품 취소·상품 시작이 맞물리는 정확한 경계
- 대기 상품 수가 같은 레인 사이의 배정 우선순위와 같은 등록 시각의 순서 기준
- 입찰 단위 후보, 금액·사진·텍스트 등 입력값의 상세 제한
- 장애 감지와 범위 판단, 결과 보류·재개를 안전하게 수행하는 기술 검증
- 동시 참여자 100명 검증의 부하 형태와 정량 합격 기준

다음 단계는 세 문서의 표현과 남은 정책을 검토한 뒤, 별도 설계 세션에서 승인된 규칙을 계약과 검증 계획으로 구체화하는 것이다. 미정 항목은 구현 담당자가 임의로 제품 정책으로 확정하지 않는다.

## 2. 제품 목적과 대상 문제

개인이 중고 물품을 출품하고 여러 구매자가 실시간 경쟁으로 가격을 정하는 웹 서비스를 만든다. 출품자는 상품과 가격 조건을 등록하고, 구매자는 공개된 상품을 살펴본 뒤 경매 진행 상태와 입찰 결과를 확인하며 참여한다. 운영자는 회차를 준비하고 중단·장애 등의 예외 상황을 처리한다. (R-01, R-02)

핵심 제품 문제는 여러 상품이 동시에 경매되는 상황에서도 사용자가 **지금 진행 중인 상품, 현재 가격, 입찰 가능 상태, 자신의 입찰 처리 결과, 최종 결과**를 명확하게 확인하는 것이다. 상품 설명·가격 탐색부터 낙찰 결과까지 하나의 흐름으로 연결하되, 공정한 승인·거절과 정확한 결과를 우선한다. (R-02, R-21~R-25)

이 프로젝트는 TCP/IP·Swing 기반 중고차 실시간 경매 솔루션 경험을 웹 기반 물품 경매로 확장한 포트폴리오다. 실시간 진행, 동시 입찰의 정확성, 데이터 정합성, 장애 복구, 객체지향 설계, 유지보수성, 테스트 가능성을 구현과 독립 검증 증거로 보여주는 것이 목표다. 문서 작성만으로 이 목표를 달성했다고 판단하지 않는다. (G-01)

실제 중고 물품의 출품과 낙찰을 다룬다. MVP에서는 결제·정산·물품 전달을 서비스 밖에서 처리하며, 낙찰은 대금 지급이나 전달 완료를 뜻하지 않는다. 향후 결제·정산 확장을 고려하는 방향은 승인했지만, 후속 업무의 구조나 기술을 미리 확정하지 않는다. (R-03, R-05)

## 4. 운영 개념과 핵심 흐름

### 4.1 회차를 모집하고 사전 공개한다

운영자는 모집 기간, 예약 시작 시각, 1~4개 운영 레인, 상품별 대기 시간을 회차 단위로 준비한다. 모집 기간은 회차끼리 겹치지 않으며, 출품은 신청 시점에 모집 중인 회차로 자동 접수한다. 모집 회차가 없으면 신청을 받지 않고 설정된 다음 모집 일정이 있으면 안내한다. 다른 회차가 진행 중이어도 미래 회차의 모집은 가능하다. (R-07, R-14, R-27, R-32)

Asia/Seoul 기준으로 **예약 시작일의 전날 00:00**에 모집을 마감하고 사전 공개한다. 예약 시각에서 24시간을 빼는 규칙이 아니다. 예를 들어 10월 20일 19:00 시작 회차는 10월 19일 00:00에 공개한다. (R-30, R-46)

모집은 시작 정각부터 마감 정각 전까지다. 공개 직전 공식 접수된 유효 출품·수정·레인 수 변경을 반영한 뒤 공개 배치를 고정한다. 공개 정각의 새 출품·수정·레인 수 변경은 해당 회차에 적용하지 않지만 입찰 개시 전 출품자 취소까지 금지하지는 않는다. 시간 설정은 계속 실제 회차 시작 때 고정한다. (D-081)

새 회차는 현재 서버 시각 ≤ 모집 시작 < 공개 시각 < 예약 시작을 만족해야 하며 지난 모집·공개 시각으로 소급 생성하지 않는다. 같은 예약 시작일의 회차들은 모집 종료시각이 같아 양수 모집기간이 겹치므로 신규 중복 설정을 거절한다. 서로 다른 예약일의 지연 회차가 같은 실제 날짜에 차례로 진행하는 것은 별개다. (D-082)

상품은 취소되지 않은 대기 상품 수가 가장 적은 운영 레인으로 배정하고 동률이면 작은 레인 번호를 선택한다. 같은 회차의 유효 등록은 최초 공식 출품 접수 순번으로 처리하며 같은 기록시각에도 순번을 따른다. 각 레인은 원래 등록순으로 진행한다. 공개 전 일반 수정·개별 취소는 다른 상품을 옮기지 않고 레인 수 변경 때만 남은 유효 출품을 전체 재배정한다. 공개 후에는 레인·번호·자리·상대 순서를 유지하고 취소 상태를 표시하며 진행만 건너뛴다. (R-28, R-34, D-087~D-090)

사전 공개 후 시작 전인 회차의 예약 일정은 임의 변경할 수 없고 회차 취소만 허용한다. 취소 기록을 남기고 상품을 다른 회차로 자동 이동시키지 않는다. 이전 회차 미완료로 인한 자동 시작 지연은 이 제한과 구분한다. 상품별 대기 시간 설정은 예약 일정과 별개이며 실제 회차 시작 전까지 조정할 수 있다. (R-15, R-31, R-41)

시작 자격을 갖춘 자동 시작 사건과 회차 취소는 회차 공통 판정순서로 처리한다. 자기 차례에 예약시각·선행 완료·기록 정합성·미취소를 재확인해 먼저 유효한 전이만 적용하고 같은 기록시각에도 순번을 따른다. 예약시각만 지났고 지연 대기 중이라는 이유로 취소를 막지 않는다. 취소 당시 유효한 출품은 회차 취소로 경매 미진행임을 표시하고 기존 개별 취소 사유는 유지한다. 공개 전 회차 취소와 진행 중 회차 전체 취소는 MVP에서 제외한다. (D-084~D-086)

### 4.2 출품자가 상품을 등록하고 관리한다

1. 상품명·설명·사진 1장 이상과 시작가·최저낙찰가·입찰 단위를 입력한다. 물품 상태와 하자는 설명으로 작성하며 별도 분류 입력은 필수로 두지 않는다.
2. 입찰 단위는 제공 후보에서 고르거나 직접 입력한다. 가격은 원화 양의 정수이며 최저낙찰가는 시작가 이상이어야 한다.
3. 필수 정보와 가격 조건이 유효하면 운영자 상품 심사 없이 자동 접수한다.
4. 공개 전에는 수정·취소할 수 있다. 공개 후에는 수정할 수 없으며 **입찰 접수 시작 전까지만 취소**할 수 있다. 상품 준비 단계에는 취소할 수 있고, 최초 입찰 대기가 시작되면 유효 입찰이 없어도 취소할 수 없다.
5. 본인 출품 목록에서 결과를 확인한다. 유찰 상품은 새로 출품을 신청해야 하며 새 신청 시각으로 배정·순서를 정한다. 이전 유찰 기록은 유지한다.

관련 요구사항: R-12, R-32~R-36, R-40, R-46, R-51. 재출품은 자동 등록이나 상품 정보 복사 편의 기능의 승인을 뜻하지 않는다.

### 4.3 각 레인이 상품을 자동 진행한다

실제 회차가 시작되면 모든 운영 레인이 첫 상품의 준비를 함께 시작한다. 이후에는 레인마다 상품 하나씩 독립적으로 경매하고 끝나면 다음 상품으로 넘어간다. (R-04, R-06, R-29)

| 단계 | 기본 설정과 동작 |
| --- | --- |
| 상품 준비 | 5초. 상품을 보여주며 입찰을 받지 않는다. |
| 최초 입찰 대기 | 10초. 유효 입찰이 없으면 유찰한다. |
| 후속 입찰 대기 | 5초. 첫 유효 입찰부터 적용하며 새 마감은 해당 입찰의 공식 접수 시각 + 회차의 후속 대기 시간이다. 거절된 요청은 마감을 바꾸지 않는다. |
| 결과 확정 | 대기가 끝나면 최고 유효 입찰가가 최저낙찰가 이상일 때 낙찰한다. 미달하거나 유효 입찰이 없으면 유찰한다. |
| 다음 상품 | 결과 처리 후 다음 대상 상품의 준비 단계로 자동 이동한다. |

세 시간은 회차마다 조정할 수 있고 같은 회차의 모든 레인에 같은 설정을 사용한다. **실제 회차 시작 전까지 수정 가능하며 시작 후 고정**한다. 중단·재개에도 같은 설정을 사용한다. (R-08, R-09, R-13~R-15)

첫 상품 준비는 모든 운영 레인이 같은 실제 회차 시작 사건의 시각을 사용한다. 각 레인의 별도 처리 완료 시각으로 나누지 않는다. 이후 상품은 이전 결과를 확인하고 해당 상품의 준비 진입을 확정한 서버 시각부터 준비 전체 시간을 부여한다. 진행 중 허용된 현재 상품 취소 후 다음 준비에도 같은 규칙을 적용한다. 이전 상품의 마감부터 소급하여 아직 시작하지 않은 다음 상품의 시간을 소진하지 않는다. 이후 전환과 재개는 각 레인에서 독립적으로 진행한다. (R-13, R-29, R-43, D-067)

여기서 실제 전이 시각은 상태와 그 시작·종료 시각을 권위 있는 변경으로 확정하면서 기록하는 서버 시각이다. 준비 시작 시각에 준비 시간을 더한 값이 입찰 개시 시각이고, 최초 마감은 그 개시 시각에 최초 대기 시간을 더한 값이다. 이미 정한 유효 개시·마감은 타이머 실행이나 화면 표시가 늦다는 이유로 이동하지 않는다. 모든 화면에서 준비 전체 시간을 보게 된다는 보장은 아니며 정확한 기록·시각 기술은 별도 검증한다. 유효 입찰의 후속 마감은 계속 공식 접수 시각을 기준으로 계산한다. (D-057, D-067, D-070)

동시에 진행하는 회차는 하나다. 여러 대기 회차는 취소되지 않은 회차의 예약시각 오름차순으로 진행한다. 이전 회차가 예약 시각까지 끝나지 않으면 지연 대기하며, 이전 완료 후 자동 시작한다. 중단·보류 회차를 건너뛰거나 예약 시각보다 일찍 시작하지 않는다. 빈 회차도 자기 차례를 기다린 후 실제 시작 시 즉시 완료한다. 각 레인에 남은 상품과 보류 결과가 없고 모든 운영 레인이 종료되면 회차를 자동 완료한다. (R-31, R-42, R-44, D-083)

### 4.4 입찰자가 가격 경쟁과 결과를 확인한다

입찰은 버튼으로 제출한다. 첫 유효 입찰은 시작가, 그다음부터는 현재 최고가에 해당 상품의 고정 입찰 단위를 더한 금액이다. 자유 금액 입력이나 대리입찰은 포함하지 않는다. 출품자의 입찰 단위 직접 입력과 입찰자의 자유 금액 입찰은 다른 기능이다. (R-10, R-12)

본인 상품에 입찰할 수 없고 현재 최고입찰자는 다시 입찰할 수 없다. 다른 사람이 최고입찰자가 되면 다시 참여할 수 있다. 여러 레인 동시 참여와 여러 상품 낙찰은 허용하며 승인된 입찰은 사용자가 철회할 수 없다. 따라서 단독 입찰자가 시작가로 최고입찰자가 된 후 최저낙찰가에 미달한 채 유찰될 수 있다. 이 결과도 승인된 정책이다. (R-17~R-20)

처음 공식 접수되는 요청은 인증·기본 형식 확인 후 공식 접수 기록에 넣은 시점을 기준으로 한다. 같은 회차·레인의 진행에 영향을 주는 입찰·출품자 취소·운영자 중단/재개/상품 취소는 공통 증가 순번으로 판정한다. 같은 기록 시각에도 순번을 따르며 요청 종류에 우선권을 두지 않는다. 기존 같은 경매의 입찰 상대 순서와 동일 요청의 원접수는 보존하고, 다른 레인까지 전역 순서로 묶지 않는다. 같은 금액의 경쟁에서는 먼저 접수된 유효 요청만 승인하며 선행 무효 요청은 후행 유효 요청을 막지 않는다. 제출 금액을 자동 인상하지 않는다. (R-21, R-23, R-26, D-055, D-056, D-059, D-063)

금액·상태·마감의 업무 판정은 선행 요청을 반영한 자신의 판정 차례에 수행한다. 공식 접수 전에 오래된 금액·마감으로 미리 거절하지 않는다. 입찰 요청의 공식 접수 시각이 그 차례의 현재 유효 마감과 같거나 늦으면 거절하고, 마감 전에 공식 접수된 유효 입찰 요청은 판정이 늦어졌다는 이유만으로 거절하지 않는다. 새 마감은 유효 입찰의 **공식 접수 시각 + 회차 고정 후속 대기 시간**이며 판정 시각부터 시간을 다시 세지 않는다. (R-08, R-21, D-057)

입찰 개시 정각에는 개시를 먼저 적용하므로 정각 출품자 취소는 거절하고 입찰은 나머지 조건으로 판정한다. 개시 직전 공식 접수된 출품자 취소는 처리 지연만으로 늦은 취소가 되지 않으며, 개시 전 접수된 입찰은 지연 처리되어도 승인하지 않는다. 정상 종료 가능한 경매는 선행 요청을 반영한 **현재 유효 마감 정각에 종료를 우선**한다. 종료 타이머나 저장이 늦더라도 마감 정각·이후 접수한 운영자 상품 취소가 종료를 앞설 수 없다. 선행 유효 입찰로 마감이 바뀌었다면 새 마감으로 판정한다. (R-21, R-26, R-33, R-43, D-064, D-065)

최초·후속 대기의 실제 재개 시각보다 먼저 공식 접수된 입찰은 재개 요청보다 순번이 뒤여도 거절한다. 실제 재개 정각의 입찰은 유효 재개보다 뒤 순번이고 나머지 조건을 만족해야 승인할 수 있다. 준비 단계 재개라면 재개 시각에 준비 전체 시간을 더한 새 개시 시각 전에는 입찰을 받지 않는다. 각 경우 현재 유효 마감 정각은 입찰 허용 구간에서 제외한다. 이 하한은 새 업무 판정에 적용하며 이미 최종 판정된 동일 요청의 조회·재전송은 원판정을 유지한다. (R-21, R-23, D-059, D-069)

중복 식별·판정 확인은 D-058~D-062, 외부 요청·자동 경계는 D-063~D-066, 준비·재개 시간은 D-067~D-070을 따르며 장애·복구·공유 의도·운영 명령은 D-071~D-080으로 구체화했다. 구체 감지 수치·증거 수집·시각·저장·순서 보장·복수 기기 동기화·앱 확인 기술과 재시도 간격·횟수는 별도 설계·검증한다. 정상 마감 우선 규칙만으로 장애 보류나 복구 불명 상황을 정상 종료하지 않는다.

종료 후 공개 상품·결과·낙찰가를 유지한다. 본인 참여·결과 화면에서 해당 상품 결과로 이동할 수 있고, 낙찰된 거래의 출품자와 낙찰자는 서로의 인증 이메일을 확인해 서비스 밖에서 후속 거래를 진행한다. (R-03, R-38, R-39, R-51)

### 4.5 연결과 운영 예외를 처리한다

개인의 연결이 끊겨도 경매는 계속되고 승인된 입찰은 유지된다. 응답을 받지 못하면 승인·거절로 단정하지 않고 **처리 확인 중**으로 표시한다. 원요청의 최종 승인·최종 거절을 어느 기기의 앱이든 수신·반영했음이 확인될 때까지 **그 회원의 해당 상품 경매에 대한 새 입찰만 제한**한다. 모든 기기의 확인이나 사람이 문구를 읽었다는 증명을 요구하지 않는다. 다른 회원의 같은 상품 입찰과 본인의 다른 상품·레인 입찰은 이 사유로 제한하지 않는다. (R-22, R-23, D-061, D-079)

입찰 의도마다 고유 요청번호를 사용한다. 동일 회원·요청번호는 원래 경매와 제출 금액에 고정되며, 같은 요청의 재전송은 원래 접수 시각·순번·승인 또는 거절을 유지한다. 동시 재전송도 효과는 한 번이고, 내용을 바꿔 같은 번호를 보내도 원요청을 변경하지 않는다. 새로운 입찰 의도에는 새 번호가 필요하다. (R-23, D-058, D-059)

실제 입찰 전 회원×경매마다 동시에 하나의 미확인 의도를 서버에 공유 등록하고 등록 확인 뒤 실제 입찰을 보낸다. 원최종 판정 확인 뒤에는 다른 업무 조건 안에서 새 의도를 등록할 수 있다. 다른 기기는 같은 의도를 조회·재전송한다. **공유 등록은 공식 입찰 접수가 아니며** 등록 시각을 입찰 판정 기준으로 쓰지 않는다. 등록 자체가 미도달·실패·불명확하면 실제 입찰을 보내거나 입찰의 최종 거절로 추정하지 않는다. 등록 후 시간초과를 이유로 의도를 버리거나 제한을 해제하지 않는다. (D-078)

재접속 후 최신 경매 상태와 원요청 결과를 같은 번호로 조회하고, 필요하면 원경매·원금액 그대로 재전송한다. 이전 요청이 서버에 도달하지 않아 재전송으로 처음 공식 접수되면 그때의 시각·순번으로 판정한다. 시간초과, 기록 없음, 인증 오류, 내용 충돌 응답 또는 경매 종료만으로 원요청의 실패를 단정하거나 제한을 해제하지 않는다. 원래 입찰이 승인됐다는 사실은 현재 최고입찰자 또는 최종 낙찰자라는 뜻과도 구분한다. 별도로 미접수를 확정해 요청을 종료하는 기능은 MVP에서 제외한다. (R-23, D-060~D-062)

운영자는 레인을 즉시 중단·재개할 수 있다. 특정 레인의 장애임이 확실하면 해당 레인만, 전체 장애나 영향 범위 불명이면 현재 회차의 미완료 레인을 모두 보류한다. 정상 마감이 장애보다 먼저 성립한 기록이 있으면 정상 종료를 적용하고 장애가 먼저이거나 선후를 모르면 결과를 보류한다. 이미 확정된 결과는 유지한다. (D-071, D-072)

원판정은 그대로 반환하고 공식 접수·선행 이력이 완전한 미결 요청은 원시각·순번으로 판정한다. 장애 복구에서 권위 있는 기록이나 처리 효과가 불명확하면 보류한다. 개인 응답 유실이나 단순 조회의 기록 없음만으로 경매 전체를 보류하지 않는다. 유효 입찰의 공식 접수 9.9초 + 후속 5초 = 마감 14.9초인데 16초에야 판정할 수 있는 장기 지연이면 원입찰을 판정하되 결과 확정·자동 진행을 보류한다. 정상 접수·판정 중 타이머 콜백만 늦은 경우와 구분하며 지연을 입찰의 최종 거절로 바꾸지 않는다. (D-072, D-073)

기록·최고입찰·진행 단계·미결 요청을 확인하고 정상 접수와 기록이 가능해진 뒤 운영자가 명시적으로 재개한다. 장애 복구 확인만으로 기존 수동 중단 사유를 해제하지 않는다. 허용된 실제 재개 시각부터 해당 단계 전체 시간을 부여하고 기존 입찰·가격·최고입찰자를 유지한다. 복구 불능이면 보류와 후속 회차 대기가 지속되는 비용을 수용한다. 별도 예외 종료는 이번 승인에 포함하지 않으며 추가하려면 범위 변경 승인이 필요하다. (R-24~R-26, D-068, D-074)

현재 상품을 운영자가 취소하면 사유와 입찰 기록을 보존한다. 진행 중 레인은 다음 상품 준비로 이동하고 중단된 레인은 중단을 유지한다. 남은 상품과 보류 결과가 없으면 종료 규칙을 적용한다. 운영자가 입찰 금액·낙찰자를 바꾸거나 이미 확정된 낙찰·유찰 결과를 수정·취소할 수는 없다. (R-26, R-42, R-43)

보류 상품은 확정 결과가 없고 선행 요청·현재 상태를 확인할 수 있을 때만 사유를 남겨 취소한다. 확정 결과 존재 여부조차 알 수 없으면 취소도 보류한다. (D-075)

중단 중 상품 A를 취소하고 다음 B가 남았다면 실제 재개를 확정할 때 B의 준비 전체 시간을 시작한다. 중단 중 B의 준비 시간을 미리 소비하거나 A의 옛 대기 단계·입찰을 B로 옮기지 않는다. (R-25, R-43, D-068)

입찰과 상품 취소는 요청한 출품·상품 경매에 고정하고 레인의 다음 상품으로 바꾸지 않는다. 중단·재개는 해당 회차의 레인을 대상으로 한다. 상품 A의 정상 종료 후 B 준비 단계에서 레인 중단이 적용되면 B의 진행을 멈추고 A의 결과를 보존한다. 공통 순번은 이런 업무 순서의 승인이지 특정 큐·락·분산 처리 방식의 채택이 아니다. (D-063, D-066)

운영 명령은 운영자·요청번호에 종류·대상·제출 사유를 고정하고 동일 명령의 원결과·원래 재개 시각을 유지한다. 재개는 해당 회차·레인과 해제할 중단 발생건에 결합한다. 옛 재개 재전송으로 새 중단을 풀거나 진행 중 새 요청번호의 재개로 시간을 갱신하지 않는다. 진행·보류·미확인 동안 원판정·중복 식별 관련 기록을 만료시키지 않고 MVP에 해당 기록의 자동 만료를 두지 않는다. 실제 운영 보존 기간은 별도 결정이며 모든 사진·개인정보의 영구 보존을 뜻하지 않는다. (D-076, D-077, D-080)

## 5. MVP 범위

| 포함 영역 | 승인 범위 |
| --- | --- |
| 계정과 접근 | 이메일 인증 가입·로그인·비밀번호 재설정, 회원의 출품·입찰, 사전 지정 운영자, 공개 조회와 거래 당사자 권한 |
| 출품 | 필수 정보·가격 조건, 자동 접수·배정, 허용 기간의 수정·취소, 본인 목록·결과, 새 신청에 의한 재출품 |
| 회차 운영 | 모집·공개·예약 시작, 1~4레인, 회차별 시간 설정, 회차 간 대기, 빈 회차와 자동 완료 |
| 실시간 경매 | 상품 준비·입찰·최고가·최저낙찰가 충족 여부·최종 결과, 승인·거절·처리 확인 중의 구분 |
| 정합성과 복구 | 동시 입찰·마감 경계·연결 끊김·서비스 장애, 중단·재개·현재 상품 취소, 기존 기록 보존 |
| 거래 후 조회 | 공개 결과·낙찰가, 본인 참여·결과, 낙찰 거래 당사자 간 인증 이메일 조회 |
| 이용 환경 | 데스크톱 전체 기능, 모바일 일반 회원 기능, 원화와 Asia/Seoul 단일 기준 |
| 검증 목표 | 4개 운영 레인·동시 연결 100명, 집중 입찰·오류 상황의 정확성과 합의한 지연 목표 |

MVP에서 제외하는 기능은 다음과 같다.

- 서비스 내부 결제·정산·환불, 배송·물품 인도 관리, 외부 거래 완료 추적, 내부 채팅.
- 자유 금액 입찰, 대리입찰, 승인 입찰의 사용자 철회, 자동 재출품.
- 여러 회차 동시 진행, 사전 공개 후 임의 일정 변경, 확정 결과 수정·취소.
- 별도의 판매자·출품 심사, 필수 카테고리·물품 상태 분류 관리.
- 다중 통화·시간대, 운영 권한 부여·회수 관리 화면, 모바일 운영자 기능.
- 최종 승인·거절 확인과 별개로 미접수를 확정하여 미확인 요청을 종료하는 기능.
- 공개 전 회차 취소와 진행 중 회차 전체 취소. 공개 후 실제 시작 전 회차 취소·허용된 개별 상품 취소는 별도 승인 범위를 따른다.

외부 거래 실패·분쟁을 이유로 경매 결과를 임의 수정하지 않는다. 실제 운영 전 금전 거래·분쟁·개인정보와 관련한 별도 검토가 필요하며, 관련 세부 정책은 [결정 기록](../decisions/DECISION-LOG.md)에서 관리한다. 제외 기능을 확장하려면 필요성과 요구사항을 다시 승인받는다.

## 6. 성공 기준과 검증 상태

기능의 인수 조건은 [MVP PRD](MVP-PRD.md)에 각 요구사항 식별자로 연결한다. 다음은 제품 수준에서 확인할 성공 기준이다.

| 확인 대상 | 합의한 기대 결과 | 관련 요구사항 |
| --- | --- | --- |
| 핵심 흐름 | 출품→사전 공개→자동 시작→입찰→결과→권한 있는 거래 연락처 조회가 연결된다. | R-01~R-03, R-35~R-39, R-45, R-51 |
| 레인 독립성 | 4개 레인의 상품·최고가·시간·결과가 섞이지 않고 각각 다음 상품으로 진행한다. | R-04, R-29 |
| 입찰·낙찰 정확성 | 허용 금액·권한·접수 순서·마감·최저낙찰가 규칙과 승인·거절·결과가 일치한다. | R-08~R-11, R-17~R-21 |
| 복구 | 미확인 결과를 실패로 오인하지 않고, 중단·장애 후 승인 기록과 상태가 일관되게 복구된다. | R-22~R-26 |
| 운영 | 취소 사유와 원래 기록을 보존하고, 회차 지연·빈 회차·보류 결과·완료를 규칙대로 처리한다. | R-31, R-41~R-44 |
| 정보 보호 | 권한 없는 조회자에게 최저낙찰가 금액·비공개 낙찰자 정보·거래 연락처가 노출되지 않는다. 거래 당사자는 승인된 상대 이메일 조회 권한을 가진다. | R-11, R-38, R-39 |
| 규모와 정확성 | 4레인·동시 연결 100명에서 검증한다. 기본 구성은 입찰 역할 20명과 관전자 80명이며 집중 입찰은 별도 시나리오로 확인한다. 합의한 시험에서 정책상 잘못된 승인·거절, 중복 반영, 잘못된 낙찰은 0건이다. | R-48, R-49 |
| 입찰 응답 | 클릭부터 승인·거절 화면 표시까지 p95 ≤ 1초. | R-49 |
| 상태 전파 | 서비스의 공식 상태 확정부터 다른 클라이언트의 갱신 표시까지 p95 ≤ 1초. | R-49 |
| 재접속 | 연결 재수립부터 최신 상태 표시까지 p95 ≤ 3초. 최신 상태는 중단·보류 상태일 수 있다. | R-49 |

이 수치는 승인된 목표이며 측정 결과가 아니다. 시험 환경·요청률·지속 시간·집중 입찰 강도·반복 횟수·실패 표본 처리·브라우저 조건은 시험 전에 결정한다. 문서 점검, 기능 실행, 장애 복구 실행, 성능 측정, 실제 운영 증거를 각각 구분한다. 현재 구현과 모든 실행 검증은 **NOT_RUN**이다.

## 7. 확정 범위 밖의 항목

| 구분 | 현재 상태 |
| --- | --- |
| 확정 요구사항 | 본 문서의 승인 범위와 PRD의 G-01, R-01~R-52. 제품 책임자가 전체 승인함. |
| 현재 검토 중인 제안 | Java / Spring Boot, React / TypeScript 등의 기술 후보와 향후 결제·정산 연계의 구체적 설계. 후보의 채택은 미승인. |
| 추가 검증이 필요한 가설 | 기본 5·10·5초의 이용 편의성, 대기 상품 수 기준 배정의 적절성, 합의한 성능 목표의 달성 가능성. |
| 아직 결정되지 않은 정책 | 입력 상세 제한·정밀도, 계정 수명·정보 접근 권한·UX, 구체 감지/기록/복구/동기화·시험 조건, 실제 운영 보존 기간·거래·개인정보 정책. |

미결정 항목의 전체 목록과 결정 시점은 [DECISION-LOG.md](../decisions/DECISION-LOG.md)를 기준으로 한다. DB 테이블, 구체적인 클래스, 실시간 통신 기술은 이번 승인 범위에 없다. 다음 설계 단계는 승인 요구사항을 구현·검증 가능한 계약으로 구체화하되, 미결정 정책을 기술 선택으로 대신 확정하지 않는다.

| 공유 입찰 의도 / SharedBidIntent | 실제 입찰 전 회원×경매에 동시에 하나의 미확인 의도로 공유 등록하는 요청 번호·경매·금액 | 공식 입찰 접수와 분리한다. 원판정 확인 후 새 의도 가능. 등록 확인 후 동일 의도만 제출·인계하며 등록 시각으로 입찰 마감을 판단하지 않음(D-078/079) |
| 승인 입찰 / Bid | 승인된 회원·금액·경매·공식 순서를 보존하는 기록 | 최고입찰·낙찰의 근거. 응답 유실로 유효성이 바뀌지 않음 |
| 입찰자 / Bidder | 경매에 참여하는 회원의 역할 | 별도 참가 승인이나 회원의 하위 엔티티를 만들 필요가 없다. 같은 회원은 출품자이기도 함 |
| 운영자 / Auction Operator | 사전 지정된 운영 권한을 가진 행위자 | 상속된 '특수 입찰자'나 모든 정보에 접근하는 만능 객체로 모델링하지 않음. 회원 역할 겸용은 미정 |
| 경매 결과 / AuctionResult | 낙찰·유찰·취소에 관한 최종 판단 내용 | 결과 확정 보류는 아직 결과가 아니다. 낙찰자와 낙찰가는 승인 Bid를 근거로 함 |
| 처리 확인 중 / Unconfirmed | 원요청의 최종 승인/거절을 앱이 수신·반영한 사실이 아직 확인되지 않은 상태 | 서버가 이미 승인했어도 발생한다. 사람의 열람 증명·Auction 진행 단계·서비스 장애 보류와 다른 축 |
| 중단 발생 건 / SuspensionOccurrence | 어느 회차·레인의 어떤 중단을 해제하려는지 구별하는 근거 | 옛 재개 명령이 새로운 중단을 해제하지 않게 함. 현재 상품 식별과는 다르며 별도 엔티티·값 객체 여부는 후보(D-077) |
| 운영 명령 / OperatorCommand | 운영자+명령 번호에 종류·대상·사유를 결합한 운영 요청 | 원결과·원재개 시각을 재사용하여 타이머 재부여와 대상 변경을 막음(D-076) |

**설계 제안:** 식별은 RoundId, LaneId, LotId, AuctionId, MemberId를 구분한다. Lane의 회차 소속과 Auction의 Lot·레인 소속을 명시한다. D-066에 따라 입찰·상품 취소는 지정 상품/경매를 유지하고 중단·재개는 해당 회차 Lane을 대상으로 한다. 이 정책이 출품 취소를 위해 반드시 Auction 객체부터 생성하라는 뜻은 아니다. 한 Lot에는 이 신청을 처리하는 상품 경매를 최대 하나 두는 모델을 우선 검토하되, 경매 객체를 출품 시 만들지 준비 진입 시 만들지는 저장·이력 설계에서 비교한다.

물리적으로 같은 물건인지 판별하는 영구 Product 엔티티, 동일 물건의 여러 출품 금지, 소유권 검증은 승인 요구사항에서 도출되지 않는다. 이를 위한 별도 상품 마스터·전역 중복 금지를 추가하지 않는다. 입찰 접수 개시 전에 취소된 Lot에 실제 입찰이 진행된 것처럼 이력을 만들지 않는다. 입찰 개시 후 운영자가 취소한 경매의 기존 입찰 기록은 보존한다.

## 3. 생명주기·상태 전이와 경계

### 3.1 회차

상태 이름은 업무를 설명하기 위한 후보다. 각 회차는 자신의 모집·진행 상태를 가진다. 시스템 전체에 '모집 중 또는 진행 중'이라는 단일 상태를 두면 R-32를 만족하지 못한다.

| --- | --- | --- | --- | --- |
| 시작 전 | 회차 실제 시작 | 상품 있으면 공통 실제 시작 시각부터 첫 준비, 없으면 종료 | 레인별 별도 완료 시각으로 첫 준비를 나누지 않음 | R-29, R-42; D-067 |
| 진행 | 현재 상품 종료, 다음 대상 존재 | 다음 준비 진입 확정 시각부터 준비 전체 시간 | 이전 마감 소급·다음 상품 즉시 입찰 개시·타 레인 대기는 불가 | R-04, R-06, R-43; D-067 |

상품의 결제됨·배송됨·인도됨 생명주기는 MVP 모델에 포함하지 않는다. 공개 전 취소 상품을 일반 공개하는 권한도 승인되어 있지 않다. 회차 취소는 D-085에 따라 미진행 상품에 회차 취소로 경매 미진행임을 표시하며 원래 개별 취소 이력을 덮어쓰지 않는다. 이 표시를 위해 Auction·Bid를 가상 생성할 필요는 없다.

### 3.4 개별 상품 경매

**설계 제안:** 진행 단계는 `순서 대기 / 준비 / 최초 입찰 대기 / 후속 입찰 대기 / 종료`로 설명한다. Lane의 중단, 장애 보류, Auction의 종료 결과를 구분해 표현한다. enum 한 개 또는 여러 값의 조합 중 어느 구현을 택하든 다음 유효 조합을 강제해야 한다.

| 순서 대기·준비 | 허용된 출품자 취소 | 취소, 진행 대상 제외 | 유효 개시 전 공식 접수는 지연돼도 먼저 판정. 개시 정각부터 거절 | R-33; D-063/064 |
| 현재 미확정 상품 | 자기 공식 순서에서 허용된 운영자 취소 | 종료·취소, 사유·입찰 보존 | 정상 마감 우선 유지. 보류 상품은 확정 결과 부재와 선행 요청·현재 상태를 확인할 수 있어야 하며 결과 존재 불명 시 취소도 보류 | R-26, R-43; D-063/065/066, D-075 |
| 종료 | 새 입찰·재개·확정 결과 수정 | 승인된 전이 없음 | 유찰 재출품은 새 신청, 새 경매 | R-20, R-40, R-43 |

유효 조합: 준비·최초 대기에는 승인 입찰이 없고 후속 대기에는 최고입찰이 있다. 낙찰에는 최고 승인 입찰과 같은 낙찰자·금액이 있으며, 유찰에는 낙찰자가 없다. 취소에는 낙찰자를 부여하지 않되 기존 입찰은 남을 수 있다. 결과가 확정된 경매는 입찰 가능 상태가 될 수 없다. 보류를 확정 결과처럼 완료 수에 넣지 않는다. 확정 여부 불명은 결과 부재의 증명이 아니며 원확정 결과가 확인되면 이를 보존한다. 시작가를 최고가 0원 또는 가상의 첫 입찰로 저장하는 모델은 INV-12와 충돌한다.

Auction의 행위 후보는 `acceptBid`, `openBidding`, `finish`, `resumeStage`, `cancelCurrent`처럼 상태 변경의 의미를 드러낸다. `setHighestPrice`, `setWinner`, `setDeadline`을 외부에서 따로 호출하는 인터페이스는 INV-15·INV-23을 우회한다. 반대로 로그인, 권한 정보 획득, 중복 결과 조회, 저장·트랜잭션, 알림 전송까지 Auction에 넣지 않는다.

애플리케이션 서비스는 행위자 확인 → 요청 결과 확인 → 일관된 대상 상태 확보 → 도메인 행위 호출 → 상태·처리 결과 저장 → 기록된 결과 응답을 조정한다. 규칙은 객체와 필요한 도메인 함수가 판정한다. 저장소·시계·타이머·실시간 전송은 외부 협력이며, 공식 접수 맥락과 판정 시각은 검증 가능한 입력으로 전달한다. 도메인 객체가 받은 접수 시각을 클라이언트가 임의 주장할 수 있게 해서는 안 된다.

공유 의도 등록·확인과 공식 입찰 접수는 별도 업무 단계다. 등록은 회원×경매의 공유 상태를 확보하며, 실제 입찰은 그 의도의 원경매·금액으로 공식 접수될 때 처음 입찰 시각·순번을 얻는다. 명령 중복 결과와 이미 판정된 입찰의 조회는 현재 상태를 바꾸는 새 행위를 실행하지 않는다. 복구 증거 수집과 권한 확인은 애플리케이션이 조정하고, 확보한 사실로 재개·취소 가능성을 판단하는 규칙은 도메인 책임으로 남긴다.

조회 DTO는 화면·권한에 맞게 구성한다. 공개 최고가, 최저낙찰가 충족 여부, 공개 결과, 거래 당사자 연락처를 한 도메인 객체의 무조건 직렬화로 내보내지 않는다. 결과의 근거인 MemberId와 거래 이메일 조회 책임을 나누되, 이메일 스냅샷/현재값 선택은 계정 수명 정책과 함께 결정한다.

## 5. Aggregate와 트랜잭션 경계 비교

### 5.1 Aggregate 대안

| 대안 | 일관성·장점 | 비용·경쟁 영향 | 변경 비용 / 판단 |
| --- | --- | --- | --- |
| A. Round가 모든 Lane·Lot·Auction·Bid를 소유 | 회차 내부 제약을 한 경계에서 설명하기 쉬움 | 서로 다른 레인 입찰도 같은 회차 변경과 경쟁하기 쉬움. 이력과 객체 그래프가 커짐. 미래 회차와의 공유 제약은 여전히 별도 | 나중에 분리하면 소유권·저장·명령·검증 범위를 크게 바꿈. 우선 채택하지 않는 제안 |
| B. Lane이 현재 Auction과 그 입찰·결과를 소유 | 한 상품 진행·중단·취소·다음 전환을 한 경계에 둘 수 있음. 레인 사이 분리 | 종료 Auction의 이력 접근과 소유권을 명확히 해야 함. 과거 경매 전체를 매번 로딩하면 비용 증가. Lot·Round와 협력은 필요 | C로 이동 시 레인/경매 트랜잭션과 저장 경로 변경. 단순한 실행 모델 후보로 유지 |
| C. Round·Lane·Lot·Auction을 분리, Bid·Result는 Auction 내부 | 입찰·마감·결과를 경매 단위로 묶고 과거 결과도 같은 식별로 보존. 각 객체의 생명주기가 분명 | 레인 중단·대상 교체·출품 취소는 두 개 이상 경계를 함께 검증·변경해야 함. 분리만 하고 별도 트랜잭션으로 처리하면 위험 | B보다 조정 계약이 많지만 이력·독립 검증은 쉬움. **조건부 우선 제안**, 최종 채택은 사용자 승인 대상 |

C를 우선 검토하는 이유는 Auction의 최고입찰·마감·결과가 입찰마다 바뀌는 반면 Lane은 대상 교체·중단을, Lot는 출품 조건을, Round는 일정·설정·전체 완료를 담당하기 때문이다. 경계를 나눴다고 각각 별도 서비스나 DB로 배치하지 않는다. 같은 프로세스·같은 트랜잭션 자원에서 필요한 여러 Aggregate를 함께 다루는 단순한 구성을 먼저 검토한다. 이는 기술 스택 채택 결정이 아니다.

C가 B보다 빠르다는 증거는 없다. B도 현재 상품과 필요한 요약만 다루면 레인별 경쟁 범위를 유지할 수 있다. C의 교차 경계 조정 비용이 수명·책임 분리의 이익보다 크다면 B를 선택할 수 있다.

**권위 있는 상태의 제안:** 현재 대상과 수동 중단 원인·발생 건은 Lane, 입찰 단계·마감·최고입찰·결과는 Auction이 소유한다. 입찰은 Lane의 접수 가능 조건도 같은 트랜잭션·경쟁 제어 규약에서 검증한다. 중단·대상 교체가 이 검증과 따로 성공하여 오래된 상태로 입찰을 승인해서는 안 된다. 제어 상태를 Auction에도 복제한다면 독립 수정은 허용하지 않고 Lane 변경과 함께 일관되게 반영해야 한다. 장애 보류의 권위 위치와 복구 증거 표현은 D-071~D-075를 만족하도록 비교한다.

공유 의도·미확인 제한은 회원 전체가 아닌 **회원×Auction**의 일관성을 요구한다. 이를 Auction 내부에 둘지 별도 참여 상태 후보에 둘지는 B/C 양쪽에서 비교할 사항이다. 별도로 두면 의도 등록·공식 접수 연결·최종 판정 확인 사이의 경쟁을 조정해야 하고, 내부에 두면 경매의 참여 상태 관리량이 늘어난다. 공유 등록이 승인됐다는 이유만으로 새 Aggregate나 분산 저장소를 확정하지 않는다.

Lot의 공개 시점 가격 조건이 해당 경매의 기준이다. Auction을 출품 시 생성한다면 공개 전 수정된 최종 조건이 경매에도 반영되어야 하고, 준비 때 생성한다면 공개된 조건을 사용해야 한다. 공개 후 서로 다른 두 가격 사본이 각자 수정되는 모델은 허용하지 않는 제안이다.

입찰 이력 전체를 매번 메모리로 읽을 필요는 없다. 현재 최고입찰과 신규 승인 기록만으로 판정하되 저장된 이력·최고값·결과가 일치하도록 보장하는 방식을 검증한다. 독립 `BidRepository`를 통해 Auction 검증 없이 입찰을 승인하는 구조는 피한다. 과거 Bid를 물리적으로 어떻게 조회하는지는 Aggregate의 변경 권한과 구분한다.

### 5.2 명령별 논리적 원자성

입찰 상태 변경은 저장 실패 시 승인으로 응답하지 않아야 한다. 저장은 성공했지만 응답·전파가 실패했다면 경매를 되돌리지 않고 기록된 결과 확인으로 이어져야 한다. 트랜잭션 뒤 실시간 전파가 누락되는 경우의 복원 방식을 기술 검증한다. 이를 위해 처음부터 메시지 브로커·분산 잠금·이벤트 소싱·Saga를 필수 전제로 두지 않는다.

### 5.3 레인 독립성과 공유 제약

입찰 가격·마감·단계·현재 상품은 Auction/Lane별 독립이다. 공유되는 것은 회차 시작 사건·고정 시간 설정·완료 조건, 시스템의 진행 회차 점유·모집 일정, 동일 회원의 식별이다. 공유 의도·미확인 제한은 기기를 넘어 MemberId × AuctionId 범위에서 일관돼야 하며 MemberId 전체 잠금이 아니다. 같은 회원의 타 레인 최고입찰·낙찰은 다른 입찰의 거절 조건이 아니다.

논리적 독립이 자원 공유 없는 물리적 독립을 보장하지는 않는다. 한 레인의 부하가 다른 레인 지연에 미치는 영향은 TV-06에서 확인한다. 반대로 전체 장애는 여러 레인에 영향을 줄 수 있으므로 '레인은 독립이니 장애 보류도 무조건 한 레인'으로 축소하지 않는다.

## 6. 동시 입찰·마감·재시도 설계

### 6.1 판정에 필요한 사실과 승인 조건

판정에는 권한이 확인된 회원, 특정 Auction, 변경하지 않은 제출 금액, 공식 접수 순서·시각, 현재 단계·입찰 가능 구간의 시작·마감·제어 상태, 출품자, 최고 승인 입찰, 가격 조건이 필요하다. 신규 요청의 승인 조건은 아래 조건을 모두 만족하는 것이다. 표의 순서는 거절 이유의 우선순위나 경합 순서를 확정하지 않는다.

| 조건 | 불충족 시 결과 | 근거 |
| --- | --- | --- |
| 가입 완료·로그인한 회원이고 해당 행위를 할 수 있음 | 승인 불가 | R-16, R-37, R-45 |
| 해당 회원×경매에 공유 등록·확인된 동일 의도의 키·경매·금액으로 새 입찰을 제출함 | 공유 등록 확인 전 실제 입찰을 진행하지 않음. 이미 존재하는 원판정 조회는 새 제출 조건으로 재심사하지 않음 | R-23; D-078/079 |
| 대상 경매가 해당 레인의 현재 상품이며 입찰 개시·미종료·접수 가능 | 준비·중단·보류·종료·취소 등에서는 승인 불가 | R-04, R-13, R-24, R-26 |
| 본인 상품도 현재 최고입찰자도 아님 | 거절, 최고입찰·마감 유지 | R-17, R-18 |
| 승인 Bid가 없으면 제출 금액 = 시작가, 있으면 제출 금액 = 현재 최고가 + 단위 | 거절, 금액 자동 변경 없음 | R-10, R-21 |
| 현재 입찰 가능 구간 시작 ≤ 공식 접수 시각 < 그 순서의 현재 유효 마감. 재개 정각은 유효 재개 뒤 순번도 필요 | 시작 전·마감 정각/이후 거절. 준비 재개는 새 개시가 하한 | R-21, R-25; D-069 |
| 해당 회원×경매의 현재 공유 의도와 다른 새 입찰 의도가 아님 | 다른 신규 의도만 제한. 현재 공유 의도의 최초 실제 제출·같은 요청 재전송·원결과 확인은 허용 경로 | R-23; D-078/079 |

이미 판정된 동일 요청의 결과 확인은 신규 입찰 판정과 구분한다. 예전에 승인된 요청을 재조회할 때 현재 최고입찰자이거나 경매가 끝났다는 이유로 그 요청을 새 거절 결과로 덮어쓰면 안 된다. 동일 요청의 정의·원판정 보존은 D-058~D-060으로 확정했다. 구체 응답 형식과 확인 프로토콜은 OPEN-10에서 계약화한다.

### 6.2 공식 접수·순서·시간 기준 — 사용자 승인 완료

2026-10-14 사용자가 추천한 세 기준을 확정했다. 정책 정본은 D-055~D-057과 R-08/R-21이다.

1. 인증·기본 형식 확인을 거친 요청을 **경매별 공통 접수 기록**에 넣으며 서버 시각·순번을 확보하고 해당 기록으로 공식 접수를 인정한다. 클릭·HTTP 도착·판정 완료와 구분한다. 공통 경계에 들어오기 전의 지연까지 공식 접수로 소급하지 않는다.
2. 같은 경매의 새 요청은 **증가하는 공식 접수 순번**대로 판정한다. 기록 시각 동률도 순번으로 판정한다. D-063은 이 상대 순서를 보존하면서 같은 회차·레인의 외부 제어 요청과 공통 순서를 정한다. 다른 레인 간 전역 순서는 강제하지 않으며 선행 무효 요청은 가격·마감을 바꾸지 않는다.
3. 유효 입찰의 새 후속 마감은 **공식 접수 시각 + 회차 고정 후속 대기 시간**이다. 판정·화면 표시 시각부터 다시 전체 시간을 더하지 않는다.

기존 마감 12:00:10.000, A 공식 접수 09.950, A 판정 10.080, 후속 5초라면 다른 조건이 유효한 A는 승인되고 새 마감은 14.950이다. A를 빠뜨린 채 옛 타이머가 결과를 확정해서는 안 된다. B가 옛 마감 정각 10.000에 정확한 다음 금액으로 접수됐다면 A 승인 뒤 갱신된 마감으로 판정하여 승인할 수 있다. A가 무효라면 마감은 10.000 그대로이고 그 정각 B는 거절한다. 예시는 같은 분 안의 시각을 줄여 쓴 것이며 저장 정밀도를 확정하지 않는다.

접수는 승인과 다르다. 접수 입구에서 아직 앞선 입찰을 반영하지 않은 가격·마감으로 먼저 거절하지 않고, 업무 조건은 자기 순번의 상태로 판단한다. 마감 확정은 현재 마감 전의 미처리 공식 접수를 누락하지 않아야 한다. 업무상 '입찰 접수 중단'은 유효 입찰의 승인 가능 상태를 닫는 의미이며, 거절할 요청의 처리 기록까지 금지한다는 뜻은 아니다.

**기술 검증 조건:** 선택한 구현에 시각·순번 부여와 기록 확정 사이의 간격이 있다면, 그 작업을 마감이 추월하여 나중에 확정된 접수를 누락하지 않도록 보호해야 한다. 미확정 시각 자체를 공식 접수로 인정하는 별도 결정은 아니며, 기록 확정·실패·복구 계약은 OPEN-09/10에서 구체화한다.

비교 이력: 판정 차례 진입을 공식 접수로 보는 안은 처리 구조가 단순해질 수 있지만 내부 대기로 마감 전에 도착한 요청을 거절할 수 있어 선택하지 않았다. 판정 시각 + 후속 시간도 서버 부하에 따라 마감이 바뀌므로 선택하지 않았다. 채택안은 표시 지연만큼 화면에서 남은 시간이 짧아지는 비용이 있다.

시간 정밀도·기록 확정/복구와 앱 확인 프로토콜은 OPEN-09/10의 기술 검증 대상이다. 장기 지연·불명 기록의 처리 정책은 D-072/073으로 확정했으며 §6.6을 따른다. 후속 5초를 일반적인 장애 감지 임계값으로 삼지 않고 기록 확정 불명을 자동 거절하지 않는다. 특정 DB·락·큐의 채택은 이번 결정에 포함되지 않는다.

### 6.3 경쟁 사건과 안전 조건 — 경합 기준 사용자 승인 완료

2026-10-15 사용자가 “추천기준 적용해줘”로 네 기준을 승인했다(D-063~D-066). 외부 요청을 같은 회차·레인의 공통 순번대로 판정하며, 각 요청의 공식 시각까지 도래한 **현재 유효한 자동 전이**를 그 요청 전에 반영한다. 선행 요청을 반영해 매번 유효 개시·마감을 다시 판단한다. 타이머 콜백의 실제 도착순이나 운영자라는 이유로 외부 요청 순서를 바꾸지 않는다.

| 기준 | 확정된 의미 | 반례·적용 한계 |
| --- | --- | --- |
| 외부 공통 순번 | 입찰·출품자 취소·운영자 중단/재개·상품 취소를 공통 순서로 판정. 같은 기록 시각도 순번 적용 | 뒤 중단이 앞 유효 입찰을 소급 거절하지 않음. 타 레인 전역 직렬화나 특정 큐 채택 아님 |

예시의 시각은 상대 초이며 정밀도를 승인하는 수치가 아니다. 개시5초에서 출품자 취소가4.990초에 접수되고5.100초에 처리되면 개시 전 취소다. 취소가5.000초에 접수됐다면 개시가 먼저여서 거절한다. 중단4.990초는 준비를 보존하고 중단5.000초는 최초 대기를 보존한다. 앞 중단으로 효력을 잃은 옛5초에 재개가 접수돼도 옛 타이머로 먼저 개시하지 않는다.

현재 마감10초에 취소가9.990초 접수되면 취소가 먼저이며10.000초·10.050초 접수라면 정상 종료가 먼저다. 실제 종료 작업이10.200초에 실행돼도 같다. 단, 선행 유효 입찰9.950초가 후속5초를 적용해 마감을14.950초로 바꾸었다면10.000초 취소는 현재 마감 전이므로 허용된다. 늦은 타이머 자체에 우선권을 주거나 이미 저장되지 않은 결과를 저장 완료로 표시한다는 뜻은 아니다.

경합 승인 당시 남긴 준비·재개 기준점은 §6.5의 D-067~D-070으로 구체화했다. 장애·장기 지연·불명 기록은 §6.6의 D-071~D-075, 운영 명령 재시도는 §6.7의 D-076/077을 따른다. 입찰 정책의 단순 유추가 아니라 각각 추가 승인된 범위다.

### 6.4 중복·재시도·미확인 결과 — 사용자 승인 완료

2026-10-14 사용자가 네 기준과 별도 미접수 종료의 MVP 제외를 승인했다(D-058~D-062, R-23, EX-09).

1. **회원 + 요청 번호**로 하나의 입찰 의도를 식별한다. 원 Auction과 금액을 고정하고 새 의도에는 새 번호를 쓴다. 재전송을 새 입찰 의도로 만들지 않는다.
2. 같은 번호·내용은 원접수·원판정을 유지하며 동시 중복도 논리 효과는 한 번이다. 다른 내용은 충돌이며 원요청을 바꾸지 않는다. 최초 거절도 현재 조건으로 다시 심사하지 않는다.
3. 같은 번호로 조회·재전송한다. 이미 공식 접수된 요청은 원시각·순번을 보존한다. 최초 미도달 요청의 재전송이 첫 공식 접수라면 그때 시각·순번으로 판단한다. 이 재전송은 조건 충족 시 실제로 입찰 승인될 수 있다.
4. 앱이 원요청의 최종 승인/거절을 **수신·반영한 사실을 자동 확인한 뒤** 회원×경매 신규 입찰 제한을 해제한다. 사람의 읽음 증명이나 수동 확인 버튼을 추가하지 않는다.

| 관찰된 상황 | 처리 및 미확인 해제 기준 |
| --- | --- |
| 같은 번호·내용, 원요청 처리 중 | 기존 처리에 연결해 확인. 새 입찰·새 순번·새 마감 효과를 만들지 않음 |
| 같은 번호·내용, 원승인 또는 원거절 존재 | 원판정을 반환. 앱 수신·반영 확인 후 제한 해제. 승인은 현재 최고입찰·최종 낙찰 보장이 아님 |
| 같은 번호·다른 경매 또는 금액 | 내용 충돌 응답, 원기록 그대로. 충돌 응답으로 원요청의 미확인 상태를 해제하지 않음 |
| 최초 전송 미도달, 재전송이 첫 공식 접수 | 재전송의 공식 시각으로 원경매·원금액 판정. 이전 클릭 시각으로 소급하거나 다음 상품으로 전환하지 않음 |
| 조회 기록 없음, 시간초과, 재시도 횟수 소진, 인증·통신·저장 오류 | 원판정 확인 실패와 원요청 거절을 구분. 이 사실만으로 미확인 해제 불가 |
| 서버 응답 전송 완료, 앱 수신·반영 불명 | 처리 확인 중 유지. 서버 전송 성공만으로 해제 불가 |
| 경매 종료·타인 최고입찰 또는 레인 다음 상품 전환 | 원요청의 결과 확인은 별도 유지. 해당 경매 제한을 다른 경매에 전파하지 않음 |

예를 들어 마감10초 전에 공식 접수9초에 승인된 요청을12초에 재전송해도 원판정·원접수9초를 반환하고 마감을 다시 늘리지 않는다. 반대로 첫 전송이 도달하지 않아12초 재전송이 첫 공식 접수라면 클릭9초를 사용하지 않고 당시 유효 마감으로 판정한다. 다른 유효 입찰이 마감을 연장했다면 승인 가능성은 원금액 등 현재 업무 조건에 달려 있다.

**별도 미접수 종료는 MVP 제외다.** 조회 기록 없음으로 해당 번호를 영구 무효화하고 제한을 푸는 별도 동작이나 제3의 최종 결과를 만들지 않는다. 승인 입찰 철회도 제공하지 않는다. 개인의 응답 유실·단순 조회 기록 없음에는 회원×경매 확인 제한을 유지한다. 장애 복구에서 권위 있는 경매 이력·처리 효과가 불명인 경우의 보류는 D-073을 따르며 두 상황을 같은 것으로 취급하지 않는다.

2026-10-15 추가 승인 D-078~D-080에 따라 실제 입찰 전에 **회원×경매당 동시에 하나의 미확인 공유 의도**를 등록한다. 원최종 판정을 확인한 뒤에는 새 의도를 등록할 수 있으며 경매당 평생 한 번만 입찰한다는 뜻이 아니다. 등록 확인 후에만 그 키·원경매·원금액으로 실제 입찰을 제출하며 다른 기기도 같은 의도를 조회·인계한다. 등록은 공식 입찰 접수나 승인 자체가 아니므로 실제 공식 입찰 시각·순번을 등록 시점으로 소급하지 않는다. 등록 확인 중과 공식 입찰 판정 확인 중을 화면·계약에서 구분한다.

등록 응답을 잃었다면 같은 등록을 조회·재시도한다. 등록이 서버에 전혀 도달하지 않았다면 그 기기는 실제 입찰을 전송할 수 없다. 다른 기기는 서버에서 동일 의도의 공유 등록을 확인한 뒤 그 의도로 최초 제출·재전송할 수 있다. 원기기의 확인을 기다리거나 별도의 새 의도를 만들지 않는다. 로컬 클릭 순간을 모든 기기가 즉시 안다는 보장과는 다르다. 등록 뒤 시간초과를 이유로 의도를 버리지 않으며 같은 의도를 제출해 원최종 판정을 확인한다. 뒤늦은 첫 공식 접수가 조건을 충족하면 승인될 수 있는 D-060의 의미도 유지한다.

**어느 기기에서든** 해당 원최종 판정의 수신·반영을 자동 확인하면 공유 제한을 해제한다. 모든 기기의 확인을 기다리거나 최신 경매 상태 표시를 원판정 확인으로 대신하지 않는다. 이미 끝난 원요청의 재조회는 새 공유 의도나 현재 경매 조건으로 재심사하지 않는다. 진행·보류·미확인 원기록은 만료하지 않으며 MVP에서 원판정 자동 만료를 도입하지 않는다. 실제 운영 보존·삭제 기간은 OPEN-12다.

공유 등록은 다른 기기가 모르는 미도달 실제 입찰을 방지하는 대신 사전 등록 단계와 인계·고착 처리가 늘어나는 비용이 있다. 단일 입찰 기기 권한 방식도 비교했으나 기기 분실·인계와 늦은 요청 차단 부담이 있어 선택하지 않았다. 공유 상태의 저장 구조·요청 번호 생성·재시도 간격/횟수·확인 메시지 유실 대응은 OPEN-06/10의 구현 검증 대상이다. 버튼 비활성화만으로 회원×경매의 제한을 보장했다고 주장하지 않는다.

| 사건 | 새 시작 기준점 | 새 개시·마감 / 상태 |
| --- | --- | --- |
| 첫 상품 준비 | 실제 회차 시작의 공통 시각 S | 상품 있는 운영 레인의 개시 O = S + P. 빈 레인은 기존 종료 규칙 |
| 진행 중 이전 상품 정상 종료·취소 후 다음 준비 | 이전 결과 확인 후 다음 준비 진입 확정 시각 N | O = N + P. 이전 마감 또는 결과 기록 시각으로 소급하지 않음 |
| 준비 단계 재개 | 허용된 실제 재개 확정 시각 R | O = R + P. R부터 바로 입찰하지 않음 |
| 최초 입찰 대기 재개 | 허용된 실제 재개 확정 시각 R | 입찰 구간 시작 R, 최초 마감 R + I. 기존 무입찰 상태 보존 |
| 후속 입찰 대기 재개 | 허용된 실제 재개 확정 시각 R | 입찰 구간 시작 R, 후속 마감 R + F. 기존 최고입찰·승인 기록 보존 |
| 중단 중 현재 상품 취소 후 다음 상품 재개 | 중단을 유지하다 허용된 실제 재개 시각 R | 다음 상품의 준비 O = R + P. 취소된 경매의 옛 입찰 단계를 복원하지 않음 |

준비로 정해진 유효 개시 O에는 D-064대로 자동 개시를 먼저 적용하며 최초 마감은 O + I다. 늦은 콜백 실행·화면 표시로 O나 마감을 이동시키지 않는다. 새 유효 입찰이 승인되면 D-057대로 **그 입찰의 공식 접수 시각 + F**를 적용한다. 최초 대기 재개 후 R+1초 첫 입찰, I=10초·F=5초라면 R+6초로 마감이 단축될 수 있으며 R+10초와 최댓값을 취하지 않는다.

새 입찰은 **현재 입찰 가능 구간 시작 이상·현재 유효 마감 미만**에 공식 접수돼야 한다. 최초/후속 재개 요청이20.000초 순번100, 실제 재개 R=20.800초, 입찰이20.100초 순번101이면 재개보다 뒤 순번이어도 재개 전 접수로 거절한다. 입찰20.800초 정각은 유효 재개 뒤 순번이고 다른 조건을 만족할 때만 가능하다. 같은 시각이라도 입찰 순번이 재개보다 앞서면 중단 상태로 거절한다. 준비 재개는 R이 아니라 새 O까지 입찰할 수 없다.

위 시간 하한은 새 입찰 판정에 적용한다. 재개 전에 이미 승인·거절된 원요청의 조회·재전송은 D-059에 따라 원판정을 유지하며 새 R로 과거 승인을 거절하지 않는다. 최초 미도달 요청이 재전송으로 처음 접수되면 그때 시각으로 현재 구간을 검증한다.

예시: A 마감10.000초, B 준비 진입10.800초, P=5초·I=10초이면 B 개시15.800초·최초 마감25.800초다. 개시 작업이16.100초에 실행돼도15.900초의 유효 접수는 개시 후 입찰로 판단한다. 화면이 늦게 도착해 준비 잔여 시간이 짧아져도 전체5초를 다시 부여하지 않는다. 이 예시는 정상 처리이며 시간 정밀도나 모든 이용자 화면의 전체 시간 보장을 승인한 것은 아니다.

**설계 제안:** Auction은 현재 입찰 가능 구간의 시작과 마감, 해당 단계·중단 여부를 함께 검증한다. 애플리케이션은 실제 전이 시각과 상태·경계를 일관되게 확보·보존하고 도메인에는 그 맥락을 입력한다. 시각 값만 먼저 저장하거나 저장 실패·확정 불명 상태를 새 정상 시작으로 노출해서는 안 된다. 이 보장 방법과 복구 판정은 OPEN-09/10·TV-08에서 검증하며 특정 DB·트랜잭션·시계 기술은 미확정이다.

### 6.6 장애·장기 지연·복구 — 사용자 승인 완료

2026-10-15 승인 D-071~D-075는 다음 판단을 정한다. 장애 감지 방법이나 기록의 확정 증거를 임의로 선택한 결정은 아니다.

마감10초·장애9.8초·복구15초이면 시간 경과만으로 낙찰하지 않는다. 필요한 확인과 재개 후 D-068의 단계 전체 시간을 부여한다. 종료 확정10초·장애11초인 경매는 원결과를 유지한다. 미결 요청은 복구 후 현재 상태로 새 요청처럼 판정하는 것이 아니라 자기 원시각·순번의 이력을 복원해 판정한다. 기록이 완전하지 않으면 그 빈칸을 무입찰이나 거절로 채우지 않는다.

개인 연결 끊김·응답 유실·단순 요청 조회의 기록 없음은 위 권위 있는 경매 이력 불명과 다르다. 최초 미도달 가능성이 있는 개인 요청 때문에 다른 회원의 입찰이나 레인 전체를 중단하지 않는다. R-22/23의 개인 요청 확인 경로와 회원×경매 제한을 유지한다.

**장기 판정 지연:** 입찰이9.9초 공식 접수되고 후속 시간이5초이면 새 마감은14.9초다. 선행 요청을 정리하고도16초에야 그 입찰을 판정할 수 있다면 원시각 기준 입찰 판정·기록을 유지하면서 결과는 보류한다. 지연만으로 그 입찰을 최종 거절하거나 곧바로 낙찰하지 않는다. 반면 정상 접수·판정은 계속됐고 종료 타이머 콜백만 늦었다면 기존 유효 마감을 유지한다. 모든 지연을 동일한 장애로 보거나 후속5초를 일반 장애 감지 임계값으로 삼지 않는다.

복구 불능이면 보류가 장기화되고 레인·회차 완료 및 후속 회차가 대기할 수 있다. 이는 승인된 MVP 처리이며 별도 예외 종료가 MVP 완성을 위한 필수 미결정 기능은 아니다. 향후 이 장기 보류 정책을 바꾸려면 별도 범위 변경 승인이 필요하다. 보류 상태를 임의 취소·유찰로 바꾸는 구현 선택으로 이 비용을 숨기지 않는다. 증거 수집·정상 접수 회복 확인·장애 안내의 세부 기술은 OPEN-09/10과 TV에서 검증한다.

### 6.7 운영 명령의 중복·재개 대상 — 사용자 승인 완료

D-076/077에 따라 **운영자+명령 번호**에 종류·대상·사유를 고정한다. 동일 명령은 원결과와 원래 실제 재개 시각 R을 반환한다. 다른 내용을 같은 번호에 넣어 원명령을 바꾸지 않는다. 진행 중 새 번호로 재개하더라도 시간을 다시 부여하지 않는다. 입찰과 운영 명령의 기록 구조를 같게 구현할지는 별도 선택이다.

재개는 Round/Lane과 **해제하려는 중단 발생 건**을 지정한다. 중단A의 재개가 성공한 뒤 중단B가 생겼다면 옛 재개를 같은 번호로 재전송해 원성공을 조회하더라도 B는 그대로다. 아직 접수되지 않았던 중단A의 재개가 B 중에 처음 도착해도 A의 재개로 B를 해제하지 않는다. 현재 Lot가 바뀌었다는 사실만으로 모든 Lane 제어를 거절하는 정책과는 다르다.

명령 기록·실제 상태 변화·원 R의 일관성과 중단 발생 건 식별은 구현 검증 대상이다. 재시도 없이 운영자가 새 명령 번호를 반복 생성하도록 요구하는 방식은 중복 제어와 다르며, 원결과와 현재 상태도 구별해서 보여줘야 한다.

### 6.8 모집·회차 경합·배정 — 사용자 승인 완료

D-081~D-090의 모집 구간은 **모집 시작 이상·마감/공개 미만**이다. 공개 직전 공식 접수된 유효 등록·변경을 반영한 뒤 공개하며, 정각에는 새 출품·공개 전 수정이 불가하다. 상품 취소는 공개 후에도 개시 전까지 허용하는 기존 규칙을 따르므로 공개 정각 취소를 일괄 금지하지 않는다. 일정 생성은 현재 ≤ 모집 시작 < 공개 < 예약 시작을 만족해야 한다.

같은 예약 시작일 회차는 공통 공개 시점까지의 모집 구간이 겹치므로 중복 모집을 거절한다. 이 규칙은 지연된 회차가 실제로 같은 날 연속 진행되는 것을 금지하지 않는다. 지연 대기 회차는 예약 시각순으로 선택하고, 자동 시작 사건과 회차 취소는 **해당 회차의 공통 순서**에서 자기 차례에 시작 자격·미시작 상태를 다시 검증한다. 예약 시각 도래만으로 이미 시작한 것으로 간주하지 않으며, 실제 시작은 D-067의 공통 확정 시각을 사용한다. 개별 상품의 O/D 정각 규칙을 이 회차 경합에 자동 확대하지 않는다.

유효 회차 취소는 미진행 상품에 회차 취소로 경매 미진행임을 표시하고 기존 개별 취소 이력과 소속을 유지한다. 상품을 다른 회차로 자동 이전하지 않는다. 공개 전 회차 취소와 진행 중 회차 전체 취소는 EX-10의 MVP 제외 범위다.

출품은 회차의 최초 공식 출품 접수 순번에 따라 유효 신청을 배정한다. 대기 수가 가장 적은 레인을 선택하고 동률은 레인 번호 오름차순이다. 무효 신청·동일 기록 시각 때문에 저장 완료순으로 순서를 바꾸지 않는다. 공개 전 일반 수정·취소는 나머지 배치를 유지하고 공개 전 레인 수 변경만 전체 재배정한다. 공개 후 취소는 그 공개 번호 자리를 취소로 남기며 다음 상품을 당겨 다시 번호 매기지 않는다.

이 규칙은 첫 배정부터 결정 가능하게 하고 공개 후 번호 혼동을 줄인다. 반면 일반 취소 후 대기 수가 불균등해질 수 있고 공개 목록에 취소 자리가 남는다. 동시 출품·공개·회차 시작의 일관성은 기술 검증이며 특정 큐·락·DB 구조 채택을 뜻하지 않는다.

## 7. 주요 도메인 협력 시나리오

### 7.1 출품에서 최초 준비까지

애플리케이션은 회원 자격·모집 구간과 회차의 최초 공식 출품 접수 순번을 확보한다. Lot가 정보·가격 조건을 검증하고 배정 규칙은 유효 신청에 최소 대기 수·동률 레인 번호 오름차순을 적용한다. 공개 직전 공식 요청을 반영한 뒤 내용·배치를 고정한다. 회차 시작 조정은 예약 시각순 후보를 선택하고 회차 공통 순서에서 시작 자격·진행 점유를 재확인한다. 유효 시작이면 Round 시간을 고정하고 운영 Lane을 공통 실제 시작 시각으로 초기화한다. 빈 Lane은 종료하며 모두 비었다면 실제 시작 뒤 Round가 즉시 완료된다. (R-07, R-15, R-27~R-36, R-44; D-081~D-084, D-087~D-090)

### 7.2 입찰 승인과 거절

회원×경매의 공유 의도를 등록·확인한 뒤 원키·Auction·금액으로 실제 입찰을 제출한다. 어느 기기도 다른 의도를 동시에 제출하지 않는다. 같은 번호의 기존 입찰은 원처리·원판정으로 연결하고 다른 내용은 충돌로 다룬다. 첫 공식 입찰 접수에서 시각·순번을 확보하며 공유 등록 시각으로 소급하지 않는다. Auction은 자기 순서의 조건을 검사하고 승인은 Bid·최고입찰·단계·마감을 함께 반영한다. 거절은 경매 상태를 유지한다. 원기록을 보존한 뒤 응답·전파하며 어느 기기에서든 원최종 판정의 수신·반영이 자동 확인되면 공유 제한을 해제한다. 응답 유실·등록 시간초과만으로 새 의도로 바꾸지 않는다. (R-08, R-10, R-17~R-23; D-058~D-062, D-078~D-080)

### 7.3 정상 마감과 결과 확정

타이머는 마감 검토를 요청할 뿐 직접 낙찰자를 지정하지 않는다. 현재 단계·유효 마감·제어 상태와 선행 요청 처리 조건을 확인한다. 공통 순번대로 선행 입찰·제어를 반영한 뒤 현재 마감 이전의 미처리 접수나 미결 접수 기록을 누락하지 않고 Auction이 최종 최고 승인 Bid로 결과를 산출한다. 현재 마감 정각·이후 상품 취소가 이를 추월하지 못한다. 결과와 Lane 전환을 일관되게 보존하고 다음 상품이 있으면 실제 준비 진입 확정 시각부터 준비 전체 시간을 부여한다. 이전 마감으로 다음 준비를 소급하지 않는다. 마지막 상품이면 Lane 종료·Round 완료 조건을 검사한다. 순서·시간 기준 정책은 확정됐으며 저장·복구 기술은 OPEN-10이다. (R-04, R-08, R-09, R-21, R-42; D-055~D-057, D-063/065/067)

### 7.4 중단·취소·재개

운영 권한·명령키·고정 내용을 확인한다. 중복이면 현재 상태를 새로 변경하지 않고 원결과·원 R을 반환한다. 새 명령은 공통 순서에서 Lane과 Auction을 함께 다루며, 중단·재개는 Round/Lane, 상품 취소는 원상품/경매를 유지한다. 선행 유효 입찰과 자동 경계를 반영하고 무효 제어는 상태를 바꾸지 않는다. 재개는 대상 중단 발생 건, 원인별 확인, 정상 접수·기록 가능성을 검증하며 장애 복구 확인만으로 수동 중단을 없애지 않는다. 중단 중 상품 취소는 중단을 유지하며 허용된 실제 재개 때 보존 단계 또는 다음 상품 준비 전체 시간을 부여한다. 보류 상품 취소는 D-075의 확인 조건을 만족해야 하고 결과 존재 불명 시 취소도 보류한다. (R-15, R-24~R-26, R-42, R-43; D-063~D-069, D-074~D-077)

### 7.5 결과 조회와 외부 거래

공개 결과 조회와 본인 요청 결과 확인은 목적이 다르다. 공개 조회는 낙찰·유찰·취소와 낙찰가를 제공하고 비공개 가격·신원 필드는 제외한다. 인증된 회원의 거래 연락처 요청은 해당 Auction의 확정 낙찰 결과에서 당사자 관계를 확인한 뒤 상대 인증 이메일을 제공한다. 유찰의 최고입찰자는 낙찰자가 아니므로 거래 연락처 권한을 얻지 않는다. 이후 외부 거래 불이행은 확정 AuctionResult를 바꾸지 않는다. (R-11, R-38, R-39, R-43, R-51)

### 7.6 장애 복구와 회차 취소

장애 복구 협력은 영향 범위와 마감 선후 증거를 확인하고 원판정·완전 이력·불명 상태를 분류한다. 복원 가능한 미결 요청은 원순서로 판정하되 장기 판정 지연 또는 장애 선행이면 결과 보류를 유지한다. 명시적 재개 전에는 기록·최고입찰·단계·미결 요청과 정상 접수·기록 가능성을 확인한다. 불명 경매를 취소로 정리하거나 개인의 미확인 응답만으로 경매 전체를 보류하지 않는다. (D-071~D-075)

회차 취소는 자동 시작 사건과 공통 순서에서 공개·미시작 조건을 다시 검사한다. 유효 취소이면 Round 시작을 막고 관련 미진행 Lot의 표시 근거를 제공하되 기존 개별 취소는 유지한다. 실제 시작이 먼저 성립한 회차에는 전체 취소를 제공하지 않는다. 개별 Lot마다 가상 AuctionResult나 Bid를 생성할지는 승인 정책에서 요구하지 않는다. (D-084~D-086)
